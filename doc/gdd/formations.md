# 陣形スキル（レシピ・カタログ）

**特定のユニット配置（編成レシピ）が盤上で揃うと発動できる能動アクション**＝senaris 独自の看板機能。「配置で撃つ特殊能力」であって、ただの配置バフではない。

- **本書はレシピの正本（カタログ）**。冒険譚が増えるたびにここへ追記する（ユニット表 [units.md](units.md) と同じ「増える表」の位置づけ）。
- 参加者が発動者1体だけで、効果を味方1体に乗せるものは **ユニットスキル** として別に置く。仕組み（レシピ・行動完了・状態補正・持続の数え方）は本書と共通で、カタログだけを分けている。

---

## 共通ルール

- 発動は **プレイヤーの明示操作**（条件が揃っても自動では出ない）。
- レシピが要求するユニットは **スキンID で照合**する（スキン未指定の駒は種別IDへフォールバック）。性能が同じでも見た目が違えば別物＝クレリック性能のゴブリンはホーリーアリアに参加できない。敵に陣形スキルを持たせるときは、その陣営のスキンをレシピに書く。
- **参加ユニットは行動完了**（1体は1ターンに1つの陣形スキルにのみ参加）。
- 参加者のレベルは、着弾のあるレシピだけ上がる。攻撃と同じ「戦ったら+1・倒したらさらに+1」（→ [combat.md](combat.md)）を**1発の単位**で当てる＝面で何体倒しても +2 が上限、対象に1体も当たらない空撃ちは 0。効果が味方に乗るだけのレシピ（②）では上がらない。
- 参加できるのは**そのターンまだ行動を使っていない**駒（待機も攻撃もしていない）。囲まれて行ける先が無い駒も参加できる＝発動に移動先も攻撃相手も要らない。
- **発動者は移動してから発動してよい**。レシピの成立も射程も移動先の位置で判定する。参加する残りのメンバーはその場に留まる（移動すると行動を使い切るため）＝寄ってきた1体が号令をかける形になる。単独発動のユニットスキルも同じ扱い。
- 効果は原則 **間接攻撃扱い**＝**支援は乗らない／包囲は乗る**（[combat.md](combat.md) 間接攻撃）。※バフ系は対象の攻撃/防御に準ずる。

## 設計原則（レシピを増やすときの判断軸）

陣形スキルは「殴るか、スキルか」の二択を作る装置。レシピを足すときは、効果を決める前にここを通す。

二択はターン単位ではなく駒単位で成立する。共通ルールの「参加ユニットは行動完了」が値札で、プレイヤーが実際に迫られるのは「このステージでスキルを撃つか」ではなく「この駒を殴らせるか、供出するか」。盤に12体いれば12回の判断になる。

### 1. すべてのスキルは行動で値付けする

生産が無いため、この作品で補充される資源は行動しかない（兵数は減る一方で、増えるのは拠点占領の garrison だけ）。効果の強さを議論する前に、何行動ぶんかを決める。

### 2. コストは、その駒の本業で払わせる

本業は駒ごとに違う。攻撃力の低い駒で払えるスキルは実質タダで、二択にならない。

| 兵種 | 本業 |
| --- | --- |
| 魔法兵 | 殴る（間接で、貫通を持つ＝対アーマー） |
| 占領兵 | 占領する。増援・湧きの停止・回復・勝利条件をすべて握る（[map.md](map.md)） |
| 歩兵・重装 | 前線を保つ／包囲の頭数になる |

### 3. 面・射程・持続で払わせ、威力では払わせない

ダメージ系の威力は発動者1体の実効攻撃力に留め、参加者ぶんを合算しない。合算した瞬間、常にスキルが勝って二択が死ぬ。①が3行動で1体ぶんの威力なのはこの原則によるもので、敵が1〜2体なら普通に殴ったほうが強い状態を保つ。

威力の攻撃力は相手によらず常に対地値で計算する＝対空値は見ず、飛行の敵にも同じ威力で通る（`atk_air` 0 のパラディンの③でも飛行のボスを狙撃できる）。対空の得手不得手は通常攻撃の住み分けで、聖なる光や爆発が空に届かない絵にはならない。

### 4. コストが定数だと、二択は解ける

「敵3体以上で撃つ」のような定数解が出ると、プレイヤーは初回に計算して以後考えなくなる。盤面によってコストが変わるスキルのほうが寿命が長い。

### 抑え方の分類

レシピごとに、どれで抑えるかを決めておく。混ぜない。

| 抑え方 | 調整する場所 | 例 |
| --- | --- | --- |
| コスト | 数値（行動数・威力・射程） | ①トリニティノヴァ |
| 機会費用 | マップ（競合する仕事を置く） | ②ホーリーアリア |
| 可用性 | 編成（そのユニットを置くか） | ③ディバインジャッジメント |

①はコストで抑える。3行動で1体ぶんの威力。加えて着弾面（中心＋周囲6）と包囲の輪（敵の隣接6）は同じ図形で、参加者以外の味方は焼ける。包囲は乗るので、囲むほど威力が上がり、囲むほど自軍を焼く。盤面に依らず常に同じ判断になる。

②はマップで抑える。`_cluster` は連結成分の探索なので、敵を囲んだ占領兵の輪はそのままクラスタになる＝配置の競合は起きない。効いているのは占領との機会費用のほうで、占領がやりたいこと（バラす）とレシピが要求すること（固める）が真逆な点、およびクレリック／プリーストの足の遅さが痛みの実体。拠点の取り合いが無いステージではタダに戻るため、ホーリーアリアが使えるステージには、そのターン占領兵が向かうべき拠点を必ず置く。中立拠点の garrison を強くするほど二択は鋭くなる。

③は編成で抑える。パラディンをレアにすることで、レベルデザインが解禁／封印を直接握る。数値調整の対象外で、強すぎて構わない。

### 例外：発見型のレシピ

③のように「盤の構造を読み解いて、この位置から撃つと気づく」ことが主眼のレシピは、二択を背負わせない。迷わせることが目的ではないため、コストは軽くてよく、要るときに必ず在ることのほうが重要になる。設計の負荷はレシピ自身ではなく、手前のステージ（溜めを作る側）とマップの構造に乗る。抑えるのは可用性で行う。

### 増やすときの注意

- `count` 固定はインフレする。冒険譚内で戦力が持ち越されるため（[map.md](map.md) carryover）、軍が大きくなるほど固定N体のコストは相対的に安くなる＝後半ほど自動的にスキル側へ傾く。後発レシピほど `count` を上げるか、効果の強さと連動させる。
- パラディンを置くとは、③を解禁するということ。パラディンは `can_capture` を持つ中で最も戦える駒なので、占領要員として出したくなる場面がある。性能だけ借りて技を封じたい場合は、paladin 性能に別スキンを貼る（レシピはスキンIDで照合する＝共通ルール）。
- 相互隣接は見た目より狭い。`triangle` は参加3体が相互に隣接している必要があり、ヘックスの輪では1つ飛ばしが距離2。発動者を挟んで左右対称に2体を置くと成立しない。密室や隘路で撃たせるステージでは、成立する配置が実際に取れるか座標で確認する。

## 発動の演出

発動したら1枚絵のカットインを挟み、盤に戻って着弾を見せる。

```
発動 → カットイン（1枚絵・約1秒・スキップ可） → 盤に戻って着弾（揺れ → 面の光 → 被弾した駒を1体ずつ）
```

- カットインだけでは「どこに当たったか・誰に効いたか」が分からない。トリニティノヴァは7ヘクスに当たる面の広さが売りなので、盤に戻って結果を見せるところまでが演出。前半が華、後半が情報。
- 盤の駒はカットインの間、撃たれる前の姿のまま置く。兵数の減少も撃破の消滅も、下の着弾の中で起こす。カットインの裏で先に消すと、明けたときには何も起きない。
- 着弾は3段に分け、まとめてではなく順に出す。一度に全部出すと1回の大きな明滅になり、何ヘックスに当たって何体が受けたのかが読めない。
  1. 画面全体が短く揺れる。当たった合図＝盤エリアだけでなく画面全体を揺らす（加護の光と同じ扱いで、右の情報ボックスも同じ衝撃の下に置く）。
  2. 効果範囲のヘックスが光る。駒の居ない空ヘックスも光らせる＝面の広さが伝わる。
  3. 被弾した駒を1体ずつ、少し間を置いて処理する。駒ごとに エフェクト → 被弾フラッシュ → 兵数の更新、撃破ならその場でフェードアウトしてから消える。順番は着弾中心に近い駒から外へ。
- 駒に重ねるエフェクトはレシピごとに1枚を描き、規約解決する（`godot/assets/formations/{recipe_id}_impact.png`。置き場と命名 → [../art/keyvisual.md](../art/keyvisual.md) §3）。武器の攻撃エフェクトのカタログからは借りない。借りると発動者スキン次第で剣の弧が天から降ってくる。絵が無いレシピは絵を出さず、面の光と被弾フラッシュだけで済ませる（欠けても穴は開かない）。
- この絵は盤でしか使わない（陣形スキルは戦闘演出シーンを通らない）ので、最初から下向き＝上から落ちてくる形で描く。演出側は回転させない。武器の攻撃エフェクトが「右へ向かう一撃」で描かれ盤で90度回されるのとは別扱いで、既存の攻撃エフェクトには影響しない。
- 大きさの倍率は持たない。絵の側を枠いっぱいに描いて釣り合わせる（攻撃エフェクトの `scale` 列に相当するものは無い）。
- ホーリーアリアのような着弾の無いものは、揺れも面の光も出さない。加護の光（画面外周から差し込む金の光）だけで見せる。光は画面全体に敷く（盤エリアだけに絞ると盤の右端で光が断ち切れる）。置き場所は画面の明暗の共通基盤（ScreenLighting）＝暗幕より前なので、暗転中も縁の光が生きる。前面パネル（右の情報ボックスなど）は光より前に浮く。
- カットインはクリック／キーで即座に飛ばせる。頭をロックしない（戦果票と違い1ステージに何度も出る＝止められる方を優先する）。着弾の3段も同じく飛ばせて、飛ばせば結果だけが残る。
- 陣形スキルで決着した場合（ボスを陣形スキルで倒す）も着弾を最後まで見せてから戦果票へ移る。決着の告知が着弾に割り込まない。
- 窓は戦闘演出シーンと同じ位置・大きさ・形（盤エリア中央の角丸の窓）。暗転は画面共通の基盤（ScreenLighting）で画面全体＝濃さは会話・戦闘と同じ。右の情報パネルは前面パネル層で幕より前＝沈まない。演出の見た目も揃う（→ [../tech/combat_scene.md](../tech/combat_scene.md)）。
- 絵はレシピごとに1枚。規約解決で、絵が無いレシピはカットインを飛ばして盤の結果だけ見せる（音は鳴らす）。置き場と命名 → [../art/keyvisual.md](../art/keyvisual.md) §3。
- 効果音は発動の頭にレシピIDの音、効果が届いた瞬間に同じIDの `_hit`（`assets/sfx/{recipe_id}.ogg` / `{recipe_id}_hit.ogg` の規約解決 → [../audio/sfx.md](../audio/sfx.md)）。レシピごとに音を変えるのは、面殲滅と全体バフが同じ音だと何が起きたのか音から分からないため。陣形スキルは戦闘演出シーンを通らないため、着弾音を `cmb_hit` から借りない。着弾音は揺れと同時に面で1回で、駒ごとには鳴らさない（被弾が続くたびに鳴らすと連打になる）。
- ユニットスキルにはカットインを付けない。単独で撃てて毎ターン飛ぶため、1秒の演出が毎回挟まると必ずスキップ連打になる。音（レシピIDの規約解決＝陣形スキルと同じ引き方。着弾音は無く発動音だけ）と盤の足元の光で足りる。

## 初出・使用

- ①②③ は [冒険譚2「アンデッドの群れ」](../campaign/tutorial2-undead-rush.md) で初確定・初教授（①=st3／②=st5／③=st7）。教える順・演出・物量との噛み合いは冒険譚側に置く。

## 実装方針（決定）

- データ化の形式：当面は `godot/domain/formation/` にハードコード（各レシピは効果自体が個別でデータ化の旨みが薄い）。レシピが増えたら CSV/JSON 化を検討。AIの「ロジック＝コード／組合せ＝データ」とは違い、陣形スキルは効果ごとに専用処理。
- 三角形の判定：参加3体が相互に隣接していれば成立（hex は3マス相互隣接で三角形）。
- 段階実装：A＝フレームワーク＋①トリニティノヴァ／B＝③ディバインジャッジメント（①と同型・範囲違い）／C＝②ホーリーアリア（ターンまたぎの持続バフを新設＝最侵襲なので最後）。
