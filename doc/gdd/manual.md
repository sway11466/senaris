# ゲーム内マニュアル

タイトルの「マニュアル」から開く、仕組みと用語を読む画面。本作は戦闘に乱数が無く、敵も特性ごとのルールで動く（[ai.md](ai.md)）。負けた理由が必ず盤上にある、という作りをプレイヤーが読んで確かめられる場所にする。

---

## 方針

- 数値の一覧は載せない。個々の数値は盤上の情報パネルで見るもので、マニュアルはその数値が何を意味し、計算のどこに効くかを説明する。
- 敵AIの章だけは要約しない。行動ルール表をそのまま載せる。要約すると「次に敵が何をするか」を読めず、この画面を置く意味が消える。
- 正本は gdd の各ドキュメント。マニュアルはそれをプレイヤー向けの言葉に書き直したもので、食い違ったら gdd 側が正しい。

## 章構成

| 章id | 章 | 内容 | 正本 |
|---|---|---|---|
| unit | ユニットの能力値 | 対地攻撃・対空攻撃・貫通率・防御・移動・射程・攻撃後移動・兵数・搭乗・占領のそれぞれの意味 | [units.md](units.md) |
| combat | 戦闘 | ダメージが決まる流れ。包囲・支援・地形・高さ・状態補正が計算のどこに効くか | [combat.md](combat.md) |
| terrain | 地形 | 地形攻・地形防、視線、足場とオブジェクトの二層、高さ | [terrain.md](terrain.md) |
| move | 移動 | 移動タイプ、地形コスト、足止め、進入不可、輸送の乗り降り | [movement.md](movement.md) |
| skill | スキル | 陣形スキルとユニットスキルの仕組み。レシピで決まること、強化・弱体・解除の別、重ねがけの数え方 | [formations.md](formations.md)・[skills.md](skills.md) |
| ai | 敵AI | 共通の仕組み・用語・特性ごとの行動開始条件と行動ルール表・輸送ユニット | [ai.md](ai.md) |
| base | 拠点・占領 | 占領の手順、回復、出撃 | [map.md](map.md) |
| rank | 評価ランク | S/A/B の判定 | [rank.md](rank.md) |

- スキルの章は仕組みだけを説明し、カタログ（どのレシピがどのスキルを出し、効果が何か）は載せない。
- 敵AIの章の構成は 共通の仕組み（表は上から当てる・行動開始条件は一度きり・攻撃されたら起きる・部隊と一斉警戒・行動順・拠点出撃）→ 用語集（距離・前進・最大間合い・脅威圏・間合取り・手負い・獲物・空敵 ほか）→ 特性ごとの行動（特性ごとに概要・パラメーター・行動開始条件・行動ルール表）→ 輸送ユニット。輸送は特性ではなく搭乗数から自動で付く性質なので、特性と横並びにしない。[ai.md](ai.md) にある行の並び順の理由づけは載せない。プレイヤーに要るのはどう動くかで、なぜそう設計したかではない。

## 画面

- 開き口はタイトルのメニューのみ（[title.md](title.md)）。盤の中からは開かない。通読用の画面を盤に被せてもその場の疑問に答える形にならないためで、盤上で用語をその場で引く道具は別の機能として扱う。
- 見せ方は設定画面と同じ様式（[settings.md](settings.md)）。全画面の暗幕、押せる物は木の板、板の外は無機質なグレー、戻るは画面左下。マニュアルはアプリケーションの操作なので、酒場の設え（羊皮紙・依頼ボード）を持たない。
- 2ペインで、左に目次、右に選んだ節の本文を出す。目次は章を上から並べ、節が2つ以上ある章（いまは敵AIだけ）は節を全部並べて、その左に章名を縦に書いた板を立てて束ねる。開閉で伸び縮みさせないのは、全部出しても縦に収まるため＝畳んだり開いたりする操作を覚えなくてよい。
- 束ねた章は章そのものの行を持たない。押せるのは節の行だけになり、いま読んでいる場所の印も常に1つで済む。縦書きは章名を90度倒して入れる（1字ずつ縦に積むと英語が読めなくなる）。
- 節の中でさらに切り替わるもの（敵AIの特性ごとの行動）は、本文ペインの上にタブで並べて切り替える。目次に載せると縦に伸びるうえ、選ぶ対象が多くなりすぎる。タブは幅に入らなければ折り返す。
- 節の見出しとタブはスクロールの外に置く。長い本文を繰っている間も、どの節のどれを読んでいるかが見えたままになる。
- タブには特性のアイコンを載せる。置き場と規約は情報パネルと同じ＝`{特性id}.png` が在れば出し、無ければ文字だけで並ぶ。
- 本文はスクロールで流す。スクロールを使うのはこの本文ペインだけ。ページ割りにしないのは、同じ内容でも言語で行数が変わり、日本語で決めたページ割りが英語で溢れるため。
- 目次は縦に必ず収まる寸法にする。いちばん長い形（節を持たない章と、束ねた章の節を全部足したもの）が収まらないと目次までスクロールすることになり、上の約束が崩れる。節を増やしたら [shot_manual.gd](../../godot/tests/manual/shot_manual.gd) で入れ物との比を測り直す。
- 左下の戻ると Esc はどちらも画面を閉じる。目次は章が常に見えていて段を上がる操作を持たないので、隅のボタンはどの画面でも「この画面を出る」の一つに保たれる。

## 本文の持ち方

- 本文は翻訳CSV `godot/data/i18n/manual.csv` に置く。1行1キーで、段落や表のセルごとにキーを振る（[../tech/i18n.md](../tech/i18n.md)）。キーは `manual.<章id>.<節>.<要素>`。
- 章・節・ブロックの並びは GDScript の定数で持つ。ブロックは段落と表で、どのキー列で構成されるかまで定数が持つ。
- 構造が参照するキーが `manual.csv` に揃っているか、CSV 側に構造から参照されないキーが無いかをテストで突き合わせる（[../tech/testing.md](../tech/testing.md)）。
