# 敵AI（思考パターン）

敵の思考を特性の単位で定義する。特性ごとに、いつ動き出すか（行動開始条件）と、1手番で何をするか（行動ルール）を書き下す。

---

## 基本方針

- AIの思考パターンを特性と呼ぶ
- 特性ごとに行動ルールを定義する
- 敵が使う情報は盤から読めるものに限る
  - Senarisは確定ゲームなのでプレイヤーが知り得ない情報で行動が決まらないようにする
- 特性と部隊はプレイヤーに見せる
  - 敵を選ぶと情報パネルの見出しに部隊名と特性が出る（→ [uiux.md](uiux.md)）
  - 隠すと確定ゲームの前提が片側だけ崩れる。敵は盤しか見ないのに、プレイヤーは敵の動き出す条件を読めない
  - とくに部隊は一斉警戒の範囲＝この1体に触れると誰まで一緒に起きるかを示す。盤からは読めない

## 特性の書き方

特性は行動開始条件と行動ルールを持つ。

行動開始条件は、その駒が動き出す条件。一度成立したら以後は判定しない。成立したあとで敵が離れても止まらない。

攻撃を受けた駒は、特性と行動開始条件によらずその時点で行動開始する。視線の外や射程外から撃たれても起きる。

行動ルールは上から順に当て、最初に成立したものを採る。1行が行動条件と行動内容の組で、行動内容には対象の選び方まで含める。

どの行も成立しなければ待機する（その場に留まり、その駒の手番を終える）。行動開始条件が成立していない駒も同じく待機する。標的にできる敵が盤上にいない場合など、末尾の行が成立しないことはある。

移動を使い切った駒は、移動を伴う行（占領・前進）を飛ばして次の行を見る。

行動条件と対象選びを別の軸に分けない。「放つかどうか」と「誰に放つか」は同じ候補集合を絞る操作で、分けると同じ条件を2箇所に書くことになる。

## 部隊

特性とパラメーターを共有するユニットの束。敵ユニットは必ずいずれかの部隊に入る。

- 特性の割り当ては部隊単位。ユニット1体ごとには割り当てない
- 1体だけの部隊も作れる。ボスだけを別扱いしたいときに使う
- パラメーターは部隊ごとに上書きできる。同じ特性で sight だけ違う2部隊を並べられる
- 行動開始条件の「部隊の誰かが行動開始済み」はこの束を見る（一斉警戒）
- 味方に部隊は無い。行動を選ぶのはプレイヤーなので特性を持たない

---

## 行動順

敵のターンは部隊を単位に順番を決める。部隊は order（1から昇順の整数）を持ち、小さいほうから動く。order は全部隊に書く。抜けはデータ整合テストで検出する。

部隊の中の順番は盤面から決める。盤上距離で最寄りの敵に近い駒から動き、同値は col → row の若い順。駒が動けば距離も変わるので毎ターン計算し直す。

前線から動かすのは、後ろの駒が先に動くと前の駒に塞がれて進めないため。順番を座標で固定して覚えると、進軍の途中で前後が入れ替わったときに詰まりが戻る。

特定の駒を先に、あるいは後に動かしたいときは部隊を分ける。「ボスは最後」はボスだけの部隊に最大の order を振って表す。

自軍に行動順はない。順番はプレイヤーが選ぶので、order は敵側だけの概念。

## 拠点出撃

拠点そのものが1つの部隊。特性とパラメーターを持ち、order で盤上の部隊と同じ列に並ぶ。行動開始条件は拠点hex基準で評価する。ambush なら索敵に敵が入るまで出さず、charge なら初手から出す。

- 行動開始したあとは、空き隣接が埋まるか garrison が尽きるまで出す
- 出す順は garrison の記述順。控えは全員が拠点hexにいて座標で並ばないため
- 出す先は、盤上距離が最小の敵に最も近い空きマス。盤上に敵がいなければ col → row の若いマス
- 出せるのは native ルールを満たす駒だけ（[map.md](map.md) 出撃）
- `ai` を書かない拠点は出撃しない。控えを抱えたまま湧かせたくない拠点（盤上の敵を倒しても決着しないことを示す拠点など）はこれで表す
- 出した駒はそのターン行動完了。次のターンからその部隊の一員としてその特性で戦う
- 出撃を行うのは、その部隊の盤上の駒を動かし終えたあと
- 一斉警戒はその部隊の中で閉じる。盤上の別部隊が行動開始しても拠点は起きない
- 部隊の内側では向きを問わない。拠点が行動開始すればそこから出した駒も起き、出した駒が行動開始すれば拠点も起きる

## 用語

### 距離

| 用語 | 定義 |
|---|---|
| 盤上距離 | ヘックスの直線距離 |
| 移動距離 | 行動ユニットが侵入できないマス（地形・すでにユニットがいるマス）を除いて、標的に攻撃可能なマスまでを地形コストで測った最小距離 |
| 地形距離 | 移動距離から駒の除外を外し、地形だけで測った最小距離 |
| 迂回距離 | 移動距離に敵ZOCも除外して測った最小距離。ただし標的自身のZOCは除外しない |
| 視線距離 | 地形の視線コストを積算した距離 |

距離量が同一の場合は座標位置で遠近を判定し、col → row の若い方が近いと判断する。

「標的に攻撃可能なマス」は射程だけでなく、そこからその標的を攻撃できるかまで見る。対空攻撃力が無い駒にとって飛行の標的は攻撃可能なマスを1つも持たない＝距離が測れない。

移動距離・地形距離・迂回距離は測れないことがある。除外したマスを避けて標的へ辿り着けないときで、そのときは「測れない」を値として扱う。行き先が無くなったときにどうするかは、特性ごとに行動ルールで決める。

地形距離は駒を壁として数えない。仲間や敵に塞がれていても、その駒がどいたあとに通れる道を測る。迂回距離で標的自身のZOCを除外しないのも同じ理由で、除外すると標的の隣へ入れず必ず測れなくなる。

侵入できない地形には、1マスの進入コストがそのユニットの移動力を超えるマスを含む。同じ地形でも通れる駒と通れない駒がいる（柵＝コスト3は移動2の駒だけを締め出す）。

視線距離は壁で途切れ、森ごしでは減衰する。定義は [movement.md](movement.md) の視線に従う。

### 移動範囲

今ターンそのユニットが止まれるマスの集合。ZOC停止（[movement.md](movement.md) ZOC停止）で切り詰められるので、ZOCマスの先は入らない。ZOCマス自体は入る（そこで移動が終わる）。

乗れる味方輸送のマスもここに入る（止まる＝乗車）。ただし前進と占領はそこに止まらない。乗るかどうかを決めるのは乗る行だけで、通り道にたまたま輸送が居たから乗る、拠点に乗っている輸送へ占領のつもりで入る、はどちらも起こらない。

### 前進

いずれも移動範囲のうち、標的への距離が最も縮むマスへ動く。使う距離だけが違う。同値のマスが複数あれば col → row の若い方、距離が縮むマスが1つも無ければ現在地に留まる。

| 用語 | 使う距離 |
|---|---|
| 最大前進 | 移動距離 |
| 回り込み | 迂回距離 |
| 見込前進 | 地形距離 |
| 直線寄せ | 盤上距離 |

回り込みは敵ZOCを避けて標的へ近づく。ZOCは入ると移動が終わるので、避けると前衛の帯に触れずに横へ滑れる。プレイヤーがZOCの帯を張れば回り込む隙間が消える。

見込前進は駒に塞がれて道が無いときに使う。塞いでいる駒はいずれ動くので、地形の上で最短になる位置へ詰めておく。幅の狭い通路に縦列で入った後続が、先頭の背中を前にして足踏みしないための行。

直線寄せは距離が測れないときに使う。壁の向こうの標的へ壁際まで詰めて止まる動きになる。

### 最大間合い

移動範囲のうち、標的を攻撃できるマスで、標的への盤上距離が最大のマスへ動くこと。同値のマスが複数あれば現在地を優先し、次に col → row の若い方。動く先が現在地なら移動しない。

下がる幅は射程上限で頭打ちになる。射程1-2の弓兵なら距離2、射程3-5の砲兵なら距離5が上限で、そこから離れると撃てなくなるため行き先にならない。

敵の移動範囲は見ない。距離を取っても翌ターン詰められることはあり、それは盤の形と足の速さで決まる。

### 反撃されない

そのマスから標的を攻撃したとき、標的が反撃してこないこと。成立するのは次のいずれか（[combat.md](combat.md)）。

- 距離が2以上＝間接攻撃（反撃が無い）
- 距離1だが、標的が距離1を撃てない（懐に死角のある砲兵など）
- 距離1だが、標的がこちらを攻撃できない（対空攻撃力の無い駒にとっての飛行）

射程と距離と相手の種別だけで決まる＝盤から読める。

### スキル対象

スキルを掛けられる相手。味方に掛けるものか敵に掛けるものかはレシピが持つ（[skills.md](skills.md)）。強化・解除は味方（自分を含む）、弱体は敵になる。

### stack 条件

同じ相手にスキルを重ねすぎないための条件。特性のパラメーター stack と、スキルの種類で決まる。

| 種類 | 対象 | stack 条件 |
|---|---|---|
| 強化 | 味方 | 対象に効いている強化が stack 本未満 |
| 弱体 | 敵 | 対象に効いている弱体が stack 本未満 |
| 解除 | 味方 | 対象に効いている弱体が stack 本以上 |

解除だけ向きが逆で、下限として働く。1本の弱体を消すために手番を使うのは損なので、何本刺さったら動くかの閾値になる。

本数は対象に効いている合計で、誰が掛けたかもスキルの種類も問わない（[skills.md](skills.md)）。ヴェノムファングとドレッドタッチの混成も合算する。

数えるのは対象1体に掛かった補正だけで、陣営全体に掛かった補正（ホーリーアリア）は数えない。1人の解除で落とせる範囲と揃える。

強化・弱体・解除のどれに当たるかはスキルのレシピが持つ。

`-` は上限なし。強化・弱体では常に成立し、解除では1本以上あれば成立する。

### 包囲可能

対象にいま隣接している自陣営の駒と、まだ行動していない味方でこのターン対象の隣へ寄れる駒を合わせて、包囲成立数（[combat.md](combat.md)）に届くこと。行動ユニット自身も数に入る。

すでに包囲されている相手は隣接数が成立数に達しているので、必ず包囲可能でもある。包囲済みかどうかを別の条件として持つ必要はない。

### 損耗

失った兵の割合。残兵数ではなく割合で見るので、兵数の上限が違うユニット同士でも並べられる。

### 手負い

その駒が攻撃できる敵のうち、損耗が最大のもの。同値は移動距離が最小のもの。

損耗に下限を置かない。全員無傷のターンは同値の割り方が効いて最も近い敵が手負いになる。最初に触れた相手へ群れが集まり、以後はその相手が損耗最大であり続ける。

盤全体から1体だけ選ぶ。行動ルールに「攻撃射程内に手負いがいる」「sight 範囲内の手負い」と書いたときは、選び終えたその1体が範囲に入っているかを見るという意味で、範囲内の敵から選び直すという意味ではない。

### 獲物

その駒が攻撃できる敵のうち、防御力が最小の敵の防御力 +10 までにいるもの。1体ではなく集合で、どれを狙うかは行動ルールの行ごとに決める。

攻撃できる敵に絞るのは、飛行ユニットを対空攻撃力の無い駒が追いかけないため。防御力に幅を持たせるのは、盤の隅の最弱1体を全員で追って手近な柔らかい敵を素通りするのを防ぐため（防御力は10刻みなので、最も柔らかい段とその次の段が入る）。

兵数は見ない。獲物が能力だけで決まるので行軍が安定し、どの駒が狙われているかをプレイヤーが読める。

上限（防御力が最小の敵の防御力 +10）は盤全体の敵から計算する。射程内など狭い範囲の敵から計算し直してはいけない。硬い前衛しか射程に入っていないターンにその前衛が獲物になってしまい、弱者狙いが硬い相手と殴り合いはじめる。

### 経路上の敵

目的地への道を塞いでいる敵。射程内の敵をどけたと仮定して、道が良くなるかで判定する。良くなるのは次のどちらか。

- 目的地への移動距離が縮む（体で道を塞いでいる）
- 目的地への迂回距離が、測れないところから測れるようになる（ZOCで足を止めている）

殴るのは、射程内の敵のうち目的地への地形距離が最小のもの＝一番前で塞いでいる駒。

1体ずつ試さず、射程内の敵をまとめてどけて測る。通路を2体で塞がれているとき、どちらか片方をどけても道は開かないので、1体ずつでは両方とも経路上ではないと読まれてしまう。

迂回距離を「縮んだか」で見ない。隣に立っているだけの敵でも、どければ避けるZOCが減って必ず短くなるため、それでは横の敵にもつられる。塞がれたかどうかは道が消えているかで見る。

### 便乗

輸送ユニットに乗って目的地まで運ばれること。乗るかどうかは到着ターン数の比較で決める。

| | 到着ターン数 |
|---|---|
| 徒歩 | 自分の地形距離 ÷ 自分の移動力、切り上げ |
| 便乗 | 輸送の地形距離 ÷ 輸送の移動力、切り上げ ＋1 |

便乗のほうが早い＝便乗の到着ターン数が徒歩を下回ること。同値なら乗らない。

地形距離はどちらもその駒の移動タイプで測るので、自分では通れない地形を輸送が越えられる場合は徒歩が測れず、常に便乗が勝つ。速さと経路を別の条件に分ける必要はない。

便乗の +1 は、最後に降りて目的地へ入るぶん。乗車はその駒の行動を終えるので、乗ったターンは進まない扱いになる。

### たどり着ける

降りたマスから目的地まで、その駒の移動タイプで地形距離が測れること。

飛行の輸送は地上の駒が渡れない地形を越えるので、降ろす側が測らないと、渡れない岸に置き去りにされた駒が永久に歩き続ける。

## 特性詳細

### charge（突撃）

前へ出て積極的に攻撃する。手番をためらいなく使う。

#### 狙い

最も単純な特性。読み合いの要素が無く、必ず前へ来ると分かっている。難易度は敵の性能と盤の形だけで決まるので、地形で受ける・包囲で潰すといった基本をプレイヤーが練習できる。

#### パラメーター

stack スキルを重ねる上限本数

#### 行動開始条件

常時

#### 行動ルール

| # | 行動条件 | 行動内容 |
|---|---|---|
| 1 | 占領兵で、移動範囲に自陣営以外の拠点がある | 盤上距離が最小の拠点へ移動して占領 |
| 2 | スキル保有で、スキル射程内に stack 条件を満たす対象がいる | 盤上距離が最小の対象にスキル |
| 3 | 間接攻撃できる駒で、移動範囲のどこかから攻撃できる敵がいる | 盤上距離が最小のその敵へ最大間合い |
| 4 | 攻撃射程内に敵がいる | 反撃されない敵を優先し、その中で盤上距離が最小の敵を攻撃する |
| 5 | 移動距離が測れる敵がいる | 移動距離が最小の敵へ最大前進 |
| 6 | 地形距離が測れる敵がいる | 地形距離が最小の敵へ見込前進 |
| 7 | 盤上に攻撃できる敵がいる | 盤上距離が最小の敵へ直線寄せ |

#3 は撃つ行ではない。移動と攻撃は別の手で、移動後にもう一度表を上から当てる（移動を伴う行は飛ばされる）ので、同じ手番のうちに #4 が撃つ。動く先が現在地なら移動は起きず、そのまま #4 へ落ちる。

#3 は近接しかできない駒には当たらない。攻撃できるマスがどれも距離1で、最大間合いが現在地と同じになるため、横のマスへ動き直すだけの手が生まれない。

#3 の標的は「移動範囲のどこかから撃てる敵」のうち盤上距離が最小のもの。いまの位置から撃てるかは問わない＝射程の外から詰めるときも、射程の外縁まで寄って止まる。

#4 が反撃されない敵を先に見るのは、同じ1手なら反撃を受けない相手を撃つほうが得だから。隣に敵がいても、距離2で撃てる相手がいればそちらを撃つ。

### ambush（待ち伏せ）

敵が索敵に入るまで動かない。動き出したあとは突撃と同じ。

#### 狙い

戦う順番をプレイヤーが選べるようになる。一度に何部隊起こすかが判断になり、欲張ると複数の部隊に囲まれる。部屋ごとに敵を釣り出すダンジョン戦の骨格。

#### パラメーター

- sight 行動開始条件となる視線距離
- stack スキルを重ねる上限本数

#### 行動開始条件

視線距離が sight 以内に敵がいる ／ 部隊の誰かが行動開始済み

| 2 | スキル保有で、スキル射程内に stack 条件を満たす対象がいる | 盤上距離が最小の対象にスキル |
| 3 | 間接攻撃できる駒で、移動範囲のどこかから攻撃できる敵がいる | 盤上距離が最小のその敵へ最大間合い |
| 4 | 攻撃射程内に敵がいる | 反撃されない敵を優先し、その中で盤上距離が最小の敵を攻撃する |
| 5 | 移動距離が測れる敵がいる | 移動距離が最小の敵へ最大前進 |
| 6 | 地形距離が測れる敵がいる | 地形距離が最小の敵へ見込前進 |
| 7 | 盤上に攻撃できる敵がいる | 盤上距離が最小の敵へ直線寄せ |

行は突撃と同じ（#3・#4 の注記も突撃を参照）。違うのは行動開始条件だけ。

### raid（拠点攻略）

敵より拠点へ向かう。護衛も一緒に動き、着いた先で戦う。

#### 狙い

プレイヤーの手番に時間制限をかける。放っておくと拠点を取られるので、守りに戻るか攻め続けるかを選ばされる。目の前の敵を無視して素通りしていくのが圧になる。

#### パラメーター

stack スキルを重ねる上限本数

#### 行動開始条件

常時

#### 行動ルール

| # | 行動条件 | 行動内容 |
|---|---|---|
| 1 | 占領兵で、移動範囲に自陣営以外の拠点がある | 盤上距離が最小の拠点へ移動して占領 |
| 2 | スキル保有で、スキル射程内に stack 条件を満たす対象がいる | 盤上距離が最小の対象にスキル |
| 3 | 攻撃射程内に経路上の敵がいる | 経路上の敵を攻撃する |
| 4 | 占領兵の乗員がいて、移動範囲に「その乗員を自陣営以外の拠点hexへ降ろせるマス」がある | そのマスへ移動して降ろす |
| 5 | 乗員がいて、移動範囲に「拠点に隣接する降車先へ降ろせるマス」がある | 拠点に最も近いマスへ移動し、たどり着ける乗員を降ろす |
| 6 | 移動範囲に、同じ部隊で空きのある輸送ユニットがあり、便乗のほうが早い | その輸送へ移動して乗る |
| 7 | 移動距離が測れる自陣営以外の拠点がある | 移動距離が最小の拠点へ最大前進 |
| 8 | 地形距離が測れる自陣営以外の拠点がある | 地形距離が最小の拠点へ見込前進 |
| 9 | 盤上に自陣営以外の拠点がある | 盤上距離が最小の拠点へ直線寄せ |

拠点への距離は拠点hexそのものまでを測る。拠点は攻撃の標的ではないので、移動距離の「標的に攻撃可能なマスまで」は当たらない。

拠点は中立も含む。占領兵でなくても向かう。拠点が複数あるときは駒ごとに最寄りへ向かうので、部隊は分かれることがある。

#3 が経路上の敵に限るのは、目の前の敵を無視して素通りするのがこの特性の圧だから。射程内でも道を塞いでいない敵は殴らず、拠点へ歩き続ける。塞がれて前進できない駒はこの行で殴るので手は余らない。

#4・#5 は乗員を持つ駒＝輸送ユニット（[特殊特性詳細](#輸送ユニット)）にしか当たらない。#3 は逆に輸送ユニットには当たらない（攻撃しない）。

#4 を占領兵に限るのは、占領できない駒を拠点hexへ降ろしても占領が起きず、拠点を塞いで後続の占領兵が入れなくなるため。#5 でたどり着けない乗員は乗せたままにする。

#6 で乗るのは占領兵に限らない。移動の遅い駒はみな乗る。定員より乗りたい駒が多いときは、部隊内の行動順で先に動いた駒が埋め、あぶれた駒は #6 が不成立になって #7 以降へ落ちる。

乗るのを同じ部隊の輸送に限るのは、目的地の違う部隊の輸送に乗ると見当違いの場所へ運ばれるため。拠点出撃から輸送へ直接乗せることはしない（[拠点出撃](#拠点出撃)の出す先は空きマスのまま）。出た駒は次のターンに #6 で判断する。

降車地点は拠点の隣なので、降りた駒が翌ターンまた乗ることはない。徒歩の到着ターンが1になり、便乗はどう測っても1を下回れないため。

最大間合いの行は持たない。攻撃するのは経路上の敵だけ＝道を空けるための攻撃で、間合いを取る移動は拠点から遠ざかる。目の前の敵を無視して素通りする圧が鈍るので、間接攻撃できる駒も塞がれた位置から殴る。

向かう拠点が盤上に無ければ待機する。敵を追わないのが突撃との差で、拠点を全部取られたあとは動かなくなる。

### weak（弱者狙い）

前衛を避けて柔らかい敵へ回り込む。硬い敵とは殴り合わない。

#### 狙い

硬い前衛を素通りする。殴られても獲物へ歩き続けるので、プレイヤーは前衛でZOCの帯を張って足止めすることになる。後衛を守れ、という圧をかける特性。

#### パラメーター

- sight 獲物を見つける視線距離
- stack スキルを重ねる上限本数

#### 行動開始条件

視線距離が sight 以内に獲物がいる

#### 行動ルール

| # | 行動条件 | 行動内容 |
|---|---|---|
| 1 | 占領兵で、移動範囲に自陣営以外の拠点がある | 盤上距離が最小の拠点へ移動して占領 |
| 2 | スキル保有で、スキル射程内に stack 条件を満たす対象がいる | 防御力が最小の対象にスキル |
| 3 | 間接攻撃できる駒で、いまの位置から一撃で倒せる敵がおらず、移動範囲のどこかから狙う獲物を撃てる | 狙う獲物へ最大間合い |
| 4 | 攻撃射程内に獲物がいる | 攻撃後の残兵が最小となる獲物を攻撃する |
| 5 | 攻撃射程内に一撃で倒せる敵がいる | 反撃されない敵を優先し、その中で盤上距離が最小の敵を攻撃する |
| 6 | 狙う獲物への迂回距離が測れる | 狙う獲物へ回り込み |
| 7 | 狙う獲物への移動距離が測れる | 狙う獲物へ最大前進 |
| 8 | 狙う獲物への地形距離が測れる | 狙う獲物へ見込前進 |
| 9 | sight 範囲内に獲物がいる | 狙う獲物へ直線寄せ |

狙う獲物＝ sight 範囲内の獲物のうち移動距離が最小のもの。移動距離が測れる獲物が1体もいなければ盤上距離が最小のもの。#3 と #6〜#9 はどれもこの1体へ向かう＝行の間で行き先が入れ替わらない。

#3 が「一撃で倒せる敵がいない」を条件に持つのは、倒しきれる相手から下がらないため。攻撃は同時解決なので倒しても反撃は受けるが、獲物を1体減らす価値のほうが大きい。近接攻撃には支援が乗る（[combat.md](combat.md)）ので、味方が隣接している状況では下がると倒しきれなくなることもある。

#5 が反撃されない敵を先に見るのは、どちらも倒せるなら反撃を受けない相手から倒すほうが得だから。#4 の対象選びは変えない。確殺を優先する行なので、反撃されない相手を先に見ると獲物を取り逃がす。

止まり方が2種類ある。行動開始条件は一度きりの判定で、最初に獲物を見つけるまで完全に眠る（隣に敵が来ても攻撃しない）。#6〜#9 の sight は毎ターンの判定で、起動後に獲物が視線から消えたら前進だけを止める（攻撃とスキルは続ける）。

後者があるので、プレイヤーは後衛を下げる・前衛で視線を切ることで足を止められる。

### swarm（群れ）

傷ついた敵へ集まる。無傷の敵には頭数が揃ってから手を出す。

#### 狙い

手負いには単独でも噛みつくが、そうでない相手には頭数が揃ってからしか手を出さない。傷を負った1体に群れが集まるので、削られた駒を下げるかどうかの判断をプレイヤーに迫る。1体だけ残ると包囲が成立せず膠着する。それがこの特性の性格。

#### パラメーター

- sight 手負いを見つける視線距離
- stack スキルを重ねる上限本数

#### 行動開始条件

常時

#### 行動ルール

| # | 行動条件 | 行動内容 |
|---|---|---|
| 1 | 間接攻撃できる駒で、移動範囲のどこかから手負いを撃てる | 手負いへ最大間合い |
| 2 | 攻撃射程内に手負いがいる | 手負いを攻撃する |
| 3 | 攻撃射程内に stack 条件を満たさない包囲可能な敵がいる | 損耗が最大の敵を攻撃する |
| 4 | スキル保有で、スキル射程内に stack 条件を満たす包囲可能な対象がいる | 損耗が最大の対象にスキル |
| 5 | 攻撃射程内に包囲可能な敵がいる | 損耗が最大の敵を攻撃する |
| 6 | sight 範囲内の手負いへの移動距離が測れる | 手負いへ最大前進 |
| 7 | sight 範囲内の手負いへの地形距離が測れる | 手負いへ見込前進 |
| 8 | 移動距離が測れる敵がいる | 移動距離が最小の敵へ最大前進 |
| 9 | 地形距離が測れる敵がいる | 地形距離が最小の敵へ見込前進 |
| 10 | 盤上に攻撃できる敵がいる | 盤上距離が最小の敵へ直線寄せ |

拠点は取らない。占領兵を混ぜても拠点へは向かわない。

#1 で下がると、その駒は包囲の頭数から外れる（隣接しなくなる）。包囲は近接・間接の両方に効く（[combat.md](combat.md)）ので、囲むのは近接の駒に任せ、間接の駒は外から撃つという住み分けになる。

#2 だけ包囲を条件にしない。手負いには単独でも噛みつく。盤の誰もまだ傷ついていないターンは最も近い敵が手負いになるので、そこで最初の一噛みが起きる。以後はその相手が損耗最大であり続け、群れが集まる。

#3 は #4 の裏返し。毒が効き切った相手は毒を重ねる価値が無いので殴りに切り替わる。stack が `-`（上限なし）なら #3 は成立せず、毒を重ね続ける。

## 特殊特性一覧

駒の性能から自動で決まる特性。部隊に割り当てる特性に重ねて働き、ステージデータには書かない。行動開始条件と行動ルールは元の特性のものを使い、そこに制約を被せる。

| 特殊特性id | 特殊特性名 | 適用条件 | 概要 |
|--------|--------|------|------|
| transport | 輸送ユニット | 搭載数が2以上 | 運ぶことに徹する。自分からは戦わず、部隊の中で最後に動く。 |

## 特殊特性詳細

### 輸送ユニット

運ぶことに徹する。自分からは戦わず、部隊の中で最後に動く。

#### 狙い

運搬役だと盤面から分かるようにする。殴り合いに加わらない駒が拠点へ寄っていくので、プレイヤーは中身が降りる前に潰すかどうかを選ぶことになる。輸送の撃破は乗員も巻き添えにする（[movement.md](movement.md) 輸送の撃破）ので、先に潰せば一度に落とせる。

#### 適用条件

搭載数が2以上。搭載数1の駒（1体だけ乗せて戦う騎乗など）は輸送ユニットとして扱わない。元の特性のまま戦う。

#### 扱い

- 部隊の中で最後に動く。同じ部隊の駒が乗り込んでから動くため。順番の中で最後というだけで、行動順そのものは部隊の order に従う
- 目的地hexには乗らない。拠点を目指すなら拠点hexの手前で止まる。塞ぐと運んできた占領兵も他の味方も拠点へ入れない
- 攻撃しない。自分から仕掛けないという意味で、殴られたときの反撃は起きる（[combat.md](combat.md)）。攻撃力を持つ輸送（飛空艇）も、敵として置く限りは撃たない
- 乗員の乗り降りをいつ行うかは、被せた特性の行動ルールが決める（raid なら #4・#5）

輸送を運搬役として使うかどうかも搭載数2以上で線を引く。乗る側は同じ部隊の輸送ユニットだけを便乗の相手に数える。

## データ構成

特性の中身（行動開始条件・行動ルール）は本書が正本で、コードが実装する。データに持つのは、特性ごとのパラメーターの既定値と、どの部隊がどの特性かの割り当ての2つ。

### 特性 ＝ `data/ai/ai.csv`

CSV正本 → `ai.json` 生成。terrain・movement と同じパイプライン（[units.md](units.md)）。`.csv` は `importer="keep"` 必須。

| 列 | 内容 |
|---|---|
| `ai` | 特性id（`charge` / `ambush` / `raid` / `weak` / `swarm`） |
| `name` | 表示名 |
| `sight` | 索敵範囲（視線距離）。`-`＝その特性は使わない ／ `*`＝上限なし（盤全体。ただし視線コスト `x` の壁は遮る） |
| `stack` | スキルを重ねる上限本数。`-`＝上限なし |

- 2行ヘッダ（1行目が列id、2行目が日本語見出し）
- 全セルを明示する。`-` は「該当なし」を表す値であって空欄ではない
- 特性が使わないパラメーターの列も `-` で埋める。CSVを見れば全特性の全パラメーターが値として読める
- 欠損は生成時に検出してデータのバグとして扱う（[architecture.md](../tech/architecture.md) CSV→データ生成のバリデーション）

### 割り当て ＝ ステージJSON

`enemy` セクションで部隊を定義し、特性を参照する。

```jsonc
"enemy": [
  { "order": 1, "name": "手下部屋", "ai": "ambush", "sight": 3,
    "units": [ {"skin":"goblin", "col": .., "row": ..}, ... ] }
]
```

- 部隊が `units` を内包する。`ai`＝特性id
- パラメーターは部隊ごとに上書きできる。無指定は特性の既定（解決順は 部隊の上書き ＞ 特性の既定）
- `order`＝行動順。全部隊に書く
- 陣営はセクションで決まるので駒に `team` は書かない
- 拠点は `bases[]` 側に `ai`・`order`・パラメーターを書く。拠点そのものが1つの部隊（[拠点出撃](#拠点出撃)）。拠点データ自体は [map.md](map.md)
