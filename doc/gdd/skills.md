# ユニットスキル（レシピ・カタログ）

発動者1体で撃てる能動アクション。味方を強化するもの・敵を弱らせるもの・状態異常を解くものがある。陣形スキルと同じ仕組みの上で動く（レシピ・行動完了・状態補正・持続の数え方はすべて共通）。違いは参加者が発動者1体だけで、効果が陣営全体でなく選んだ1体に乗ることだけ。

本書はユニットスキルの正本（カタログ）。冒険譚が増えるたびにここへ追記する。敵が使うスキルも同じ表に載せる（仕組みが同じで、持ち主が違うだけのため）。

## 用語

スキルは2種類あり、総称して「スキル」と呼ぶ。

| 日本語 | 正式名称 | コード・ファイル名 | 何が違うか |
|---|---|---|---|
| 陣形スキル | formation-skill | `formation` | 複数人の配置（レシピ）が揃うと撃てる |
| ユニットスキル | unit-skill | `skill` | 発動者1体で撃てる |

コード側で `unit_skill` と綴らないのは、ユニットの見た目を持つ `unit_skin` と1文字違いになるため（同じ `godot/data/units/` に並ぶと取り違えやすい）。文中の正式名称は unit-skill、識別子は `skill` で通す。

## 共通ルール

- 発動はプレイヤーの明示操作。条件が揃っても自動では出ない。
- 発動者はスキンID で照合する（スキン未指定の駒は種別IDへフォールバック）。陣形スキルと同じ扱い＝ピクシー性能の別スキンはピクシーダストを撃てない。
- 発動者は行動完了。1体は1ターンに1つのユニットスキル／陣形スキルにのみ参加する。
- 対象は隣接1マス以内の1体。味方を強化するもの（ピクシーダスト・ピュリファイ）は自分自身も選べ、敵を弱らせるもの（ヴェノムファング・ドレッドタッチ）は敵だけを選べる。
- 移動した後でも発動できる。隣接の判定は移動先で行う。陣形スキルも発動者は同じ扱い。
- いま効いているユニットスキルは、ユニットを選択したときの情報パネルと戦闘レポートに出る。
- 効果対象が1体のもの（`buff_scope` が `unit`）は演出シーンを出す。攻撃と同じく2体が対峙する画で、兵数が減る代わりに補正が乗る。仕様 → [../tech/combat_scene.md](../tech/combat_scene.md) ユニットスキルの演出。盤の見た目（掛かっている駒の足元の光）と効果音（`map_skill`）は併用する。
- 演出を出すのは、敵もスキルを撃つため。1マス30〜60pxの盤で足元の光だけでは、掛けられたことに気づけない。満員のドレッドタッチは攻防-80で殴られるより重く、機構の重さに演出が釣り合っていなかった。尺の重さはスキップで受ける（→ [../tech/combat_scene.md](../tech/combat_scene.md) テンポ・スキップ）。
- 陣形スキルのカットイン（1枚絵）は付けない＝単独で撃てて毎ターン飛ぶため、毎回1秒挟むとスキップ連打になる。
- 発動者は Lv+1。攻撃の「戦ったら+1・倒したらさらに+1」（→ [combat.md](combat.md)）のうち前半だけが乗る＝スキルでは撃破が起きない。対象は増えない。
- 重ねがけできる。2体が同じ相手に掛ければ効果は足し合わさる。同じスキルの重ねがけも許す（陣形スキルの既定＝同種を重ねないとは扱いが違う）。
- 持続はスキルごとに決める。数え方は陣形と同じで、発動陣営のターン開始で満了判定する（→ [combat.md](combat.md) 状態補正）。
- 敵も放つ。いつ放つか・誰に放つかは特性の行動ルールで決まる（[ai.md](ai.md)）。放つとその駒は行動完了＝そのターンは殴らない。陣形スキル（複数人）はまだ敵が使わない。
- 敵が同じ相手に何本まで重ねるかは特性のパラメーター `stack` で決まる（[ai.md](ai.md) stack 条件）。上限に達した相手には掛けず攻撃に転じる。重ねがけできること自体はルールなので、プレイヤー側は制限されない。
- チャージ（再使用間隔）を持つスキルがある。駒ごとにチャージ量を持ち、毎ターン開始時に +1 される。チャージ量がレシピの必要量に達すると発動できる。発動するとチャージ量は 0 に戻る。盤に出た直後のチャージ量は 0＝溜まるまで撃てない。チャージ量は将来、他のスキルで加速できる余地を残してある。

## レシピ一覧

### ①ピクシーダスト — 単体強化

| 項目 | 内容 |
|---|---|
| 発動 | ピクシー1体（単独） |
| 対象 | 自分自身、または隣接する味方1体 |
| 効果 | 対象の実効攻撃力・実効防御力に `10 × 発動したピクシーの残兵数` を加算 |
| 持続 | 自軍ターン3回ぶん（3回目の次の自軍ターン開始で満了。間の敵ターンでは減らない） |

- 加算は実効値に対して行う＝レベル・包囲・地形の補正は乗らない。満員（8体）なら常に +80 と読める。
- 強さを決めるのは掛ける側の残兵数。損耗したピクシーが撒く粉は薄い。
- 値は発動した瞬間に決まり、以後は動かない。掛けたあとにピクシーが削られても倒されても、掛かった補正は変わらない。
- ピクシーは攻防10・移動5の飛行で、単体では戦えない。撃つ相手を選んで前線へ運ぶのが役割になる。

### ②ヴェノムファング — 単体弱体

| 項目 | 内容 |
|---|---|
| 発動 | ロックサーペント1体（単独） |
| 対象 | 隣接する敵1体 |
| 効果 | 対象の実効攻撃力・実効防御力に 0.9 を掛ける |
| 持続 | 発動側ターン3回ぶん（3回目の次の発動側ターン開始で満了。間の相手ターンでは減らない） |

- 1本では軽い（攻防10%減）。効いてくるのは重なったときで、2本で 0.81（約2割減）、3本で 0.73（約3割減）、4本で 0.66（約1/3減）と急に危うくなる。ロックサーペント自体の攻撃力は低く、脅威は毒の側にある。
- 係数は掛け合わさるので、重ねても 0 にはならない。行動不能にはならず、痛いだけで済む。
- 持続が3ターンあるので、2体が交互に刺せば毒が切れない。群れが3体以上いると重なりが増えていく。
- 味方1体を強化するピクシーダストと、対象が敵になる点だけが違う。仕組みは同じ状態補正。

### ③ピュリファイ — 状態異常の解除

| 項目 | 内容 |
|---|---|
| 発動 | クレリック／プリースト／ビショップ1体（単独） |
| 対象 | 自分自身、または隣接する味方1体 |
| 効果 | 対象に掛かっている有害な状態補正をすべて取り除く |
| 持続 | 即時（持続しない） |

- 取り除くのは有害なものだけ。ピクシーダストのような味方から掛かった強化は残る。
- 1回の発動で対象に掛かっている有害な補正を全部落とす＝ヴェノムファングが3本刺さっていても1回で済む。聖職の行動1回と引き換えなので、掛けられた数が多いほど得になる。
- 発動者はホーリーアリアと同じ顔ぶれ（占領兵の系統）。

### ④ドレッドタッチ — 単体弱体

| 項目 | 内容 |
|---|---|
| 発動 | ゴースト1体（単独） |
| 対象 | 隣接する敵1体 |
| 効果 | 対象の実効攻撃力・実効防御力から `10 × 発動したゴーストの残兵数` を減算 |
| 持続 | 発動側ターン3回ぶん（3回目の次の発動側ターン開始で満了。間の相手ターンでは減らない） |

- ピクシーダストの符号を反転させた形。加算は実効値に対して行い、満員（8体）なら -80 と読める。値は発動した瞬間に決まり、以後ゴーストが削られても倒されても変わらない。
- 強さを決めるのは掛ける側の残兵数＝ゴーストを削れば効きが薄くなる。対処法が盤の上に見える。
- ゴーストは攻防10・移動5の飛行で、射程1。掛けるには隣接する必要があり、防10 なので次の相手ターンにはまず消える。ゴースト1体と引き換えに相手の1手を奪う駒で、単体では機能しない。
- 冒険譚2 で飛行に触れられるのは魔法兵だけ（前衛・聖職は `atk_air=0`）。掛けられた側が反撃で始末できるとは限らない。

### ⑤スライムスプリット — 分裂

| 項目 | 内容 |
|---|---|
| 発動 | スライム1体（単独） |
| 対象 | なし（隣接する空きマスへ自動配置） |
| 効果 | 発動者の複製を1体、隣接する空きマスに生成する |
| 持続 | 即時（持続しない） |
| チャージ | 3ターン |

- 生成された駒の兵数は発動時点の発動者の兵数を引き継ぐ。最大兵数は type の既定値（8）。削ってから分裂させれば弱い個体しか出ないが、拠点に入れば満員まで回復できる。
- 発動者の兵数は減らない。頭数が増えるぶん総戦力が増える。
- 増殖の上限は設けない。隣接に空きマスが無ければ発動できず、チャージ3ターンで速度を抑える。
- 状態補正を掛けるスキルではない。効果の型は `spawn`（駒を盤に追加する）で、既存の `buff` / `cleanse` とは別の経路を通る。
- 対象選択は不要。空きマスの中から自動で1つ選ぶ（プレイヤーに選ばせない＝敵専用スキルのため）。
- 演出シーン（2体が対峙する画）は出さない。盤上で湧く位置を光らせるだけ。

### ⑥ポイズンスティング — 継続ダメージ

| 項目 | 内容 |
|---|---|
| 発動 | スコーピオン1体（単独） |
| 対象 | 隣接する敵1体 |
| 効果 | 対象の残兵が毎ターン 1 減る |
| 持続 | 発動側ターン3回ぶん（3回目の次の発動側ターン開始で満了。間の相手ターンでは減らない） |

- 減るのは対象側のターン開始時。掛けられた側が自分の手番の頭で気づける。発動側のターン開始にすると相手のターン中に減って見落とす。満了の数え方だけは他のスキルと同じで発動側ターン開始。
- 残兵1で止める。毒では全滅しない。倒すのは戦闘の役目で、殴らずに毒だけで削る戦法を最適解にしないため。
- 重ねがけは加算。2本刺されば毎ターン2減る。ピュリファイ1回で全部落ちるのは他の弱体と同じ。
- 攻防を下げるヴェノムファング（②）の上位版にはしない。効果の軸を変えることで、2つが並んだときに役割が分かれる。ロックサーペントは硬い相手を柔らかくし、スコーピオンは居座った相手を追い立てる。
- 兵数が直接減る唯一の弱体。回復拠点・泉へ下がる理由が毒の側から生まれる。
- 演出シーンでは兵量バーは動かない。掛けた瞬間には減らず、最初に減るのは次の対象ターン開始のため。損害数の位置には毒が掛かったことを出す（→ [../tech/combat_scene.md](../tech/combat_scene.md) ユニットスキルの演出）。
- エフェクトは当面 `thrust`（刺突の汎用。斬撃と同じ銀白の横一文字）を指す。毒の色は絵に持たせず、盤の弱体の輪と演出の表示で受ける。毒だと絵でも示したくなったら、同じ形の毒色の変種を足して差し替える。

## 実装方針

- データ化の形式は陣形スキルに揃える。当面 `godot/domain/formation/` にレシピとしてハードコードし、増えたら CSV/JSON 化を検討する。
- レシピは演出で使うエフェクトID（`combat_effect`）を持てる。書かなければ発動者スキンの `combat_effect` へ落ちる。エフェクトの単位を「誰が撃ったか」ではなく「何を撃ったか」にするための列で、ピュリファイはクレリックが撃ってもビショップが撃っても同じ絵になる（→ [../art/units.md](../art/units.md) §3.4 と同じ考え方）。
- 発動音はレシピIDで引く（`godot/assets/sfx/{recipe_id}.ogg`）。陣形スキルと同じ規約解決で、絵とはキーが別＝エフェクトの音へ落とさない（→ [../audio/sfx.md](../audio/sfx.md) 動的解決）。鳴らすのは演出シーンの一撃が出る瞬間で、発動と同時ではない。
- 状態補正エントリは `scope: unit`・`op: add` で積む（既存の器をそのまま使う＝新しい演算は要らない）。発動者の残兵数を掛けた値をエントリに焼き込むので、集計は掛けられた側だけを見れば済む。
- 対象選択の操作は陣形スキルの着弾ヘックス指定と同じ流れを使い、選べる範囲を自分＋隣接の味方に絞る。敵を対象にするスキル（ヴェノムファング・ドレッドタッチ）はレシピの `buff_side:"enemy"` で絞り込み先を敵に替える（既定は `"ally"`）。
- 状態補正エントリは強化か弱体かを持つ（レシピの `buff_kind` → エントリの `kind`。値は `buff` / `debuff`、省略＝`buff`）。ピュリファイが落とす対象と、下の盤の見た目の出し分けがこれを見る＝値の符号から推測しない（「攻撃は下がるが防御は上がる」ようなスキルが出たときに破綻するため）。真偽値ではなく種類で持つのは、あとから「強化でも弱体でもない印」が要るときに値を足すだけで済むから。
- 盤の見た目は強化／弱体の2値まで。強化＝黄緑、弱体＝紫で、掛かっている駒の足元に出す。両方効いていれば両方出す（弱体＝内側の太い輪／強化＝その外側の細い輪＝半径が重ならないので互いを潰さない）。
  - スキルごとに色を割り当てないのは、増えるたびに覚える色が増え、1マス30〜60pxでは区別できないため。何が何本効いているかは情報パネルと戦闘レポートに出るので、盤は向きだけ伝えれば足りる。
  - 塗りではなく輪にするのは、塗ると立ち絵の足元に隠れて前側の三日月しか見えないため。弱体を内側・太くするのは、掛けられたことに急いで気づく必要があるのが弱体の側だから（強化は自分で掛けたので知っている）。
  - 弱体を赤にしないのは敵陣営の色と紛れるため。淡い紫だと明るい地形に沈むので、明度を落とした濃い紫にする。
- ポイズンスティングは補正値を積むのではなく、持続の間ターン開始に兵数を減らす＝効果の型 `dot`（`buff` / `cleanse` / `spawn` とは別の経路）。持続と解除は既存の器に乗せるため、エントリ自体は `kind: debuff`・`scope: unit` の状態補正として積み、補正チェーンには参加させない。減算は残兵1で止める。
- ピュリファイは状態補正を積まず落とす＝効果の型 `cleanse`（`BattleState.clear_debuffs`）。落とすのは `kind` が `debuff` で対象1体（`scope:"unit"`）のエントリだけ。陣営全体に掛かった補正を1人のピュリファイで消せてしまわないための線引きで、味方から掛かった強化も残る。着弾が起きないのはホーリーアリアと同じ＝戦闘結果は空・レベルは上がらない。
