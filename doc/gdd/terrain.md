# 地形

盤に敷く地形の考え方。ルール（攻防・視線・移動）と見た目（絵・高さ）の受け持ちを決める。

係数と移動コストの中身は [combat.md](combat.md) 地形効果／[movement.md](movement.md)、絵の作り方は [../art/terrain.md](../art/terrain.md)。

---

## 二層（タイプとスキン）

地形はタイプとスキンの二層で持つ。

| 層 | 正本 | 受け持ち |
|---|---|---|
| 地形タイプ | [terrain_type.csv](../../data/terrain/terrain_type.csv) | ルール。地形攻・地形防・視線コスト・移動コスト |
| スキン | [terrain_skin.csv](../../data/terrain/terrain_skin.csv) | 見た目。絵・高さ・向きのばらし方・繋がり方 |

マップに書く1文字が1タイプ。1つのタイプに複数のスキンがぶら下がり、ステージ側でマスごとに選べる。同じルールを別の舞台の絵で出せる＝崖と花崗岩の崖、荒地と墓標の荒れ地。

---

## 種類（足場とオブジェクト）

地形タイプは足場かオブジェクトのどちらかである。terrain_type.csv の `layer` 列が持つ。

| 値 | 意味 | 絵 |
|---|---|---|
| `footing` | 地面そのもの | 上面（ヘックス1枚）＋側面（段差に貼る帯） |
| `object` | 地面の上に載るもの | 立ち絵1枚。足場の上に立てる |

1マスに置くのは1タイプだけで、ルールを出すのもそのタイプだけ。オブジェクトのマスに敷かれた足場は見た目専用で、攻防にも視線にも移動にも関与しない。

分類は盤への置かれ方で決まる。面や線として敷くものが足場、点として置くものがオブジェクト。柵だけは線として敷くがオブジェクト（→ 下記）。

---

## 足場

- 上面はヘックスを覆う1枚。真上から見た絵。
- 側面は段差に貼る帯。左右シームレス。盤が基準高さを持つと段差は盤のいたるところに出るので、足場は側面を持つ。
- 高さ（`elevation`）はスキンが持つ。同じタイプでもスキンごとに違ってよい。
- 側面を描くのは高いほうのタイル。低い隣と接する辺に、自分の側面画像で壁を下ろす。

## オブジェクト

- カメラに正対する板1枚。駒と同じ置き方（[board_unit_renderer.gd](../../presentation/board/board_unit_renderer.gd)）。
- 駒より奥に立てる。同じマスに駒が入るとき、駒が手前・オブジェクトが奥になる。
- 高さは立ち絵が持つ。`elevation` は0、`orientable` は `none`。
- 下に敷く足場をスキンが `map_ground` で指定する。空にしない。

柵と壁だけは例外で、カメラに正対する板ではなく、ワールドに向きを持って立てた板になる。ヘックス中心から、繋がる隣の辺の中点まで。向きは板の置き方が出すので、絵は横から見た1枚で足りる（繋がり方別に64枚を持たない）。

## スキンの命名

```
footing   {型ID}                              road / plain / bedrock
          {型ID}_{持ち味}{連番}                road_stone1（石畳）/ plain_grave1（墓地の草地）

object    {足場スキンID}_{型ID}_{持ち味}{連番}  road_building_town1（道の上の街区）
                                              plain_fence（平地の柵）
                                              plain_grave1_fort_crypt1（墓地の納骨堂）
```

同じ絵の向き違いは末尾に `_v` `_r` `_l` を足す。足場だけが違う変種も、足場名ではなく持ち味で名乗る。

---

## 盤の高さ

ステージは行と列それぞれに基準の高さを持つ。あるマスの高さは3つの和。

```
高さ ＝ 行の基準 ＋ 列の基準 ＋ スキンの elevation
```

行と列の和なので、奥へ上がる盤も、横へ上がる盤も、左上から右下へ流れる盤も、同じ仕組みで書ける。単位は TILE=1.0（ヘックスの中心〜頂点）。

高さは見た目だけを動かす。移動コストにも地形効果にも視線にも入らない。

通れないことを決めるのは、そこに置いた地形タイプである。高さは「通れなさそうに見える」ことだけを担当する。奥を崖で塞ぐなら、基準高さを上げたうえで、通れない地形をそこに置く。両方を書いて初めて、見た目とルールが一致する。

この形で出せるもの:

- 奥へ行くほど徐々に高くなる土地
- 急に高くなる崖で奥へ抜けられない盤
- 山頂に立ち、その先は崖で行き止まりの盤

### ステージデータ

ステージJSONに `height` を置き、`row` と `col` に配列を書く。長さはそれぞれ盤の行数・列数。省略すると全部0＝平ら。

```json
"height": { "row": [0, 0, 0.18, 0.18, 0.36], "col": [0, 0, 0, 0.18] }
```
