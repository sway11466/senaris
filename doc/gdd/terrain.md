# 地形

盤に敷く地形の考え方。ルール（攻防・視線・移動）と見た目（絵・高さ）の受け持ちを決める。

攻防の計算式は [combat.md](combat.md) 地形効果、移動コストは [movement.md](movement.md)、絵の作り方は [../art/terrain.md](../art/terrain.md)。

---

## 二層（タイプとスキン）

地形はタイプとスキンの二層で持つ。

| 層 | 正本 | 受け持ち |
|---|---|---|
| 地形タイプ | [terrain_type.csv](../../godot/data/terrain/terrain_type.csv) | ルール。地形攻・地形防・視線コスト・移動コスト |
| スキン | [terrain_skin.csv](../../godot/data/terrain/terrain_skin.csv) | 見た目。絵・高さ・向きのばらし方・繋がり方 |

マップに書く1文字が1タイプ。1つのタイプに複数のスキンがぶら下がり、ステージ側でマスごとに選べる。同じルールを別の舞台の絵で出せる＝尾根と花崗岩の尾根、平地と洞窟の床。

### 地形タイプの性格

種類・識別文字・性格は `terrain_type.csv` が正本（id と `memo` 列を見る）。攻め寄り・守り寄り・障害・進入不可を、地形ごとの係数と移動コストで表す。拠点（砦）の占領/出撃/回復だけは地形補正とは別レイヤー → [map.md](map.md)。

係数と移動コストの実数はここに書かない（調整で乖離するため）。`terrain_type.csv` / `movement.csv` を見る。川は攻防とも補正なしで、飛行だけが進入できる（低い水面なので視線は遮らない）。橋はオブジェクトの地形タイプ（`=`）で、性能と移動は道相当（作りは [../art/terrain.md](../art/terrain.md) §3.7）。

地形を増やす＝`terrain_type.csv` に1行＋`terrain_skin.csv` に1行＋`movement.csv` に1列（コード不変）。

## 種類（足場とオブジェクト）

地形タイプは足場かオブジェクトのどちらかである。terrain_type.csv の `layer` 列が持つ。

| 値 | 意味 | 絵 |
|---|---|---|
| `footing` | 地面そのもの | 上面（ヘックス1枚）＋側面（段差に貼る帯） |
| `object` | 地面の上に載るもの | 置き方による（→ オブジェクト）。足場の上に置く |

1マスに置くのは1タイプだけで、ルールを出すのもそのタイプだけ。オブジェクトのマスに敷かれた足場は見た目専用で、攻防にも視線にも移動にも関与しない。

分類は盤への置かれ方で決まる。面や線として敷くものが足場、点として置くものがオブジェクト。柵（線として敷く）と橋（面として敷く水平の板）は例外で、どちらもオブジェクト（→ 下記）。

層が分けているのは置かれ方だけで、ルールではない。攻防・視線・移動コストが他のタイプと丸ごと同じでも構わない＝盤への置かれ方が違えば別のタイプにする。

---

## 足場

- 上面はヘックスを覆う1枚。真上から見た絵。
- 側面は段差に貼る帯。左右シームレス。盤が基準高さを持つと段差は盤のいたるところに出るので、足場は側面を持つ。
- 高さ（`elevation`）はスキンが持つ。同じタイプでもスキンごとに違ってよい。負も可（水面のように地面より低い足場）。
- 駒の足元の高さ（`floor`）もスキンが持つ。駒の立ち絵だけがこの高さに立ち、影・兵数バー・リングは上面のまま。`floor` が `elevation` より低ければ駒は地形に沈み（森＝木々の間の地面）、高ければ浮く（水面の上を飛ぶ）。上に立つ地形は両方を同じ値にする。
- 側面を描くのは高いほうのタイル。低い隣と接する辺に、自分の側面画像で壁を下ろす。

## オブジェクト

置き方は3種で、スキンが `placement` で持つ（足場はこの列を持たない）。

| 値 | 置き方 | 絵 |
|---|---|---|
| `standee` | カメラに正対する立ち絵の板（既定） | 立ち絵1枚。駒と同じ置き方 |
| `panel` | 辺に沿ってワールドに立てた板（柵） | 横から見た帯1枚（`{skin_id}_side.png`） |
| `flat` | 水平の板（橋） | タイル1枚。ヘックス形の板として敷く |

- `orientable` は `none`、立ち絵（standee）だけ `flip_x`（左右反転）まで許す。カメラに正対する1枚なので左右は入れ替えられるが、回すと足元が外れ、上下反転は逆さに立つ（→ [../art/terrain.md](../art/terrain.md) 反復対策）。下に敷く足場をスキンが `map_ground` で指定する。空にしない。
- 高さは2列で受け持ちが分かれる＝`elevation` の高さに足場（map_ground）を敷き、`floor` の高さにオブジェクト（と駒）を置く。地面の上に立つ standee / panel は両方0。
- `standee`: 駒と同じくカメラに正対する立ち絵1枚。足元はマス中心より手前に置く＝立ち絵は足元から上へ伸びるので、盤の俯角のぶん体が奥のマスに乗って見えるのを戻す。手前へずらす量はスキンが `object_foot_z` で持ち（正＝手前）、駒の 0.6 より小さくしておけば同じマスに駒が入ったとき駒が手前に立つ。大きさもスキンが持つが、盤はその数値を読まない。立ち絵の余白に焼き込む（→ [../art/terrain.md](../art/terrain.md)）。
- `panel`: ヘックス中心から、繋がる隣の辺の中点まで立てた板。向きは板の置き方が出すので、絵は横から見た1枚で足りる（繋がり方別に64枚を持たない）。
- `flat`: 自分のタイル絵を、ヘックス形の水平な板として `floor` の高さに敷く。足場は `elevation` の高さに敷かれ、板との間に空間が残る。橋はこれで作る＝`elevation` と `ignore_board_height` を川に合わせ、`floor` を岸と同じ0にすると、板は岸の高さに浮き、下の水は絶対水位のまま隣の水面とつながる＝橋の下を水がくぐる。マスごとの高さ上書きはペアがそのまま「水位と板の高さ」になる＝水位を変えた湖にもそのまま架かる（→ [../art/terrain.md](../art/terrain.md) §3.7）。マスの読み取り面（グリッド・オーバーレイ・クリック・駒）は板のほう。

## スキンの命名

```
footing   {型ID}                              road / plain / bedrock
          {型ID}_{持ち味}{連番}                road_stone1（石畳）/ plain_grave1（墓地の草地）

object    {足場スキンID}_{型ID}_{持ち味}{連番}  road_building_town1（道の上の街区）
                                              plain_fence（平地の柵）
                                              plain_grave1_fort_crypt1（墓地の納骨堂）
                                              river_bridge_stone1（川の上の石橋）
```

同じ絵の向き違いは末尾に `_v` `_r` `_l` を足す。足場だけが違う変種も、足場名ではなく持ち味で名乗る。橋のように幅の役を持つスキンは、持ち味と向きの間に役（`_left` `_right` `_mid`）を挟む（→ [../art/terrain.md](../art/terrain.md) §3.7）。

## 盤の高さ

ステージは行と列それぞれに基準の高さを持つ。あるマスの高さは3つの和。

```
高さ ＝ 行の基準 ＋ 列の基準 ＋ スキンの elevation
```

行と列の和なので、奥へ上がる盤も、横へ上がる盤も、左上から右下へ流れる盤も、同じ仕組みで書ける。単位は TILE=1.0（ヘックスの中心〜頂点）。駒の足元（`floor`）も同じ式に乗る＝elevation の代わりに floor を足した高さに駒が立つ。マスごとの高さ上書きを書いたマスだけはこの式に乗らず、書いた値がそのまま高さになる。

高さは見た目だけを動かす。移動コストにも地形効果にも視線にも入らない。

通れないことを決めるのは、そこに置いた地形タイプである。高さは「通れなさそうに見える」ことだけを担当する。奥を崖で塞ぐなら、基準高さを上げたうえで、通れない地形をそこに置く。両方を書いて初めて、見た目とルールが一致する。

この形で出せるもの:

- 奥へ行くほど徐々に高くなる土地
- 急に高くなる崖で奥へ抜けられない盤
- 山頂に立ち、その先は崖で行き止まりの盤

### 盤の高さを無視するスキン

スキンが `ignore_board_height` を持つと、行・列の基準を足さない＝`elevation` と `floor` がそのまま絶対高さになる。水面のように、盤が傾いても一定の高さを保ちたい足場が使う。基準高さは行と列の和なので、水域が複数行にまたがると水面自体が段々になってしまう。無視フラグで水面を1つのレベルに固定し、まわりの地面を基準高さで持ち上げれば、岸の段差は「高いほうが側面を描く」既存の規則で出る。

同じ規則が滝も出す。マスごとの高さ上書きで水位を段にすると、上の水が下の水へ側面を下ろす。川の側面画像は落ちる水なので、その辺が滝になる（→ [../art/terrain.md](../art/terrain.md) §1）。

### マスごとの高さ上書き

ステージは terrain_skins のエントリに `elevation` と `floor` をペアで書くと、そのマスだけ高さを直接指定できる（水面レベルの違う湖・浅瀬など）。片方だけ書くのはエラー＝適用されない。書いた値がそのまま最終の高さで、盤の高さ（行＋列の基準）もスキンの `elevation` / `floor` も足さない。スキンの無視フラグにもよらない＝「このマスはこの高さ」と読める。

```json
{ "col": 4, "row": 2, "skin": "river", "elevation": -0.36, "floor": -0.18 }
```

高さ上書きは見た目の指定なので、既定スキンのマスに書くときもスキンを明示する（エントリはスキン指定と一体で、塗り直すと上書きも消える）。

### ステージデータ

ステージJSONに `height` を置き、`row` と `col` に配列を書く。長さはそれぞれ盤の行数・列数。省略すると全部0＝平ら。

```json
"height": { "row": [0, 0, 0.18, 0.18, 0.36], "col": [0, 0, 0, 0.18] }
```
