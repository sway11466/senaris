# 評価ランク

ステージ勝利時の成績を **S / A / B** の3段階で評価する。「同じ勝ちでも上手い勝ちがある」を示し、再挑戦の動機にする。敗北にはランクを付けない。

## 判定

ターン消費率と生存率それぞれで S / A / B を判定し、**低い方**が最終ランクになる。

- **ターン消費率** ＝ 使ったターン数 ÷ `turn_limit`。S: 50% 未満・A: 75% 未満・B: 75% 以上が基準。
- **生存率** ＝ 残った自軍ユニット数 ÷ 開始時の自軍ユニット数。兵数が減っていてもユニットが生きていれば生存。S: 50% 以上・A: 25% 以上・B: 25% 未満が基準。
  - 数えるのは**盤上＋輸送の中＋拠点の中**。失われた駒だけが数から落ちる＝傷ついた駒を拠点へ退避させても（[map.md](map.md) 回復）生存として数える。開始時も同じ物差しで数える。
  - 拠点の控えは帰属先で数える＝まだどちらにも解放されていない中立の控えは、どちらの数にも入らない。
  - 兵器（移動タイプ `stationary` → [movement.md](movement.md)）は数えない。置いて壊させる駒で、移動0だから拠点へ退避もできない＝使うほど生存率が落ちるのでは、盤に置く判断とランクが逆を向く。撃破も同じ物差しで数える＝敵の兵器を壊した数は戦果に乗らない。

上記の比率を基準にステージごとの具体的な閾値を算出し、ステージ JSON の `rank` に書く。暗黙の計算式には頼らない。

```json
{
  "rank": {
    "turn_s": 15, "turn_a": 22,
    "survival_s": 4, "survival_a": 2
  }
}
```

`rank` が無いステージではランクを評価・表示しない。書くなら4キーとも書く＝片方の軸だけで評価するステージは作らない。低い方を最終ランクにする仕組みなので、片方を空けるとその軸が常に B を返して全体が B に落ちる。抜けはデータ整合テストが検出する。

## 記録

ベストランクを進捗セーブの `ranks` に記録する（`cleared` と並列・`version` 据え置き）。2回目以降は前より良いランクのときだけ上書きする。冒険譚単位の Steam 実績（[../sales/monetization.md](../sales/monetization.md)）が全ステージのランクを参照する。

## 表示

戦果票に押す印がランクそのもの（`S` / `A` / `B`）。行ごとの基準チェックと合わせて、見せ方は [uiux.md](uiux.md) §決着の演出。

セレクト画面では、ステージの木札の右端に同じ印を小さく押す（[stage_select.md](stage_select.md) 状態）。暗い木の上なので封蝋の赤ではなく焼き印の色にする。冒険譚の貼り紙にはランクを出さない＝あそこは制覇したかどうかだけを示す（`DONE` の印）。ランクはステージ単位の評価なので、戦果票と木札で見せる。
