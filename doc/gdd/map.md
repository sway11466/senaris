# マップ・拠点・ステージ

拠点／占領、エネミー＆ステージ構成といった「マップ側」の設計メモ。

---

## 用語

### ターン

**1ターン ＝ 自軍と敵軍が1回ずつ行動する1巡。** ターン板の `turn n / limit`、ステージJSONの `turn_limit`、イベントの `turn` は、すべてこの数え方で数える。

- 1巡の中の各陣営の手番は「自軍ターン」「敵ターン」と呼ぶ。1ターン ＝ 自軍ターン1回 ＋ 敵ターン1回。
- スキルや状態補正の持続も同じ数え方。持続1 ＝ 次に自陣営の手番が巡ってくるまで ＝ 1ターンぶん（[combat.md](combat.md) 状態補正）。
- **「ラウンド」とは呼ばない。** 同じものを2語で呼ぶと持続の勘定がぶれるため、ターンに統一する。

## 勝敗条件

- 原典（ネクタリス）は **「敵全滅」または「敵拠点の占領」を50ターン以内に達成** で勝利。
- **本作＝ステージごとに勝敗条件を「条件リスト」で設定し、いずれか1つで決着（OR）**。【方針確定】
  - **勝利条件**（ステージが組み合わせる）: **殲滅**（敵が盤上から消え、かつ復帰手段＝出せる garrison も無い）／**敵本拠地の占領**（`hq` の敵拠点を取る）／**ボス撃破**（指定ユニット）…（特定hex確保などは追って）。
  - **敗北条件**: 自軍が盤上0 かつ 復帰手段なし（自軍所有の拠点に、出撃できる garrison が1体も無い）／**味方本拠地を奪われる**／**ターン制限を超過**（時間切れ＝引き分けなしで敗北）／**ステージが指定した敗北条件**（守るべき拠点の喪失など。勝利と同じくOR）。勝利の殲滅と対称。拠点の中の控えはまだ生きている戦力として数える＝盤上が空でも、出せる駒がある限り負けにはしない。
  - **殲滅は「盤上＋復帰手段」で数える**：拠点の中の眠り駒（garrison）は盤上に居ないが、出せる控えがある限りその陣営は消滅していない＝決着しない。盤上だけを空にしても敵保持の拠点から出撃してくるので、勝ちきる（敵を消滅させる）には実質その拠点の制圧が要る。
  - **相討ち全滅**は自軍が盤上から消えていれば敗北優先（暫定踏襲）。
  - この「盤上＋復帰手段」で勝敗を見る方式を案Bと呼ぶ。副作用として、盤上0でも控えを出さず引き籠ると膠着しうるため、ターン制限で決着させる（＝時間切れ敗北。下記）。
- **判定**: ステージJSONの `victory` 配列（OR評価）を `BattleState.victory_conditions` が判定する。
  - ボス撃破 `{ "type": "defeat_unit", "actor": "..." }`（ボスの駒に `actor` を書いて名指す。enemy 部隊の `units[]` 内でよい）。デバッグステージ: `godot/data/stages/debug-victory/boss.json`。
  - 本拠地占領 `{ "type": "capture_hq" }`＝`hq:"enemy"` の拠点をすべて自軍が保持で勝利（該当 hq が無ければ不成立＝空勝ち防止）。**`hq:"player"` の拠点を奪われたら敗北**（常時ルール・hq を置いたステージだけ効く。奪還で解消）。本拠地の印は所有者と独立なので、開始時に敵へ奪われている味方の本拠地（`hq:"player", team:"enemy"`）も書ける。デバッグステージ: `godot/data/stages/debug-victory/hq.json`。占領は移動の瞬間に起きるため、決着チェックは移動直後にも走る（MatchController）。
  - 敗北条件も同じくリスト＝ステージJSONの `defeat` 配列（OR評価）を `BattleState.defeat_conditions` が判定。勝利側と同じ器で、判定は `Victory.defeat_condition_met`。未知タイプは不成立（前方互換）。
    - 拠点の喪失 `{ "type": "lose_base", "bases": [ { "col": C, "row": R }, … ] }`＝名指しした拠点が敵所属になったら敗北（奪還で解消。盤に拠点が無い座標は「まだ失っていない」扱いで不成立＝指定ミスで即敗北にしない）。**hq喪失の常時ルールとは別軸**＝あちらは陣営の要（本拠地）、こちらはステージが名指しする守り物（護衛する町・預かった砦）。中立拠点でも指定できる。
    - 護衛対象の喪失 `{ "type": "lose_unit", "actors": [ "…", … ] }`＝名指しした駒が撃破されたら敗北（勝利側の `defeat_unit` と対。駒に `actor` を書いて名指す）。
    - **1条件の中は AND、条件どうしは OR**＝対象を複数持てて、その条件が成立するのは全部失ったとき。「AもBも失ったら負け」は1条件に2つ、「AかBを失ったら負け」は1つずつ2条件、と書き分ける。対象が空の条件は不成立（空指定で即敗北にしない）。
    - デバッグステージ: `godot/data/stages/debug-victory/defend_base.json`（1つ）・`defend_two.json`（2つのAND）。マップエディタの「勝敗」モードで指定・確認できる（パネルで条件を追加＝OR、その条件に対象を追加＝AND）。
  - 殲滅勝ち/全滅負けは条件リストと無関係に常時有効（相討ち・hq喪失は敗北優先）。**敗北は勝利より優先**＝同時に成立したら負け。**閉じ込め判定（案B）**＝消滅を「盤上0 かつ 復帰手段なし」で判定（`_has_reinforcement`）。
  - **ターン制限**＝ステージJSONの `turn_limit`（1ターン＝両陣営1巡）。`turn_number > turn_limit` で**時間切れ敗北**（引き分けなし・勝利条件を満たしていればそちらが優先）。**実ステージJSONでは必須**（`load_file` が未指定/0以下を push_error＝データのバグ扱い）。値はステージごとに決める。`build` は未指定を素通し（0＝無制限。合成テスト用）。決着チェックは `MatchController.end_turn` でも走る（ターン跨ぎで発火）。

## 拠点・占領

- **拠点＝城・砦（軍事拠点）** と定義する。
- 拠点は4つの機能を持つ: **①防御地形 ②占領（即時） ③出撃（ネクタリス方式） ④回復（休憩）**。

### 拠点＝地形（防御に強い）

- 拠点は **守りに寄せた地形タイプ**（`fort`＝砦）として `terrain_type.csv` に持つ。攻は下げ、防は上げる（係数は CSV 参照）。移動は地上コスト1（普通に入れて占領できる）。
- 見た目・地形補正・移動コストは既存の地形システムに乗る（[combat.md](combat.md) 地形効果／[movement.md](movement.md)）。占領・出撃・回復のロジックは地形とは別レイヤー（後述）で持つ。
- **「占領可能な拠点かどうか」は地形ではなく `Base` の有無で判定する**（`state.base_at(hex)`）。地形 `fort`/`castle` は防御＋見た目だけで、`Base` とは**自動連動させずステージで重ねて配置する**【現状維持の方針】＝`Base` の無い fort は単なる防御地形、平地の上の `Base` も占領可。実装は [base.gd](../../godot/domain/capture/base.gd)・`BattleState`。

### 拠点の値（team / rest / hq）・ユニットの陣営（native / recruited）

拠点は3つの値を別々に持つ。占領で動くのは `team` だけで、他は不変。

- **`Base.team`（可変）＝ 現在の所有者**（味方／敵／中立）。占領で変わる。出撃できるかを見るときの「いま誰のものか」。
- **`Base.rest`（不変）＝ 誰が中に入って回復できるか**（味方／敵／両方。JSONキーは `rest`）。占領しても変わらない。敵の納骨堂を味方が取っても休めない、を表す。
- **`Base.hq`（不変）＝ 本拠地の印と、その陣営**（味方／敵。JSONキーは `hq`。無ければ普通の砦）。勝敗条件だけが見る。所有者とは独立＝開始時に奪われている本拠地も書ける。

拠点は「生まれつき誰のものか」を持たない。味方拠点・敵拠点・中立拠点という言い分けは開始時の所有者の話で、規則上の違いは無い。控えの駒がどう振る舞うか（寝返るか・閉じ込められるか）は、拠点ではなく**ユニット側の生来の陣営 `native`** で決まる（下記「帰属」）。

- **native=味方の控え**: 自軍が出撃できる味方の控え。敵に拠点を取られると閉じ込め（捕虜）＝敵の戦力にはならない。
- **native=敵の控え**: 敵が出撃させる＝**湧き元**。味方が占領すると湧きを止められる（denial）。
- **native=中立の控え**: 取った側が解放して自分の戦力にできる（下記「帰属」）。
- 1つの拠点に native の違う控えを混ぜてよい。取った側は自分の駒だけ出せ、相手の駒は閉じ込める。

#### 帰属（recruited_team）

ユニットは陣営を表す値を3つ持つ。役割が違うので混ぜない。

| 値 | 意味 | 変わるか |
|---|---|---|
| `native_team` | 生来の陣営。ステージ初期の所属 | 不変 |
| `recruited_team` | 帰属先。どちらの戦力として世に出たか | 中立の駒が解放された瞬間に一度だけ確定 |
| `team` | 現在の陣営。盤の上でいまどちらとして振る舞うか | 占領・出撃で動く |

- 既定は `native_team` と同じ。最初から味方の駒は自軍、敵の駒は敵で確定済み＝全駒が常に帰属先を持つ。
- 中立 native の駒だけ帰属が未確定で、出撃（解放）した側に確定する。先に取ったほうの仲間になる争奪がここで決まる。
- 確定後は不変。拠点を奪い返されても帰属は動かない＝寝返らない。
- JSONには書かない。データ上は `native` から導出する。**控えの駒の `native` は必須**（拠点からの既定は無い。書き忘れは読み込みで警告）。

### 占領（即時）

- **占領できるのは兵種「占領兵」**（cleric / priest / bishop / paladin ＝ `can_capture` true）。兵種が占領兵なら占領可、という対応で揃える（unit_type.csv の兵種列と `can_capture` を一致させる）。
- そのうち **ステージ設計の軸になる3アーキタイプ**を据える（残りの priest＝高火力 も占領兵として併用できる）:
  - **クレリック**：安価で脆い（数で押す／使い捨て寄り）。
  - **ビショップ**：高耐久で保持向き（占領した拠点を守る）。
  - **パラディン**：戦えるエリート（占領しつつ前線でも機能）。
- **占領＝即時**: 占領可ユニットが敵・中立の拠点hexへ移動すると、コマンドメニューの「待機」が **「占領」** に変わる（[uiux.md](uiux.md)）。選ぶと移動が確定し、その拠点の所属が自軍へ移る。専用コマンドではなく待機のラベル変更で、domain が自動占領する。駐留敵がそのhexに居る間は進入できない（倒してから入る）。

### 出撃（ネクタリス方式・寝返り／解放）

- 拠点は中に **garrison（眠っている控え駒）** を抱える＝**初期配置ぶん＋回復で中に入ってきた駒**。
- **出撃**: 所有者は garrison から1体を選び、**拠点に隣接する空きhexへ1歩で出す**（出した駒はそのターン行動完了・次ターンから通常行動）。出撃できるのは「**拠点の所有者＝その駒の帰属先**」のとき（帰属未確定の駒は所有者を問わず出せる）。
- **出せるのはその駒が入れる地形だけ**＝進入不可の地形（歩行にとっての壁・瓦礫など）は出撃先にならない。判定は移動タイプごと＝同じ瓦礫でも飛行なら出せる。壁の上に湧いて動けない駒を作らないため。
- **そのターン行動を終えた駒は出撃させられない**。「入る」も1手＝行動終了なので、入って出るの往復（実質ノーコストの再配置）は成立しない＝次の自軍ターンから出せる。初期配置の控えと占領で手に入れた控えは行動していない＝この制限を受けない（初手から出せる）。
- **出撃→直接乗車**: 拠点に隣接する**乗れる味方輸送のマスも出撃先になる**＝garrison の駒をそのまま輸送に乗せられる（盤上には出ない・そのターンは降ろせない）。詳細 → [movement.md](movement.md)（輸送）。
- **占領時の挙動は帰属で決まる**:
  - 帰属が未確定の駒（native=中立でまだ誰にも解放されていない）→ 占領した側が出撃させられる＝取った側の戦力になる。出した瞬間に帰属が確定する。
  - 帰属が確定済みの駒（native=味方／敵、または一度解放された元中立）→ 寝返らない。相手に拠点を奪われると中に閉じ込められ出られない（再奪還で再び出せる＝「眠っていた敵が復活」）。だが消えてはいない。
  - つまり中立の駒が取った側に付くのは最初の一回だけ。味方が解放したエルフを敵が拠点ごと奪っても、敵の戦力にはならず捕虜になる。
- **殲滅カウントは盤上のみ**：中の眠り駒は数えない。味方が敵拠点を制圧すれば中の敵は出られず、殲滅勝利を妨げない（[勝敗条件](#勝敗条件)）。
- **garrison の種別・数・生来の陣営（`native`）はステージデータで指定**（例: 囚われた町人を **ノービス×2・native=player**）。`native` は駒ごとに必須。**type に制限は設けない**＝中立拠点のドラゴンを味方が解放すれば味方のドラゴンになる（拾い物が強いほど占領が嬉しい）。見た目は type に紐づくスキンをそのまま使う（味方側スキンを持たない type は敵側の絵のまま出る）。陣営で絵を変えたければスキンを足す＝アート側の話で、配置のルールでは縛らない。

### 回復（休憩）

- 駒は**自軍拠点の中に入って回復**（ネクタリス式）＝hex の“上”に乗るのではなく garrison として中で休み、兵数が max まで回復してから出撃で戻す。**兵数のみ回復、Lvは据え置き**。
- **回復できるか（＝中に入れるか）は拠点の `rest` で決まる**（味方／敵／両方）。`rest:"enemy"` の拠点は味方が奪っても入れない＝出撃拠点にしかならない。出撃は `rest` と無関係で、所有者なら控えを出せる（納骨堂の控えにファイターが居れば、取った味方が出せる）。
- 回復で中に入った駒も garrison 扱い＝**閉じ込め／寝返りのルールが同様に効く**（味方拠点が奪われれば、中で回復中の味方は閉じ込められる＝出られないが味方のまま）。
- **輸送は積載ごと中に入る**＝入った時点で荷を降ろし、搭乗駒も garrison になる（全員が回復・出撃の対象）。→ [movement.md](movement.md)（輸送）

### 中に入る／帰属（native）

- **回復＝「中に入る」モデル**: 自軍所有の拠点hexで移動確認メニューの**「入る」**を選ぶと garrison になり盤上から消える（**選択式**＝上に立って fort 地形で守る選択も残る）。ターン開始で**満員へ全回復**（Lv据え置き）。出るのは出撃（1歩・行動完了）。**`rest` が自軍を含まない拠点には入れない**（回復できない＝入る意味が無いので、入る操作ごと出さない。出撃拠点にはなる）。収容数は無制限。**盤上最後の1体でも、入った直後に復帰手段が残るなら入れる**（案B＝`can_enter_base_at`。全周封鎖など入れば即敗北になる場合だけ不可）。
- **`Unit.native_team`（生来の陣営）**: 盤上の駒は既定＝初期陣営で、ステージJSONの `"native"` で上書き可。garrison の駒は `"native"` 必須（既定なし）。閉じ込め駒は回復もしない。
- 出撃の可否は帰属で見る＝帰属未確定なら誰でも出せる／確定済みは「所有者＝帰属先」のときだけ出撃可（奪われた駒は閉じ込め・奪還で復活）。

## ステージデータの構成

- ステージは JSON データで記述する（ASCII地形グリッド＋ユニット配置）。データは `data/`、それを盤面(BattleState)に組み立てるローダー `StageLoader` は `application/`（data＋domain の両方に依存するため）。詳細 → [../tech/architecture.md](../tech/architecture.md)。
- ステージは冒険譚ごとのフォルダに束ねる: `godot/data/stages/<冒険譚>/<ステージ>.json`（→ [campaigns.md](campaigns.md) ステージの束ね方）。
- 演出・見た目のキー（presentation 専用＝BattleState には入らない）:
  - `dialogue`: 戦闘前後の会話 `{ "intro": [...], "outro": [...] }`・各行 `{speaker, skin, text}`・テキストは翻訳キー。仕様 → [../campaign/authoring.md](../campaign/authoring.md)
  - `terrain_skins`: 地形の見た目差分（座標→skin_id の列挙。未指定セルは type の既定スキン）。性能の `terrain` グリッドとは別レイヤー
  - `margin`: 外周＝盤の外側に何マスぶん地形を描くか（下記）

### 外周（margin）

盤の縁のマスは「盤の外に何があるか」が分からない。柵や道のような繋がる地形（`connect`）はそれで絵が決まるので、外側を作者が描けるようにしたのが `margin`。

- `cols` / `rows` は遊べる盤のまま。`terrain` だけを外周ぶん大きく書き、厚みを `margin` で言う。グリッドは `(cols + 2*margin)` 文字 × `(rows + 2*margin)` 行。
- 駒・拠点の座標は盤の0起点のまま。ずれるのは `terrain` の読み出し位置だけで、`margin: 0` なら書き方も挙動も従来と変わらない。
- 外周は描かない・駒は入れない・盤（`BattleState`）にも存在しない。接続タイルの向きを引くためだけのデータ。
- 厚みは 1 で足りる。offset 座標では6近傍が必ず col±1・row±1 に収まるので、1周あればどのマスの隣も覆える。
- `terrain_skins` は外周のセルも指せる（`col`/`row` が負値や `cols` 以上になるだけ）。
- 縁の絵がどう決まるかは [../art/terrain.md](../art/terrain.md) §3.5。
- 例（24×9 の盤に外周1周＝26文字×11行）:
  ```json
  "cols": 24, "rows": 9, "margin": 1,
  "terrain": [
    "FFFFFFFFFF%%%%%%%%%%%%%%%%",
    "FFFFFFFFFF%%%%%%%%%%%%%%%%",
    "（中略：盤の9行が1文字ずつ内側に入る）",
    "LLLL....%%%%%%%%FFFFFFFFFF"
  ]
  ```

### 駒の配置（陣営セクション）

- 駒は**陣営ごとのセクション**に分けて書く。**このゲームは味方＝人間操作／敵＝AI操作が1:1**なので、陣営で構造を分ける（駒ごとの `team` は書かない＝セクションが陣営を決める）。
  - **`player`**: 自軍の駒の配列。人間が操作する（AI/部隊は持たない）。
  - **`enemy`**: 敵の**部隊(squad)の配列**。**敵は必ずどれかの部隊に属する**（バラ配置は無い）。各部隊は AI プリセット `ai` を持つ。ただの1波は名前なしの `{ "ai": "charge", "units": [...] }` でよい。
- 各駒（`player[]` / `enemy[].units[]`）の記法は共通: `type`（性能）か `skin`（見た目・性能は逆引き）＋ `col`/`row`＋任意 `troops`（損耗・省略＝満員）／`level`（成長・省略＝1）＋任意 `actor`（下記）。輸送は `passengers:[...]`。`player` の駒にはもう1つ `supply`（名簿との突き合わせ方 → [campaigns.md](campaigns.md) 戦力供給モデル）を書ける。
- 駒に番号は書かない。盤の駒には内部の通し番号（id）が振られるが、これは実行時のハンドルであってデータの語彙ではない。駒を名指すのは `actor` の役目で、勝敗条件も名簿も会話も `actor` を見る。
- **性能は `type` が唯一の出どころ**＝攻撃・防御・移動・射程などをステージ側から上書きすることはできない。ボス個体や強化型が要るなら `type` を足す（数値がステージに散らばるとバランス調整の見通しが効かなくなるため）。駒に書けるのは個体の状態（`troops`/`level`）だけ。
- **部隊(squad)** ＝ `{ "order": 行動順, "name"?: 表示名, "ai": 特性id, ...上書き, "units": [...] }`。`ai` は [ai.md](ai.md) の特性（`charge`/`ambush`/`raid`/`weak`/`swarm`）。`sight`・`stack` は部隊ごとに上書きできる。`order` は敵の行動順（[ai.md](ai.md) 行動順）で、`ai` を持つ拠点も同じ列に並ぶ。
- 例:
  ```json
  "player": [
    { "type": "fighter", "col": 2, "row": 5 }
  ],
  "enemy": [
    { "order": 1, "ai": "charge", "units": [ { "skin": "goblin", "col": 9, "row": 5 } ] },
    { "order": 2, "name": "奥の部屋", "ai": "ambush", "sight": 3, "units": [ ... ] }
  ]
  ```

### 陣営の表記（拠点の team / rest / hq・駒の native）

- **拠点・native の陣営は可読な文字列**で書く: **`"player"`（自軍）／`"enemy"`（敵）／`"neutral"`（中立）**。内部は int 規約（0/1/-1）で持つが、データ側では数値を書かない（`StageLoader` が文字列→int に変換）。駒の陣営はセクションで決まる（上記）ので `team` は書かない。
- **`bases[].team`**: 開始時の所有者。省略時は `neutral`。
- **`bases[].rest`**: 誰が中に入って回復できるか。`"player"`／`"enemy"`／`"both"`。省略時は `both`（エディタは常に書き出す）。占領しても変わらない。
- **`bases[].hq`**: 本拠地の印。`"player"`／`"enemy"` で、その陣営の本拠地になる。書かなければ普通の砦。1陣営に本拠地1つが基本で、複数書けば「全部取るまで勝てない」になる。所有者（`team`）と食い違わせると「開始時点で奪われている本拠地」になる（例: `hq:"player", team:"enemy"`）。
- **`native`**: 駒の生来の陣営（[出撃・寝返り](#出撃ネクタリス方式寝返り解放)を決める）。盤上の駒と搭乗駒は省略時にセクション陣営／輸送と同陣営。**garrison の駒は必須**（`"player"`／`"enemy"`／`"neutral"`）。
- 敵が控えを出す拠点は、その拠点自体が1部隊＝`ai`（特性）と `order`（行動順）を書く（[ai.md](ai.md) 拠点出撃）。書かない拠点は AI 出撃しない。
- 例（拠点＋garrison）:
  ```json
  "bases": [
    { "col": 9, "row": 6, "team": "neutral", "rest": "both",
      "garrison": [ { "type": "novice", "count": 2, "native": "player" } ] },
    { "col": 4, "row": 9, "team": "enemy", "rest": "enemy", "hq": "enemy", "ai": "charge", "order": 40,
      "garrison": [ { "skin": "zombie", "count": 2, "native": "enemy" } ] }
  ]
  ```
  ↑ 1つ目は**中立拠点だが garrison は `native:"player"`** なので、敵に踏まれても寝返らず自軍の解放待ち（囚われの町人）。2つ目は敵の本拠地で、味方が奪っても休めない（`rest:"enemy"`）。

### 名前つきの駒（actor）

`type` は性能の型でしかなく、同じ型の駒が複数いると誰が誰か区別できない。特定の駒を指す必要があるとき（名簿に載る仲間・繰り返し登場するキャラ・勝敗条件で名指すボスや護衛対象）は、駒に `actor` を書いて識別する。データから駒を指す手段はこれ一本。

- 値は冒険譚のなかで一意な文字列。名簿は冒険譚ごとに持つので、冒険譚をまたぐ一意性は要らない。同じ役どころが1人しかいないなら、そのユニット名をそのまま使ってよい（例: `"elf"`）。
- 名簿への出入りと配置（[campaigns.md](campaigns.md) 戦力供給モデル）、会話の分岐（[../campaign/authoring.md](../campaign/authoring.md)）、[勝敗条件](#勝敗条件)の `defeat_unit`／`lose_unit` がこの値を見る。
- 敵の駒にも書ける（ボスの名指し）。名簿に載るのはステージ終了時に自軍へ帰属している駒だけなので、敵の `actor` が仲間になることはない。
- 名前のない雑兵には書かない。書かない駒は名簿に載らず、そのステージ限りで使い捨てになる。
- 勧誘対象は中立拠点の garrison 駒に書く。解放されて初めて名簿に載る。
- 例（勧誘対象のいる中立拠点）:
  ```json
  "bases": [
    { "col": 12, "row": 4, "team": "neutral", "rest": "both",
      "garrison": [ { "type": "elf", "actor": "elf", "native": "neutral" } ] }
  ]
  ```
- 例（次ステージで名簿から配置。加入していなければこの位置は空のまま）:
  ```json
  "player": [
    { "col": 3, "row": 5, "actor": "elf" }
  ]
  ```

### イベント（途中で起きること）

ステージの途中で何かを起こす仕組み。**`events` ＝ 途中で起きることの配列**で、各イベントは引き金（いつ起きるか）と中身（何が起きるか）を1つずつ持つ。引き金は `turn`（Nターン目）か `on`（盤の出来事）のどちらかを書く。中身は `type` で、増援と会話を扱う。

**増援** ＝ 開始時に盤に存在しない駒が、指定のターンに加わること。**この語はこの意味だけに使う。** 拠点の控え（garrison）を出すのは[出撃](#出撃ネクタリス方式寝返り解放)であって増援ではない。盤に居る敵部隊が途中で動き出すこと（[ai.md](ai.md) 行動開始条件）も増援ではない。どちらも既に盤の上にある戦力が動くだけで、戦力そのものは増えていない。

#### 引き金

- `turn` ＝ Nターン目。[ターン](#ターン)の数え方（両陣営1巡）で、そのターンの `team` 側の手番が始まる時点で発生する。
- `on: "capture"` ＝ 拠点の占領。`col`/`row` に書いた拠点の所属が `team` 側へ変わった瞬間に発生する。中立からでも敵からでも同じ扱い（どちらも盤の支配が動いた）。中立拠点の解放も、敵に先を越された瞬間も、これで拾う。
- 発生は1回だけ。同じ引き金に複数のイベントを書いてよい。
- `once` に同じ名前を書いたイベントは互いに排他＝どれか1つが発生したら、残りは以後発生しない。同じ拠点に味方版と敵版の会話を置き、先に起きたほうだけを流す、という書き方に使う。同じ名前が同時に条件を満たしたときは、先に書いたほうが発生する。

#### 増援（`type: "reinforce"`）

- 駒の記法は陣営セクションと共通＝`type` か `skin` ＋ `col`/`row`、任意で `troops`/`level`/`actor`、輸送は `passengers`。**座標は駒ごとに書く。** 隅・辺といった相対指定は持たない（盤ごとに置き場所を選べるようにするため）。
- 置く先が埋まっている／その駒が入れない地形なら、**最寄りの空きへずらす**。ずらせる先が無ければその駒だけ出さず、ログを1行残す。イベント全体は止めない。

#### 会話（`type: "talk"` ／ 増援に添える `dialogue`）

- `dialogue` を書いたイベントは、その場で会話を挟む。増援なら駒を盤へ出してから流し（何が来たのかを盤に見せたうえで喋らせる）、占領なら拠点の所属が変わってから流す。会話の間は盤の操作を止め、読み終える（またはスキップする）と戻る。1ターン目のイベントに書いた会話は流れない（開幕の会話は intro が担う）。
- 駒を出さず会話だけを起こすイベントは `type: "talk"`＝`units` を持たない。
- `on: "capture"` のイベントは敵ターンでも会話を流す。敵の1手ずつの間で盤を止め、閉じてから次の手へ進む。`turn` 起点で `team: "enemy"` のイベントに `dialogue` は書かない＝敵の手番が始まる時点で発生するため、AI が動き出す前に盤を止める場所がない。
- `focus` を書いたイベントは、発生地点へカメラを寄せてから会話を始める。増援の行き先は指定座標ではなく実際に出た hex＝ずれて出ても本当の場所を見せる（盤の端に湧く増援は寄せないと画面の外に出たままになる）。占領は拠点の hex。すでに見えている位置なら動かさない（[uiux.md](uiux.md) 敵ターンのカメラと同じ判定）。

| キー | 意味 |
|---|---|
| `id` | イベントの名前。必須・ステージ内で一意。セーブが未発火のイベントを覚えるのに使う（[../tech/gamesystem.md](../tech/gamesystem.md) 中断セーブ） |
| `turn` | 引き金＝発生ターン（`on` とはどちらか一方を書く） |
| `on` | 引き金＝盤の出来事。いまは `capture`（拠点の占領）のみ（`turn` とはどちらか一方を書く） |
| `col` / `row` | `on: "capture"` が見る拠点の位置 |
| `type` | 何が起きるか。`reinforce`（増援）／ `talk`（会話だけ） |
| `team` | `player` / `enemy`。イベントの主語となる陣営＝増援は加わる駒の陣営、占領は取った側 |
| `once` | 排他の名前。同じ名前のイベントはどれか1つだけ発生する（省略＝排他の相手を持たない） |
| `ai` | 増援の `team` が `enemy` のときの AI プリセット（1つの部隊として加わる。省略＝既定） |
| `order` | 増援が加わる部隊の行動順（[ai.md](ai.md) 行動順）。`team` が `enemy` の増援には必須＝湧いた部隊も行動順の列に並ぶ。抜けはデータ整合テストが検出する |
| `label` | 残りターンの表示に使う翻訳キー。訳文の `{n}` に残りターン数が入る（例「飛空艇 到着まで あと{n}ターン」）。省略＝表示を出さず黙って加わる。`turn` 起点のイベントだけが持つ（`on` 起点は残りターンを数えられない） |
| `units` | 加わる駒の配列（`reinforce`） |
| `dialogue` | 発生した瞬間に挟む会話。ステージの `dialogue` ブロックのキー名を書く（省略＝会話なし）。台本は[../campaign/authoring.md](../campaign/authoring.md) 会話パート |
| `focus` | `true` で発生地点へカメラを寄せる（省略＝寄せない） |

- 例（5ターン目に、パラディンを乗せた飛空艇が盤の南西の隅へ来て、到着の会話が入る）:
  ```json
  "events": [
    { "turn": 5, "type": "reinforce", "team": "player",
      "label": "t2.st7.event.airship",
      "dialogue": "arrive", "focus": true,
      "units": [
        { "type": "airship", "col": 0, "row": 10,
          "passengers": [ { "type": "paladin" } ] }
      ] }
  ]
  ```

- 例（エルフの里を味方が解放したときと、敵に先に取られたときで別の会話が入る。流れるのはどちらか一度だけ）:
  ```json
  "events": [
    { "on": "capture", "col": 12, "row": 4, "team": "player",
      "once": "elf_village", "type": "talk", "dialogue": "elf_join", "focus": true },
    { "on": "capture", "col": 12, "row": 4, "team": "enemy",
      "once": "elf_village", "type": "talk", "dialogue": "elf_lost", "focus": true }
  ]
  ```

**残りターンは常時見せる**（[uiux.md](uiux.md) 残りターン板）。「持ちこたえろ」とだけ言われても、あと何ターン耐えるのかが読めないと我慢の量を測れない。`label` の訳文には何が来るのかを書く（例「飛空艇 到着まで」）。予告なしに戦力が湧くのは避ける形（[map_patterns.md](map_patterns.md) P10 波状）でもある。

  - 標準ロスター ＝ **テーマ0** と位置づける（→ [units.md](units.md) の対応表）。
  - マップに実際に出る分だけ命名すればよい（全テーマ×全種を先に作り込む必要はない）。
