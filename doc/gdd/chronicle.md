# クロニクル

タイトルの「クロニクル」から開く、冒険の記録を読む画面。出会った駒と見た陣形スキルが溜まり、冒険譚ごとに会話／イベント（会話の通し読み）・戦果・設定集・物語が読める。集めるもの（図鑑）ではなく**冒険の記録**として扱う＝名前は日本語でも「クロニクル」（英語 Chronicle）。

マニュアル（[manual.md](manual.md)）が仕組みと用語の説明に徹し、個々のユニット・スキル・物語を持たないのに対し、クロニクルは**プレイヤーが経験した個別のもの**を置く場所。両者の線引きは「仕組み→マニュアル／個別→クロニクル」。

---

## 骨組み

開き口はタイトルのメニューのみ（[title.md](title.md)）。盤の中からは開かない。

中は2つの軸に分かれる。

| 軸 | 章 | 何が溜まるか |
|---|---|---|
| 全体で溜まるもの | ユニット／陣形スキル | 冒険譚をまたいで累積する。どの冒険譚で出会っても同じ枠が埋まる |
| 冒険譚ごとのもの | 会話／イベント／戦果／設定集／物語 | 冒険譚を1つ選んでから読む。冒険譚の一覧が入口 |

- 全体の章は「まだ埋まっていない枠がある」をプレイヤーに見せる。冒険譚の章は「遊んだ冒険を読み返す」。
- 未クリア・未経験のものを匂わせる度合いは章ごとに決める（下記）。ユニット・スキル・設定集は**数だけ**見せ、会話／イベントは**見ていない出来事の存在を出さない**（盤中の「ストーリーを確認」と同じ）。
- デバッグ冒険譚（[stage_select.md](stage_select.md)）で見たもの・遊んだものは、どの章にも記録しない。クリア記録・ランクと同じ扱い。

## ユニット

- **単位はスキン**（`skin_id`・[units.md](units.md)）。性能（type）は複数スキンで共有されるので、プレイヤーが覚える見た目で1枠。同じ性能の別スキン（プリーストとスケルトン）は別枠。
- **並びと束ね**は `unit_skin.csv` の分類（`category`）と行順をそのまま使う（[../art/units.md](../art/units.md) §2）。クロニクル専用の順序は持たない。味方の章は兵種で並び（歩兵・占領兵…）、敵の章は素性で並ぶ（ゴブリン・アンデッド…）。見出しは `unit_group.<id>.name` で引く。
- **埋まる条件は「盤に現れた」**。味方は参戦した時点、敵は盤上に出た時点（増援・拠点からの出撃・敵が解放した中立を含む）。戦った／倒したまでは求めない＝逃げ切る遊びや間接攻撃だけの回で埋まらず、盤の判断と記録が逆を向くのを避ける。プレイヤーが見る前に退いた駒は無い（敵ターンに出た駒は自ターンに盤にいる）ので、これで足りる。
- **載せるもの**
  - 絵：盤の絵（`map`）と戦闘演出の絵（`combat`・[../art/overview.md](../art/overview.md)）。
  - 名前（`unit.<skin_id>.name`）と分類。
  - 性能の数値：対地攻撃・対空攻撃・貫通率・防御・移動（タイプ）・射程・攻撃後移動・兵数・搭乗・占領。**数値の一覧はここが担う**（マニュアルは数値を載せない方針）。
  - ユニットスキル（[skills.md](skills.md)）：その駒が撃てるものを性能の一部として載せる。発動者が1体なので駒の枠に属し、駒が埋まれば読める＝別枠にしない。
  - 短い説明文（`unit.<skin_id>.desc`・`chronicle.csv`）。
- **未解放の枠**：黒いシルエットのカードで置き、名前は「？」で伏せ、押しても開かない。分類ごとに「埋まった数／全部」を出す。総数を見せるのが「まだある」の合図。
- **見せ方**：分類ごとに束ねた羊皮紙のカードを格子に並べる。格子のカードに載るのは盤の絵と、その下の名前の1行。数値は出さない。盤の絵は切り抜かず、盤と同じ大小関係で載せる＝キャンバスの下端から 200×1.3 px を紙の高さに当て、足元を紙の下端に揃える（[../art/units.md](../art/units.md) キャンバスが大きさの基準）。倍率 1.3 までの駒が紙に収まり、超える駒（レッドドラゴン）は紙をはみ出す＝切らない。カードを押すと拡大したカードが手前に開き、盤の絵と戦闘演出の絵を並べて、上に挙げたものを載せる。閉じると格子へ戻る。

## 陣形スキル

- 単位はスキル（[formations.md](formations.md) スキル一覧）。ユニットスキルはここに置かない（上記）。
- **埋まる条件は「盤で発動された」**。自分が撃っても、敵に撃たれても解放。冒険譚2でトリニティノヴァ・グレイス・ディバインジャッジメントを教わる順（st3／st5／st7）と自然に一致する。
- **並びと束ね**は [formations.md](formations.md) 表A の「分類」列と行順をそのまま使う（ユニット章が `unit_skin.csv` に従うのと同じ）。クロニクル専用の順序は持たない。分類は 弓攻撃・魔法攻撃・特殊攻撃・強化・弱体化・その他 と、敵のスキルをまとめた「敵」。敵のスキルは効果で分けない＝プレイヤーが探して使うものではないので、味方の束に混ぜて組めないスキルを探させない。見出しは `skill_group.<id>.name` で引く。
- **載せるもの**
  - 絵：カットインの絵（`assets/formations/<id>.png`・[../art/keyvisual.md](../art/keyvisual.md) 陣形スキルの絵。発動者ごとに絵が分かれるスキル（トリックショット）は「発動者になれる駒」の先頭のスキンの絵＝`trick_shot_archer.png`）と、レシピの図。図は形どおりのヘックス配置に要るスキンの盤の絵を置いたもので、形ごとに配置を1つ決める。対象の周りを見る形（斥候型・背後型）は対象の敵ヘクスも描かないと形が伝わらないので、敵ヘクスに敵の代表＝ゴブリンの駒を置く。斥候型は弓兵を対象から距離2に、斥候を対象に隣接し弓兵には隣接しない位置に置く＝2人が隣り合わなくてよいことが図で読める。背後型はその形を実装するときに図も足す。
  - 名前（`skill.<id>.name`）と分類。
  - 効果・射程・持続・人数・発動できる駒。
  - 発動条件（並べ方）。図は代表の配置を1つ描くだけなので、成立の条件は言葉でも出す。
  - 発動者と参加者の候補。図は候補の代表1体で描くので、ウィッチでも良い・ビショップでも良いはここで分かる。
  - 短い説明文（`skill.<id>.desc`）。マニュアルが載せないカタログ（どのスキルが何を出すか）はここが担う。並べ方には触れない＝形の行と図が担うので、説明文は技そのものだけを書く。
- **未解放の枠**：名前は伏せ、要るユニットの盤の絵を黒塗りにして人数ぶん並べる＝ヒント。見せるのは「誰が要るか」まで、「どう並べるか」（形と位置）は見せない。発見型のスキル（ディバインジャッジメントのように盤を読んで気づくもの・[formations.md](formations.md) 例外：発見型のスキル）やステージで教えないスキル（トリックショット）で隠したいのは形と位置であって顔ぶれではない＝顔ぶれを見せても発見は消えず、逆に顔ぶれが無いと総当たりになる。黒塗りの数はスキルの人数（`count`。「5以上」は最低の5）、候補が複数ある枠は表Aで先頭に書いたスキンで代表する。黒塗りは切り抜き、全員の高さを揃えて枠に収める＝5人並ぶ紙でも重ならないことを優先し、ユニット章の格子のような大小関係は付けない。分類ごとに「埋まった数／全部」を出し、黒塗りの枠が「まだある」の合図＝プレイヤーはここを見て盤の上で探す（配置のレシピが成立すると行動メニューに項目が出る）。
- **見せ方**：ユニット章と同じ羊皮紙のカードを分類ごとに格子に並べる。格子のカードに載るのは、解放済みならカットインの絵とスキル名、未解放なら黒塗りの顔ぶれと「？」で、数値は出さない。押すと拡大したカードが手前に開き、上段にカットインの絵とレシピの図を並べ、上に挙げたものを載せる。未解放のカードは押しても開かない。

## 冒険譚の一覧

冒険譚ごとの章の入口。ユニット章・陣形スキル章と同じ羊皮紙のカードを格子に並べ、1冒険譚＝1枚。カードには冒険譚の絵・名前・サマリーを載せる。

- ステージセレクトのボード（[stage_select.md](stage_select.md) シリーズボード）ごとに束ね、ボード名を見出しにしてその下にカードを並べる。ボードの並びと名前はセレクトと同じ。1段はボードと同じ3枚。

- 絵はステージセレクトの冒険譚カードと同じ（[stage_select.md](stage_select.md) 冒険譚カード）＝`{id}_card.png` があればそれ、無ければ扉絵 `{id}_cover.png`。
- 一度も遊んでいない冒険譚は暗い紙にし、絵を黒塗りにする（背景まで描いた絵なので真っ黒な四角になる）。名前は出し、押せば開く。
- **冒険譚ランク**＝全ステージのベストランク（[rank.md](rank.md) 記録）のうち**最も低いもの**。ステージ内で2軸の低い方を取るのと同じ物差し＝全 S でなければ S にならない。全ステージをクリアするまでは出さない。
- **クリア時間の合計**＝各ステージの所要時間ベスト（[../tech/gamesystem.md](../tech/gamesystem.md) 所要時間）の和。所要時間を持たないステージ（仕組みより前のクリア）が1つでもあれば合計は出さない。遊び直せば埋まる。
- 未クリアの間は「クリア数／ステージ数」を出す。
- 冒険譚を選ぶと4つの節＝**会話／イベント**・**戦果**・**設定集**・**物語**をタブで切り替えて読む。開いたときは先頭の会話／イベント。タブは同じ幅に揃える。タブの左端に矢印だけの丸い木のボタン（←）を置き、冒険譚の一覧へ戻る。
- 物語の節は、冒険譚を全部クリアしてから読める。本のように見開きでページをめくって読む（下記 画面）。冒頭にあらすじを置き、前史・真相・敵の動機・人の変化まで書く（クリア後に読むので、真相を伏せない）。あらすじより後ろの中身は別途決める。
- チュートリアルの3本は、チュートリアルであることを隠さず、その話の人物が書いた作中の文書の形で「何を覚えたか」を綴る。ゴブリンの襲撃＝新兵の日誌（教わる側）、アンデッドの群れ＝調査隊の騎士が都市へ出す報告書（陣形スキルを各機関の手の内として記録する）、竜狩り＝ヴァンガードの手記（育てる側。筋があるのであらすじも兼ねる）。

## 戦果

- ステージごとの行：クリア済みか・ベストランク・所要時間のベスト。いずれも進捗セーブに記録済みで、新しい記録は持たない。
- 未クリアのステージは題名を出さず「？」の行にする（セレクト画面の未解放と同じ扱い）。
- 撃破数・損失数の累計は**載せない**。回ごとの数は中断セーブが持つもので、進捗に残していない。積み上げの数字は「稼ぐ」動機を作り、生存率と逆を向く。

## 会話／イベント（会話の通し読み）

冒険譚の会話を、全ステージぶんつなげて1本のスクロールで読む。会話パネル（`ConversationPanel`）は使わない。

- **段**：1ステージ＝1段。見出しにステージの題名、左に盤の絵、右にそのステージの会話を並べる。段をステージ順に縦に積み、盤も会話と一緒にスクロールする。
- **会話の順**：開幕 → イベント会話 → 決着。イベント会話の順は下記のマニフェストが持つ＝書き手が決める。
- **会話の1行**：顔の小さな絵（会話パネルと同じ顔）・話し手の名前・台詞。行は詰めて並べ、紙に載せず画面の地に置く。
- **盤の絵**：ステージの初期配置の盤を PNG に書き出したもの（`godot/assets/chronicle/<冒険譚 id>/<ステージ id>_map.png`・書き出しは `marketing/shot_stage` を `--size 960x540` で・[../tech/tools.md](../tech/tools.md)）。回ごとの盤の状態は記録していないので、どの回を読んでも同じ絵。地形や配置を直したら書き出し直す。左の列は本文の幅の4割。
- **読める範囲**：経験した会話だけ（[../tech/gamesystem.md](../tech/gamesystem.md) 経験した会話）。未経験のイベントは出さず、存在も匂わせない。記録の無いステージ（仕組みより前のクリア）は見出しと盤だけで会話は無し。
- 未クリアのステージの段で終わる（決着の会話が無い＝物語がそこまで）。
- 盤中の「ストーリーを確認」（[uiux.md](uiux.md) ターン終了・システムメニュー）はそのまま残す。あちらは「いま遊んでいるステージの読み直し」、こちらは「冒険譚を後から通して読む」。

### 分岐の扱い

- **仲間の台詞**（`joined:<actor>`・[../campaign/authoring.md](../campaign/authoring.md) 会話の分岐）：切り替えない。仲間は居る前提で、仲間の行は常に出す。
- **拠点の取得／喪失**（`once` で捨て合う味方版／敵版・[map.md](map.md) イベント）：両方を経験していれば、そのイベントの会話の頭に「取得／喪失」のボタンを置き、押すと会話が入れ替わる。片方しか経験していなければボタンは出さない。
- 最初に出すのは最後に遊んだ回で起きたほう（進捗セーブの記録）。
- 両方を経験したかは、起きたイベントを足していく `user://chronicle.json` で見る（[../tech/gamesystem.md](../tech/gamesystem.md) クロニクル）。進捗セーブ側は最後に遊んだ回だけを上書きで持つ。

## 設定集

会話だけでは分からない背景を読む場所。冒険譚ごとに1本の長い文書。

- **形**：マニュアルの本文ペインと同じ縦スクロールで通して読む。目次は持たず、節見出しだけ入れる。盤は使わない。
- **構成**：前半は型どおりの節（舞台・依頼の経緯・一行の顔ぶれ・相手は何者か）、後半は読み物（物語の背景・前史・会話で語られなかったこと）。いまの冒険譚 doc（`doc/campaign/*.md`）の並びをそのままプレイヤー向けに書き直したもの。固有名は持たせず役職で呼ぶ（[../campaign/worldbuilding.md](../campaign/worldbuilding.md)）。
- **解放は節ごと**に「どのステージをクリアしたら」を宣言する。文書は解放された節まで表示し、末尾に「続きは冒険のあとで」と1行置く＝先が在ることだけ分かる。節の題名は伏せる。会話で明かされる前に設定集で先に知れてしまうのを避けるための仕組みで、開始時から読める節（舞台・依頼の背景）と決着後に読める節（敵の正体・前史の真相）を書き手が分ける。
- **正本**：各冒険譚の構想メモ（`doc/campaign/*.md`）と [../campaign/world.md](../campaign/world.md)。メモに無い裏設定は載せない＝書きたければ先にメモへ足す。

## 画面

- 見せ方はマニュアル・設定画面と同じ様式（[settings.md](settings.md)・[manual.md](manual.md) 画面）。ユニット・陣形スキル・冒険譚の一覧のカードだけは羊皮紙＝依頼ボードの貼り紙と同じ紙（[../art/menu.md](../art/menu.md)）。全画面の暗幕、押せる物は木の板、板の外は無機質なグレー、戻るは画面左下。
- 章の切り替えは左の目次（ユニット／陣形スキル／冒険譚の一覧）。目次は固定で、冒険譚を選んでも入れ替えない。冒険譚を選ぶと本文側がその冒険譚に替わり、4節（会話／イベント／戦果／設定集／物語）はタブで切り替える。段を持つのはここだけ。
- 左下のボタンは常に「← メニュー」＝画面を出る。冒険譚の一覧へ戻るのはタブの左端の「←」。Esc は一段上がる＝冒険譚を開いていれば一覧へ戻り、一覧にいれば画面を出る。
- 本文はスクロールで流し、ページ割りにしない（マニュアルと同じ理由＝言語で行数が変わる）。物語の節だけは例外で、本のように見開き2ページで開き、ページをめくって読む。ページの区切りは書き手が決める（下記 本文の持ち方）。
- カードの格子は紙を先に並べて画面を出し、絵は読み込めた順にあとから載せる（絵の読み込みで画面を止めない）。読み込み中の紙は明るいまま空＝暗い紙（未解放）とは混ざらない。2回目からは開いた瞬間に絵が並ぶ。

## 本文の持ち方

クロニクル専用の構造（どの節をどの順で出すか）は `godot/data/chronicle/` に集める。ゲーム進行（`campaign.json`）には載せない。本文そのものは他と同じく翻訳CSV（`godot/data/i18n/`）に置く。

- 冒険譚ごとのマニフェストは `godot/data/chronicle/<冒険譚 id>.json`。設定集（`lore`）と会話／イベント（`story`）の並びと解放条件を持つ。読むのは `ChronicleLoader` で、ファイル名が冒険譚 id。
- 設定集の本文は翻訳CSV `godot/data/i18n/chronicle.csv`。キーは `lore.<冒険譚>.<節>.<段落>`。1行1キーで段落ごとに振る。
- ユニットの説明文（`unit.<skin_id>.desc`）も `chronicle.csv`。ゲーム中は読まず、クロニクル画面だけが読むため。
- スキルの説明文（`skill.<id>.desc`）は `skills.csv` に置く。情報パネルがゲーム中に読む（[../tech/i18n.md](../tech/i18n.md)）。

```json
"lore": [
  { "id": "stage",  "unlock": [] },
  { "id": "party",  "unlock": [] },
  { "id": "enemy",  "unlock": [ { "type": "cleared", "stage": "goblin-raid-st4" } ] },
  { "id": "origin", "unlock": [ { "type": "cleared", "stage": "goblin-raid-st7" } ] }
]
```

- 会話／イベント（`story`）はステージの並びと、そのステージで出すイベント会話の並び（`events`）を持つ。**出す順はここが正本**＝遊んだ回の記録は「経験したか」だけを見る。並びが記録と食い違えば（ステージのイベントを足して `events` に書き忘れた等）テストで落ちる。
- 節の `id` が翻訳キーの `<節>`。段落は `lore.tutorial1-goblin-raid.origin.1` から連番で、CSV に在るぶんだけ順に出す（段落数を JSON に書かない）。
- 物語の本文も `chronicle.csv`。キーは `book.<冒険譚>.<ページ>` で、1キー＝1ページ。ページは `book.<冒険譚>.1` から連番で、CSV に在るぶんだけ順に出す（奇数が左・偶数が右の見開き）。区切りは書き手が決めるので、訳文がページに収まらないとあふれる＝全言語で1ページに収まっているかをテストで見る。
- 構造（マニフェストの節）と `chronicle.csv` のキーの突き合わせはテストで見る（[../tech/testing.md](../tech/testing.md)）。マニュアルの `manual.csv` と同じ。
- 画面の文言は `chronicle.csv` の `ui.chronicle.*`。

## 記録の持ち方

出会ったユニットと見た陣形スキルは、進捗セーブとは**別のファイル** `user://chronicle.json` に持つ（[../tech/gamesystem.md](../tech/gamesystem.md) クロニクル）。

- 性格が違う：進捗は「どこまで進んだか」（冒険譚・ステージ単位・クリア時に書く）。クロニクルは「何に出会ったか」（冒険譚をまたいで溜まる・盤を離れるときに書く）。
- 版が独立する：ユニットやスキルの追加でクロニクルの形が変わっても、進捗の版を動かさずに済む。
- 失っても進行は壊れない：ファイルが読めなくても、遊び直せば埋まるだけ。
- 持つのは `skin_id` の集合と、スキル id の集合。加えて経験した会話の累積＝冒険譚→ステージごとに、遊んだ回の在籍 actor（開始時・クリア後）と起きたイベント。
- **書くのは盤を離れるとき**（決着・中断・タイトルへ戻る）にまとめて。クリアを待たない＝負けた回に見た敵も残り、再挑戦の前に相手を確かめられる。中断セーブから再開した回も、盤に出た時点でまた記録するので取りこぼさない。
- 戦果・設定集の解放は進捗セーブの既存の記録（クリア・ランク・所要時間）から導く。クロニクルのファイルに重ねて持たない。経験した会話の累積だけは進捗から導けない（進捗は最後に遊んだ回で上書きする）ので、ここで持つ。

## サイトとの関係

公式サイトの「仕様リファレンス」（[../sales/site.md](../sales/site.md)）は、この画面をもとにデータから生成する別ページ。指すのは**ユニットと陣形スキルの章だけ**。会話／イベント・物語・設定集は経験に紐づく読み物なので出さない。陣形スキルの章はサイトでは**レシピを伏せる**（名前・絵・効果・総数まで。要るユニット・形・説明文は出さない）＝クロニクルは解放した人にレシピを見せるが、サイトは誰にでも見えるので答えを置かない。
