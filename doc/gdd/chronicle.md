# クロニクル

タイトルの「クロニクル」から開く、冒険の記録を読む画面。出会った駒と見た陣形スキルが溜まり、冒険譚ごとに戦果・物語（会話の通し読み）・設定集が読める。集めるもの（図鑑）ではなく**冒険の記録**として扱う＝名前は日本語でも「クロニクル」（英語 Chronicle）。

マニュアル（[manual.md](manual.md)）が仕組みと用語の説明に徹し、個々のユニット・スキル・物語を持たないのに対し、クロニクルは**プレイヤーが経験した個別のもの**を置く場所。両者の線引きは「仕組み→マニュアル／個別→クロニクル」。

---

## 骨組み

開き口はタイトルのメニューのみ（[title.md](title.md)）。盤の中からは開かない。

中は2つの軸に分かれる。

| 軸 | 章 | 何が溜まるか |
|---|---|---|
| 全体で溜まるもの | ユニット／陣形スキル | 冒険譚をまたいで累積する。どの冒険譚で出会っても同じ枠が埋まる |
| 冒険譚ごとのもの | 戦果／物語／設定集 | 冒険譚を1つ選んでから読む。冒険譚の一覧が入口 |

- 全体の章は「まだ埋まっていない枠がある」をプレイヤーに見せる。冒険譚の章は「遊んだ冒険を読み返す」。
- 未クリア・未経験のものを匂わせる度合いは章ごとに決める（下記）。ユニット・スキル・設定集は**数だけ**見せ、物語は**見ていない出来事の存在を出さない**（盤中の「ストーリーを確認」と同じ）。
- デバッグ冒険譚（[stage_select.md](stage_select.md)）で見たもの・遊んだものは、どの章にも記録しない。クリア記録・ランクと同じ扱い。

## ユニット

- **単位はスキン**（`skin_id`・[units.md](units.md)）。性能（type）は複数スキンで共有されるので、プレイヤーが覚える見た目で1枠。同じ性能の別スキン（プリーストとスケルトン）は別枠。
- **並びと束ね**は `unit_skin.csv` の分類（`category`）と行順をそのまま使う（[../art/units.md](../art/units.md) §2）。クロニクル専用の順序は持たない。味方の章は兵種で並び（歩兵・占領兵…）、敵の章は素性で並ぶ（ゴブリン・アンデッド…）。見出しは `unit_group.<id>.name` で引く。
- **埋まる条件は「盤に現れた」**。味方は出撃した時点、敵は盤上に出た時点（増援・拠点からの出撃・敵が解放した中立を含む）。戦った／倒したまでは求めない＝逃げ切る遊びや間接攻撃だけの回で埋まらず、盤の判断と記録が逆を向くのを避ける。プレイヤーが見る前に退いた駒は無い（敵ターンに出た駒は自ターンに盤にいる）ので、これで足りる。
- **載せるもの**
  - 絵：盤の絵（`map`）と戦闘演出の絵（`combat`・[../art/overview.md](../art/overview.md)）。
  - 名前（`unit.<skin_id>.name`）と分類。
  - 性能の数値：対地攻撃・対空攻撃・貫通率・防御・移動（タイプ）・射程・攻撃後移動・兵数・搭乗・占領。**数値の一覧はここが担う**（マニュアルは数値を載せない方針）。
  - ユニットスキル（[skills.md](skills.md)）：その駒が撃てるものを性能の一部として載せる。発動者が1体なので駒の枠に属し、駒が埋まれば読める＝別枠にしない。
  - 短い説明文（`unit.<skin_id>.desc`・`chronicle.csv`）。
- **未解放の枠**：黒いシルエットのカードで置き、押しても開かない。分類ごとに「埋まった数／全部」を出す。総数を見せるのが「まだある」の合図。
- **見せ方**：分類ごとに束ねた羊皮紙のカードを格子に並べる。格子のカードに載るのは盤の絵だけで、名前も数値も出さない。カードを押すと拡大したカードが手前に開き、盤の絵と戦闘演出の絵を並べて、上に挙げたものを載せる。閉じると格子へ戻る。

## 陣形スキル

- 単位はスキル（[formations.md](formations.md) スキル一覧）。ユニットスキルはここに置かない（上記）。
- **埋まる条件は「盤で発動された」**。自分が撃っても、敵に撃たれても解放。冒険譚2で①②③を教わる順（st3／st5／st7）と自然に一致する。
- **並びと束ね**は [formations.md](formations.md) 表A の「分類」列と行順をそのまま使う（ユニット章が `unit_skin.csv` に従うのと同じ）。クロニクル専用の順序は持たない。分類は 弓攻撃・魔法攻撃・特殊攻撃・強化・弱体化・その他 と、敵のスキルをまとめた「敵」。敵のスキルは効果で分けない＝プレイヤーが探して使うものではないので、味方の束に混ぜて組めないスキルを探させない。見出しは `skill_group.<id>.name` で引く。
- **載せるもの**
  - 絵：カットインの絵（`assets/formations/<id>.png`・[../art/keyvisual.md](../art/keyvisual.md) 陣形スキルの絵）と、レシピの図。図は形どおりのヘックス配置に要るスキンの盤の絵を置いたもので、形ごとに配置を1つ決める。斥候型・背後型は対象の敵ヘクスも描かないと形が伝わらないので、その形を実装するときに図も足す。
  - 名前（`skill.<id>.name`）と分類。
  - 効果・射程・持続・人数・発動できる駒。
  - 発動者と参加者の候補。図は候補の代表1体で描くので、ウィッチでも良い・ビショップでも良いはここで分かる。
  - 初出の冒険譚。
  - 短い説明文（`skill.<id>.desc`）。マニュアルが載せないカタログ（どのスキルが何を出すか）はここが担う。
- **未解放の枠**：名前は伏せ、要るユニットの盤の絵を黒塗りにして人数ぶん並べる＝ヒント。見せるのは「誰が要るか」まで、「どう並べるか」（形と位置）は見せない。発見型のスキル（③のように盤を読んで気づくもの・[formations.md](formations.md) 例外：発見型のスキル）やステージで教えないスキル（④トリックショット）で隠したいのは形と位置であって顔ぶれではない＝顔ぶれを見せても発見は消えず、逆に顔ぶれが無いと総当たりになる。黒塗りの数はスキルの人数（`count`。「5以上」は最低の5）、候補が複数ある枠は表Aで先頭に書いたスキンで代表する。分類ごとに「埋まった数／全部」を出し、黒塗りの枠が「まだある」の合図＝プレイヤーはここを見て盤の上で探す（配置のレシピが成立すると行動メニューに項目が出る）。
- **見せ方**：ユニット章と同じ羊皮紙のカードを分類ごとに格子に並べる。格子のカードに載るのは、解放済みならカットインの絵、未解放なら黒塗りの顔ぶれだけで、名前も数値も出さない。押すと拡大したカードが手前に開き、上段にカットインの絵とレシピの図を並べ、上に挙げたものを載せる。未解放のカードは押しても開かない。

## 冒険譚の一覧

冒険譚ごとの章の入口。1冒険譚＝1行で、サマリーを出す。

- **冒険譚ランク**＝全ステージのベストランク（[rank.md](rank.md) 記録）のうち**最も低いもの**。ステージ内で2軸の低い方を取るのと同じ物差し＝全 S でなければ S にならない。全ステージをクリアするまでは出さない。
- **クリア時間の合計**＝各ステージの所要時間ベスト（[../tech/gamesystem.md](../tech/gamesystem.md) 所要時間）の和。所要時間を持たないステージ（仕組みより前のクリア）が1つでもあれば合計は出さない。遊び直せば埋まる。
- 未クリアの間は「クリア数／ステージ数」を出す。
- 一度も遊んでいない冒険譚も行は出す（セレクトで見えているものは並びを揃える）。中身は空。
- 冒険譚を選ぶと3つの節＝**戦果**・**物語**・**設定集**。

## 戦果

- ステージごとの行：クリア済みか・ベストランク・所要時間のベスト。いずれも進捗セーブに記録済みで、新しい記録は持たない。
- 未クリアのステージは題名を出さず「？」の行にする（セレクト画面の未解放と同じ扱い）。
- 撃破数・損失数の累計は**載せない**。回ごとの数は中断セーブが持つもので、進捗に残していない。積み上げの数字は「稼ぐ」動機を作り、生存率と逆を向く。

## 物語（会話の通し読み）

冒険譚を1本の物語として通しで見せる。読むための目次ではなく、**盤を挿絵にした流れ**。

- **流れ**：ステージ順に 開幕 → イベント会話 → 決着 を連ね、ステージの切り替わりで題名を章題として出す。ステージ境で止めずに次へ続く。イベント会話の順は下記のマニフェストが持つ＝書き手が決める。
- **挿絵＝ステージごとの1枚絵**。`godot/assets/chronicle/<冒険譚 id>/<ステージ id>.png` を背景に敷き、その上に会話パネル（`ConversationPanel`）をいつもどおり出す＝ゲーム中の開幕会話と同じ画。盤は組まない＝回ごとの盤の状態は記録しておらず、初期配置の盤を組み直しても読んでいる場面とは合わない。絵は置かれたものだけを拾う（無い章は暗幕だけ）。素材は `godot/assets/chronicle-src/`。
- **読める範囲**：経験した会話だけ（[../tech/gamesystem.md](../tech/gamesystem.md) 経験した会話）。未経験のイベントは流れに出さず、存在も匂わせない。記録の無いステージ（仕組みより前のクリア）は章題だけ出して本文は無し。
- 始める場所はステージから選べる。読んでいる間の操作は3つ＝**次へ**（1行ずつ）・**次の章へ**（次のステージの開幕へ飛ぶ）・**やめる**（章の一覧へ戻る）。
- 未クリアのステージに差しかかったらそこで終わる（決着の会話が無い＝物語がそこまで）。
- 盤中の「ストーリーを確認」（[uiux.md](uiux.md) ターン終了・システムメニュー）はそのまま残す。あちらは「いま遊んでいるステージの読み直し」、こちらは「冒険譚を後から通して読む」。

### 分岐の切り替え

台本の分岐（[../campaign/authoring.md](../campaign/authoring.md) 会話の分岐）は、両方を経験していれば読みながら切り替えられる。

- **在籍による行の出し入れ**（`joined:<actor>`）：仲間 X が「居た回」と「居なかった回」の両方を経験していれば、X の加入／未加入を切り替えられる。片方しか経験していなければ固定。切り替えは仲間ごとに独立＝加入キャラの台詞は色付けに限る取り決めなので、組み合わせを作っても筋は通る。
- **どちらか一方しか起きないイベント**（`once` で捨て合う味方版／敵版・[map.md](map.md) イベント）：両方を経験していれば、どちらが起きたかを切り替えられる。
- 切り替えは読んでいる途中で分岐に差しかかったとき、パネル脇に出す（両方を経験している箇所だけ）。開始前に顔ぶれを選ばせない。
- 既定は最後に遊んだ回。盤中の「ストーリーを確認」も同じ既定で動くので変わらない。
- このために、遊んだ回の顔ぶれと起きたイベントを `user://chronicle.json` に**足していく**（[../tech/gamesystem.md](../tech/gamesystem.md) クロニクル）。進捗セーブ側は最後に遊んだ回だけを上書きで持つ。

## 設定集

会話だけでは分からない背景を読む場所。冒険譚ごとに1本の長い文書。

- **形**：マニュアルの本文ペインと同じ縦スクロールで通して読む。目次は持たず、節見出しだけ入れる。盤は使わない。
- **構成**：前半は型どおりの節（舞台・依頼の経緯・一行の顔ぶれ・相手は何者か）、後半は読み物（物語の背景・前史・会話で語られなかったこと）。いまの冒険譚 doc（`doc/campaign/*.md`）の並びをそのままプレイヤー向けに書き直したもの。固有名は持たせず役職で呼ぶ（[worldbuilding.md](worldbuilding.md)）。
- **解放は節ごと**に「どのステージをクリアしたら」を宣言する。文書は解放された節まで表示し、末尾に「続きは冒険のあとで」と1行置く＝先が在ることだけ分かる。節の題名は伏せる。会話で明かされる前に設定集で先に知れてしまうのを避けるための仕組みで、開始時から読める節（舞台・依頼の背景）と決着後に読める節（敵の正体・前史の真相）を書き手が分ける。
- **正本**：各冒険譚の構想メモ（`doc/campaign/*.md`）と [world.md](world.md)。メモに無い裏設定は載せない＝書きたければ先にメモへ足す。

## 画面

- 見せ方はマニュアル・設定画面と同じ様式（[settings.md](settings.md)・[manual.md](manual.md) 画面）。ユニットと陣形スキルのカードだけは羊皮紙＝依頼ボードの貼り紙と同じ紙（[../art/menu.md](../art/menu.md)）。全画面の暗幕、押せる物は木の板、板の外は無機質なグレー、戻るは画面左下。物語の通し読みだけはステージの挿絵を敷くので、絵の上に会話パネルと暗幕（ゲーム中の会話と同じ濃さ）。
- 章の切り替えは左の目次（ユニット／陣形スキル／冒険譚の一覧）。冒険譚を選ぶと目次がその冒険譚の3節（戦果／物語／設定集）に入れ替わり、戻るで一覧へ上がる。段を持つのはここだけ＝左下のボタンは常に「一段上がる／画面を出る」で、目次の段が1つなら画面を出る。
- 本文はスクロールで流し、ページ割りにしない（マニュアルと同じ理由＝言語で行数が変わる）。

## 本文の持ち方

クロニクル専用の構造（どの節をどの順で出すか）は `godot/data/chronicle/` に集める。ゲーム進行（`campaign.json`）には載せない。本文そのものは他と同じく翻訳CSV（`godot/data/i18n/`）に置く。

- 冒険譚ごとのマニフェストは `godot/data/chronicle/<冒険譚 id>.json`。設定集（`lore`）と物語（`story`）の並びと解放条件を持つ。読むのは `ChronicleLoader` で、ファイル名が冒険譚 id。
- 設定集の本文は翻訳CSV `godot/data/i18n/chronicle.csv`。キーは `lore.<冒険譚>.<節>.<段落>`。1行1キーで段落ごとに振る。
- ユニットの説明文（`unit.<skin_id>.desc`）も `chronicle.csv`。ゲーム中は読まず、クロニクル画面だけが読むため。
- スキルの説明文（`skill.<id>.desc`）は `skills.csv` に置く。情報パネルがゲーム中に読む（[../tech/i18n.md](../tech/i18n.md)）。

```json
"lore": [
  { "id": "stage",  "unlock": [] },
  { "id": "party",  "unlock": [] },
  { "id": "enemy",  "unlock": [ { "type": "cleared", "stage": "goblin-raid-st4" } ] },
  { "id": "origin", "unlock": [ { "type": "cleared", "stage": "goblin-raid-st7" } ] }
]
```

- 物語（`story`）はステージの並びと、そのステージで出すイベント会話の並び（`events`）を持つ。**出す順はここが正本**＝遊んだ回の記録は「経験したか」だけを見る。並びが記録と食い違えば（ステージのイベントを足して `events` に書き忘れた等）テストで落ちる。
- 節の `id` が翻訳キーの `<節>`。段落は `lore.tutorial1-goblin-raid.origin.1` から連番で、CSV に在るぶんだけ順に出す（段落数を JSON に書かない）。
- 構造（マニフェストの節）と `chronicle.csv` のキーの突き合わせはテストで見る（[../tech/testing.md](../tech/testing.md)）。マニュアルの `manual.csv` と同じ。
- 画面の文言は `chronicle.csv` の `ui.chronicle.*`。

## 記録の持ち方

出会ったユニットと見た陣形スキルは、進捗セーブとは**別のファイル** `user://chronicle.json` に持つ（[../tech/gamesystem.md](../tech/gamesystem.md) クロニクル）。

- 性格が違う：進捗は「どこまで進んだか」（冒険譚・ステージ単位・クリア時に書く）。クロニクルは「何に出会ったか」（冒険譚をまたいで溜まる・盤を離れるときに書く）。
- 版が独立する：ユニットやスキルの追加でクロニクルの形が変わっても、進捗の版を動かさずに済む。
- 失っても進行は壊れない：ファイルが読めなくても、遊び直せば埋まるだけ。
- 持つのは `skin_id` の集合と、スキル id の集合（スキルには初めて出会った冒険譚 id を添える）。加えて経験した会話の累積＝冒険譚→ステージごとに、遊んだ回の在籍 actor（開始時・クリア後）と起きたイベント。
- **書くのは盤を離れるとき**（決着・中断・タイトルへ戻る）にまとめて。クリアを待たない＝負けた回に見た敵も残り、再挑戦の前に相手を確かめられる。中断セーブから再開した回も、盤に出た時点でまた記録するので取りこぼさない。
- 戦果・設定集の解放は進捗セーブの既存の記録（クリア・ランク・所要時間）から導く。クロニクルのファイルに重ねて持たない。経験した会話の累積だけは進捗から導けない（進捗は最後に遊んだ回で上書きする）ので、ここで持つ。

## サイトとの関係

公式サイトの「仕様リファレンス」（[../sales/site.md](../sales/site.md)）は、この画面をもとにデータから生成する別ページ。指すのは**ユニットと陣形スキルの章だけ**。物語と設定集は経験に紐づく読み物なので出さない。陣形スキルの章はサイトでは**レシピを伏せる**（名前・絵・効果・総数まで。要るユニット・形・説明文は出さない）＝クロニクルは解放した人にレシピを見せるが、サイトは誰にでも見えるので答えを置かない。
