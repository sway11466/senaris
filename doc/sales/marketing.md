# マーケティング

対象：外に出す素材の方針と置き場、チャネルごとの方針。各チャネルで実際に何を入力するかは、チャネル単位のファイルに置く。

価格・配布バリエーション・チャネルの選定は [monetization.md](monetization.md)、タイトル名と副題の実体は [naming_decision_senaris.md](naming_decision_senaris.md)、ロゴは [../art/logo.md](../art/logo.md)。

---

## 届ける相手

英語圏に振る。ヘックス制ターン戦術の潜在層は英語圏のほうが厚く、Steam の集客もこの層で回る。同人系直販のうち itch のユーザーベースが英語圏中心なのも同じ方向を向く（[monetization.md](monetization.md) の販売チャネル）。

英語テキストの質が効く。盤面のゲーム性で買う客層のため、絵よりも文が読まれる。優先度が高いのはストアページの一行目とチュートリアルの会話パートで、ステージ内の UI ラベルは短く誤解の余地が少ないぶん後回しでよい（[i18n.md](../tech/i18n.md)）。

## 素材の方針

素材は次の要素でできている。それぞれ別の仕事をし、同じことを重ねて言わない。

| 要素 | 何を伝えるか |
| --- | --- |
| ロゴ | 作品名と、盤上の戦いであること（ヘックスに剣） |
| 副題 | 名前しか見えないときのジャンル保険 |
| キービジュアル | 棚で目を留めさせる引き |
| 紹介画像 | 実際の画面。遊んでいるあいだ何を見ているのか |
| ティザー | 世界観と雰囲気 |
| トレーラー | 遊びの流れ |
| タグ | どの棚に並ぶか＝誰に見つかるか |
| 説明文 | なぜ買うか（乱数なし・生産なし） |
| 特徴リスト | 何ではないか＝期待値の設定 |

### ロゴ

ヘックスに剣が刺さった紋章で、名前と同時にジャンルを出す。文字だけでは伝わらないヘックス盤の側を、絵の側が一目で伝える。作りとバリエーションは [../art/logo.md](../art/logo.md)。

単独で置くだけでなく、他の要素の中にも入る。キービジュアルに載せるのは Steam の要件、ほかに動画の末尾とサイトのヘッダ。

### 副題

タイトル名そのものは語義を伝えない。`Senaris` は造語で、英語話者が拾えるのは `-is` 終わりのラテン語風の響き（Solaris / Polaris の系列）＝SF かファンタジーの固有名、という程度。名前の仕事は覚えられることと検索で辿り着けることに限り、意味の伝達は残りの要素に割り振る。

### キービジュアル

仕事は引き。棚に並んだ中で目を留めさせるところまでを持ち、ジャンルの識別はロゴが担当する。

出す面の大きさに小・中・大の3段あり、段ごとに別の絵を用意する。1枚を全段で使い回さない。面が変われば読めるものが変わり、絵とロゴのどちらが前に出るかも変わる。

| 段 | 面 | 絵とロゴの比重 |
| --- | --- | --- |
| 小 | いちばん小さい面 | 絵よりロゴが目立つ |
| 中 | 中くらいの面 | 絵とロゴが同じくらい主張する |
| 大 | 大きな面 | 絵が中心で、上に載るものを邪魔しない |

小さい段は横 200px 程度まで縮む。この寸法では網目は模様として残るが盤上の駒は識別できないため、盤面の縮図ではなくモチーフを大きく置く構図にする。スクリーンショット的な密度にすると縮小時にただの灰色の面になる。

小は、ロゴと赤竜のユニット立ち絵を組んで作る。竜は生成し直さず盤で使っている絵をそのまま置く。組み立ては [build_keyvisual.py](../../godot/tools/keyvisual/build_keyvisual.py)、出力は `godot/assets/promo-src/keyvisual/`。ロゴと竜が横幅を半分ずつ使い、中央で少し重なる。

中と大は画題が決まっていない。小が本編の赤竜をそのまま置いた絵なので、中・大で別の竜が出ると段どうしが揃わない。ここは絵柄の一致を先に決める。実作業の追跡は backlog。

ヘックス盤は英語圏では第一にウォーゲームの記号で、硬派層に効く一方、軽快な戦術ゲームを探す層には重く見える方向にも振れる。どちらに転ぶかは線の太さ・彩度・キャラの造形が決めるため、絵柄の方針（[../art/direction.md](../art/direction.md)）とタグの配分は同じ判断になる。

### 紹介画像

仕事は中身の目録。棚で見つけさせて開かせるまでがロゴ・キービジュアル・タグの担当で、こちらは開いた人に、遊んでいるあいだ何を見ることになるのかを正確に渡す。このジャンルに興味のある人しか読まない前提で、正確さを優先する。

先頭の1〜2枚しか見られないことが多いので、盤が写るものを前に置く。カットインと会話は盤が写らないが、見せ場と物語は買う理由になるので落とさず後ろに置く。

| 順 | 絵 | その絵を出す狙い |
| --- | --- | --- |
| 1 | 盤の全景。駒を選んで移動範囲が出ていて、敵を囲みかけた形が見えている | 遊びが位置取りであること。包囲が核であること |
| 2 | 戦闘の演出。左右に隊列が並び、攻撃が入る瞬間 | 駒をぶつけた結果の見え方。兵数が減る＝損耗が残ること |
| 3 | 陣形スキルのカットイン | 決め技があること。1枚絵としての見せ場 |
| 4 | 会話パート | 一話ずつの冒険譚があること。世界観 |

足りないと感じたら足す。

### ティザー・トレーラー

ティザーは世界観、トレーラーは遊びの流れ。狙いが違うので1本に混ぜない。

自前でホストせず Steam か YouTube に載せる。変換・再生互換・転送量を持たなくて済む。

### タグ

タグを選ぶ行為は語を選ぶことではなく、誰の隣に並ぶかを選ぶこと。

英語圏のヘックス戦術棚は客層が三つに割れている。

- Advance Wars 系 … 軽快・キャラ立ち・カジュアル寄り。母数が最も大きい。
- ヘックスウォーゲーム系 … 硬派・歴史もの・数値志向。濃いがファンタジーとは遠い。
- 戦術パズル系 … 与えられた戦力を噛み合わせて解く手触り。コンセプト（[../concepts.md](../concepts.md)）に最も近い。

このうち戦術パズル系は語では取りに行けない。あの手触りに対応するタグが用意されておらず、`Puzzle` を使うと「解が一つある問題」を期待した層が来て外れる。パズル性は説明文の deterministic が担当し、タグでは歯ごたえの側だけを拾う。

したがって選ぶのは Advance Wars 系とヘックスウォーゲーム系の配分になる。大きいタグが露出の母数を、小さいタグが能動的に追う層への到達を担当するので、両方を混ぜたうえで並び順で配分する。硬派側のタグを上位に置かない＝この層は歴史ものとシミュレーション的な深さを期待しているため、上位に来ると期待値が外れる。低位ならヘックス好きだけを拾える。

絵柄を名乗るタグ（`Hand-drawn` ほか）は使わない。本作はアートに AI 生成を含み、Steam ではそれがストアページに開示表示される（[monetization.md](monetization.md) の AI 生成コンテンツ）。手描きを名乗るタグと開示が同じページに並ぶと矛盾として突かれる。特徴リストでいう手作りのマップはレベルデザインの話で、こちらは抵触しない。

Steam に設定する語（20枠に対して12。埋めきらない＝迷う語を足すと並び順が濁る）。

| 順 | タグ | 役割 |
| --- | --- | --- |
| 1 | Turn-Based Tactics | 棚の中心 |
| 2 | Strategy | 母数の最大化 |
| 3 | Turn-Based Strategy | 同上。Advance Wars 系の主戦場 |
| 4 | Hex Grid | ニッチだが能動的に追う層へ確実に届く。本作の看板 |
| 5 | Fantasy | ヘックス棚では珍しく、差別化がタグ側でも効く |
| 6 | Turn-Based Combat | 取りこぼし回収 |
| 7 | Tactical | 同上 |
| 8 | Singleplayer | 期待値の設定（マルチを期待させない） |
| 9 | Difficult | 歯ごたえを探す層。パズル側の濃度をここで代替する |
| 10 | Medieval | 世界観 |
| 11 | Indie | 規模の期待値 |
| 12 | Wargame | 硬派側。低位に置いて弱く効かせる |

- タグ名は Valve の固定リストに合わせる必要があるため、綴りは登録時に実在を確認する。
- 開発者が設定できるのは初期値と初期の並びまで。最終的にユーザー投票で動く。
- 日本語表示のタグは英語タグと同義ではなく、対応が一対一でない語がある。日本語圏へ出すときは別に決める。
- itch のタグは上限10で、9語で止める（[itch_page.md](itch_page.md)）。推薦にもブラウズ導線にも効かないため、Steam ほど配分を作り込まない。

### 説明文

乱数なしと生産なしを一行目で言い切る。どちらも画面では伝わらず、タグにも定着した受け皿がない。運で負けないことは戦術ゲーム好きが能動的に探している価値のため、言葉で言い切る価値がある。

英語で通る語彙は perfect information / deterministic / no RNG / no dice。副題が `Deterministic` を使うので、説明文は別の語で言い換えて重複を避ける。

先行作の固有名詞は宣伝文に出さない（[monetization.md](monetization.md) の IP・権利）。ジャンルは自前の語で説明する。

### 特徴リスト

差別化（なぜ買うか）と期待値の設定（何ではないか）は別の仕事。前者は説明文の一行目に使い切り、後者は特徴リストに置く。混ぜると焦点がぼける。

ステージ制は後者にあたる。英語圏のこのジャンルではステージ制がデフォルト（Advance Wars 系も戦術パズル系も区切られたミッションを順に解く形）のため、mission-based と書いても情報量がない。書く価値があるのは、そこから派生する二つ。

- 手作りのマップであること。近年は hand-crafted が品質のシグナルとして働き、手続き生成への疲れの受け皿になる。
- 1ステージが短く、区切って遊べること。所要時間を添える。

ただし冒険譚の中では戦力が引き継がれる（[map.md](../gdd/map.md) の carryover）。「1ステージ完結」と言い切ると逆方向の誤解が出るため、ステージは短く区切られるが冒険譚を通して戦力が繋がる、というところまで含める。

期待値を外すと返金とレビューに出る。恒久的な部隊育成や戦略マップを期待して買った人が外れる形が典型。一行目で押さず、特徴リストで確実に伝える。

## 本文

外に出す英語の実文の正本。形式は Markdown で持ち、チャネルごとの形式へ写す（itch は HTML＝[itch_page.md](itch_page.md)）。二重管理になるので、直すときは正本を先に直す。

短い説明文。

```
Hex-grid fantasy tactics with no RNG and no unit production: you win with the squad you are handed.
```

ページ本文。

````markdown
Senaris is a turn-based tactics game on a hex grid. There are no random rolls and no unit production. Both sides start with a fixed force, and the whole game is how you interlock the units you already have. The same attack resolves the same way every time — when you lose a unit, the board can tell you why.

## What to expect

- Hand-crafted maps. Every stage is placed by hand, not generated.
- Short stages, from about 10 minutes each, so you can stop at a clean break.
- Single-player only.
- No base building, no persistent army management, no strategic overworld.

More about the game: [senaris.in](https://senaris.in)
````

一行目で差別化（乱数なし・生産なし）、`What to expect` で期待値の設定という分担にする。carryover はチュートリアル1が各話独立のため初回では書かない。継承の入るチュートリアル3を収録する回で足す。チャネル専用の段落（itch の `About this demo` など）は正本に置かず、チャネル側のファイルに持つ。

## 素材の置き場

3面（Steam・itch・公式サイト）へ出すものは `channels/` に置く。Godot に読ませないため `.gdignore` を添える。

```
channels/
  screenshots/   3面で同じものを使う。高解像度・無加工
  steam/         枠ごとの書き出し
  itch/          cover 画像
  web/           公式サイト一式（[site.md](site.md)）
```

絵の正本は `godot/assets/promo-src/`（ロゴは [../art/logo.md](../art/logo.md)）。`channels/` に入るのは、そこから面ごとの枠に切り出したもの。枠の比率が面ごとに違うため、共有できるのは切る前の master までで、切り出しは面ごとに持つ。切らずに同じものを回すのはスクリーンショットだけ。

文はここに置かない。素材の方針は本書、チャネルごとの入力は各チャネルのファイル、サイトの文言は [site.md](site.md)、devlog の原稿は `doc/devlog/`。会話本文を `doc/campaign/` に置くのと同じ扱いで、読んで判断するものは doc に集める。
