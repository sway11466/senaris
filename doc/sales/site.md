# 公式サイト（senaris.in）

対象：senaris.in に置くページの内容・言語・素材・配信構成・ドメイン運用。ゲーム内の画面は対象外。

配信先の選定経緯は [ADR-0005](../adr/ADR-0005-site-hosting-cloudflare-workers.md)。
見せ方（届ける相手・伝える語彙・期待値の設定）は [marketing.md](marketing.md) が正本で、ここはそれを web という面に落とす側を扱う。

---

## 役割

サイトの仕事は2つに絞る。Steam のストアページへ送ることと、名前で検索した人が公式の在り処を確かめられること。

ニュース欄やブログは作らない。更新義務だけが残り、放置されたサイトは無いより悪い。例外は仕様リファレンス（ゲーム内の図鑑と同じ内容を出す別ページ）で、更新頻度が低くデータから生成できる。

先行作の固有名詞は宣伝文にも出さない。デッドコピーに見えない作りを徹底する方針（[monetization.md](monetization.md)）はサイトにも及ぶ。ジャンルは自前の語で説明する。

## ページ

### 表札

ストアページができるまでの姿。ロゴと、何のゲームかを言う一行と、開発中であることだけを置く。一行に使う語は [marketing.md](marketing.md) の短い説明文に従う＝副題（`Senaris: Deterministic Fantasy Tactics`）が `Deterministic` を使うので、ここは別の語で言い換える。

背景に絵を1枚敷き、その上にロゴと文を重ねる。文を載せる帯は、絵の中で暗く細部の少ない領域を測って選ぶ（[../art/promo.md](../art/promo.md) のキービジュアルは上段が該当する）。

Steam へのリンクはストアページができるまで置かない。行き先の無い「準備中」の文字が画面の主役になる。

### ランディングページ

ストアページができてから表札と差し替える。載せる文と絵はストアページのものを流用する＝サイトのために書き起こさない。

構成は上から、閉じた扉の1枚絵（`assets/menu/door.png` を周囲ぼかしで黒背景へ溶かす。スクリーンショットの縮小画像が扉へ吸い込まれる）→ 酒場の中（一行の説明と紹介動画）→ 特徴とスクリーンショット → Steam へ・併売先（BOOTH／itch）→ フッター（連絡先・プレスキット・権利表記）。Steam ボタンは右上に固定する。仕様リファレンスへのリンクを持つ。

動画は自前でホストせず、Steam のウィジェット埋め込みか YouTube に載せる。変換・互換・転送量を持たずに済む。

## 言語

英語を正、日本語を従とする。ルート（`senaris.in`）が英語、`senaris.in/ja/` が日本語。

英語圏に振る判断そのものは [marketing.md](marketing.md)。サイト側の理由は2つ足す。

- 入口が非対称。英語話者が日本語のページに着けば離脱するが、日本語話者が英語のページに着いても切り替えリンクを押せる
- ゲーム本体が ja と en の2言語（[../tech/i18n.md](../tech/i18n.md)）なので、サイトだけ片方にするとスクリーンショットの言語と食い違う

ブラウザの言語による自動リダイレクトはしない。共有された URL が人によって別の画面を出すと、SNS で「このページ」と指した先がずれる。切り替えはヘッダのリンクだけ。

機械翻訳で片方を作らない。2枚とも独立した原稿として書き起こす。サイトのコピーは訳すと死ぬ種類の文章で、ゲーム内テキストの翻訳（正本は日本語）とは向きが逆になる。

## 素材

絵とロゴの正本は `assets/promo-src/`（[../art/promo.md](../art/promo.md)）。`site/` に置くのは配信用のコピーで、正本を描き直したら手で入れ直す。

- 画像は WebP に変換し、1ページ合計 1MB 以内を目安にする
- ロゴはパス化済みの SVG をそのまま使う＝フォントを配らない（[ADR-0004](../adr/ADR-0004-logo-typeface-ofl.md)）
- 扉の絵は 1280×720 しか無いので全画面に敷かず中央に置く。酒場の内観は1枚絵が無いため、セレクト画面のスクリーンショットを流用する

## ソースの置き場

`site/` に置く。`.gdignore` を添えて Godot に読ませない＝製品ビルドにも入らない。

```
site/
  wrangler.jsonc
  public/          配信するファイル一式
```

静的サイトジェネレータは使わない。ページ数が少なく共通部分の使い回しが要らないので、ビルド工程を持つ利得より依存を抱える負担が上回る。ページが増えて必要になった時点で入れる。

## 配信

Cloudflare Workers の静的アセット。Worker スクリプト（`wrangler.jsonc` の `main`）を持たない構成にすると、リクエストは Worker を起動せず課金の対象にならない。

- 制限は 20,000 ファイル／バージョン、1ファイル 25MiB。超える大きさのものは R2 に置く
- カスタムドメインは Workers 側で `senaris.in` を追加する。DNS レコードと証明書は Cloudflare が作るので手で足さない
- `www.senaris.in` は Redirect Rule でルートへ飛ばす

## ドメインと DNS

`senaris.in` の登録は AWS Route 53、DNS は Cloudflare。Route 53 の登録済みドメイン側でネームサーバーを Cloudflare に向けて分けている。

ドメインはプロダクトごとに1本取る。開発元のドメイン（`craftkobo.com`）はゲーム以外の事業に使うので、その下にぶら下げない。問い合わせ先のメールは開発元側に置く＝ゲームが増えても窓口が1つで済む。

`.in` を選んだ経緯。`senaris.com` は 2002 年からスペインの個人が保持していて取得できず、`.net` `.org` も登録済み。`.io` は年 $71 と企画の規模に釣り合わず、ccTLD 存続の論点もある。`.games` は年 $37。`.in` は年 $8 で、インドの ccTLD だが居住制限が無く、2005 年の一般開放から外国人に開かれたまま安定している。

### メール

DNS には TXT を2件置いている。

| 名前 | 値 | 意味 |
| --- | --- | --- |
| `@` | `v=spf1 -all` | このドメインからメールを送らない |
| `_dmarc` | `v=DMARC1; p=reject;` | 名を騙ったメールは受信側で捨てさせる |

senaris.in からメールを送り始めるなら、SPF の書き換えが先に要る。忘れると自分が出したメールが全て弾かれる。受信（MX）はこの2件と無関係で、後から足せる。
