# ADR-0005: サイトの配信に Cloudflare Workers を使う

- **ステータス**: 承認済み (Accepted)
- **決定日**: 2026-08-23
- **対象**: senaris.in の配信とドメイン運用（ゲーム本体の配布は対象外）

---

## コンテキスト

`senaris.in` を取得し、公式サイトを出す段になった。決めることは2つある。ドメインの登録と DNS をどこに置くか、静的ファイルをどこから配るか。

`.in` はインドの ccTLD で、Cloudflare Registrar が扱っていない。ドメインを取得した AWS Route 53 から、Cloudflare へ移管する道が最初から無い。

配信の候補は、Route 53 に寄せる S3 + CloudFront、Cloudflare Pages、Cloudflare Workers、その他のホスティング（Firebase Hosting ほか）。S3 単体は HTTPS が付かないので候補にならない。

Cloudflare 自身が Pages から Workers への移行を進めている。静的配信・SSR・カスタムドメインの機能は Workers 側が追いつき、新機能は Workers にしか入らない。Pages が止まる予定は無いが、新規に始めるなら Workers が勧められている。

---

## 決定

**登録は Route 53 に残し、DNS を Cloudflare に向け、配信は Cloudflare Workers の静的アセットで行う。**

- Route 53 の登録済みドメイン側で、ネームサーバーを Cloudflare のものに変更する。Route 53 のホストゾーンは Cloudflare が有効になってから削除する（残すと課金が続く）
- Worker スクリプト（`wrangler.jsonc` の `main`）を持たない構成にする。静的アセットへのリクエストは Worker を起動せず、課金の対象にならない
- カスタムドメインは Workers 側で追加する。DNS レコードと証明書は Cloudflare が作るので手で足さない

運用の詳細は [../sales/site.md](../sales/site.md) が正本。

---

## 根拠と影響 (Consequences)

### 採用する利点

- **転送量の課金が無い。** 静的アセットの配信はリクエスト数の上限も無く、規模の読めない公開初期に費用を気にしなくていい
- **構成が小さい。** 証明書の発行も更新も自動で、リージョンの制約（CloudFront の証明書は us-east-1 でしか作れない、など）に付き合わずに済む
- **後から動くものを足せる。** 仕様リファレンスの生成やフォームのような処理が要るようになっても、同じプロジェクトに Worker を足せばいい
- Pages を選ぶより寿命が長い見込み

### 引き受ける欠点

- **事業者が2社にまたがる。** ドメインの更新は AWS、DNS と配信は Cloudflare で契約先が分かれる。`.in` を選んだ時点で避けられない
- 移管ロックと有効期限の管理は Route 53 側を見に行くことになる
- 配信が Cloudflare に依存する。移すことはできるが、そのときは DNS ごと動かす作業になる

### 見送った案

- **S3 + CloudFront** — Route 53 に寄せられるが、証明書のリージョン制約と転送量課金があり、構成部品が多い
- **Cloudflare Pages** — 今できることは足りているが、新機能が入らない側なので、これから作るものの置き先には選ばない
- **ドメインごと他社へ移管** — `.in` を扱う登録事業者は他にもあるが、移管そのものに手間と待ち時間があり、Route 53 に置いたままで困ることが無い
