# BGM（音楽制作・組込）

BGM の制作方針と組込の運用。少ない曲を作り込み、ムード別に使い回す。翻訳アセットの運用（[../tech/i18n.md](../tech/i18n.md)）と同じく「素材パイプラインの取り決め」を扱う。

## 前提

- 制作者はゼロから作曲はしないが、楽譜が読め、ベースのメロディがあれば編曲・修整ができる。
- 配布はまず Steam（PC）＝商用。

## 方針

全曲を自作アレンジで賄う。AI 支援で出した旋律のたたき台を土台に、MuseScore で編曲・仕上げをする。たたき台はあくまでベースで、良し悪しの判断と仕上げは制作者が行う。

曲数はむやみに増やさず、ムード別のライブラリ（下記）を横断で使い回す。足りなくなったら新曲より先に、同じ `.mscz` からの編成違い（短調化・テンポ変更・楽器の増減）で派生させる＝統一感が出て元手も増えない。

## ツール

- Muse Hub — Muse 社の配布・更新ランチャー。下記を入れる入口。
- MuseScore Studio（旧 MuseScore 4）— 楽譜作成ソフト本体。制作・編集はこれ。
- Muse Sounds — 高品質音源（オーケストラ等）。Muse Hub 経由で入れる。
- ffmpeg — WAV から Ogg Vorbis への変換とループ加工（下記ワークフロー）。

## データ形式

| 形式 | 拡張子 | 役割 | 扱い |
|---|---|---|---|
| MuseScore 原本 | `.mscz` | 編曲の原本 | **必ず残す**（後で直せる） |
| MusicXML | `.musicxml` | 記譜の交換フォーマット | ベースメロディの受け渡し・編集の入口 |
| MIDI | `.mid` | 演奏データ | たたき台の取り込み・プレビュー |
| Ogg Vorbis | `.ogg` | 最終成果物 | Godot に載せる。原本から作り直せる生成物 |

- 原本 `.mscz` が正。`.ogg` は生成物だが、絵の PNG と同じくコミットする（置くだけで鳴る運用のため）。
- `.ogg` の中身は Ogg Vorbis 必須（罠）。`.ogg` はコンテナ名で、中身が Opus のファイルも同じ拡張子を名乗る。Godot 4 が読めるのは Vorbis だけ（Opus はインポートが `valid=false`）。MuseScore から直接 `.ogg` を出すと Opus になりうるので、必ず WAV 経由で ffmpeg 変換する。
- 書き出しの基準値: WAV（中間）＝44100 Hz／16bit PCM／ステレオ（Godot の既定ミックスレートに合わせる）。OGG Vorbis（最終）＝44100 Hz／`-q:a 6`。
- MIDI から取り込むとリズム解釈がずれることがあるので手直し前提。

## 制作ワークフロー

```
たたき台（AI支援で出した .musicxml / .mid）
  → 編曲（MuseScore、原本 .mscz で保存）
  → 書き出し（.wav＝可逆。44100Hz / 16bit / ステレオ）
  ┌─ ここから下は tools\gen_bgm.ps1 が一括で行う ─────────────┐
  │ → ループ長の算出（.mscz の小節数・拍子・テンポから）      │
  │ → ループ加工（ループ長で切り、切った残響を先頭に足す）    │
  │ → 変換（ffmpeg で Ogg Vorbis → assets/bgm/{track_id}.ogg）│
  │ → Godot 組込（.import に loop=true）                      │
  └───────────────────────────────────────────────────────────┘
```

```
powershell -File godot\tools\gen_bgm.ps1 <track_id> …      # ループ曲
powershell -File godot\tools\gen_bgm.ps1 victory -Stinger  # 一発曲（折り返さない・loop=false）
```

以下は素材が仕様どおりかを確かめるための説明で、手順としては上のコマンド1つで足りる。スクリプトは各段でクリップ・残響長・コーデックを検証し、統合ラウドネスを報告する（音量は補正しない＝原本と食い違わせないため）。ツールの索引は [../tech/tools.md](../tech/tools.md)。

### ループ加工（ループ曲のみ）

MuseScore の書き出しは末尾に残響のしっぽが付く。これをループ長ちょうどに切り（切らないと1周ごとに無音の間が入る）、切り落とした残響を先頭に足し込む。理想的なループ音声は「1周ぶんの音」＋「前の周から染み出す残響」の重ね合わせなので、残響を捨てると継ぎ目で不連続が知覚される。

```
loop(t) = s(t) + s(t+L)   … t < 残響長（L＝ループ長）
        = s(t)            … それ以降
```

ループ長は楽譜から求める。

```
L = 小節数 × 1小節の拍数 × 60 ÷ テンポ(♩)
```

例: `menu` は 32小節・4/4・♩=100 → 32 × 4 × 60 ÷ 100 = **76.800秒**。

トリムと加算は1コマンドで済む（`atrim` が切り出しを兼ねる）。

```
ffmpeg -i in.wav -i in.wav -filter_complex \
  "[0]atrim=0:<L>,asetpts=PTS-STARTPTS[body];\
   [1]atrim=<L>,asetpts=PTS-STARTPTS,apad=whole_dur=<L>[tail];\
   [body][tail]amix=inputs=2:normalize=0:duration=first[out]" -map "[out]" looped.wav

ffmpeg -i looped.wav -c:a libvorbis -q:a 6 assets/bgm/{track_id}.ogg
```

`normalize=0` は必須（省略すると音量が半分になる）。`-q:a 6` は約 160kbps。

確認すること。

- 先頭に無音があれば加工前に落とす（`silencedetect` / `volumedetect`）
- 加工後のピークが元と変わっていない（＝加算でクリップしていない）
- 変換後に `ffprobe` で `codec_name=vorbis`（`OpusHead` なら失敗）

スティンガー（`victory` / `defeat`）はループしないので加工不要＝末尾の残響は残す。

適用条件は 残響長 < ループ長（既存曲は残響約3秒に対しループ 60〜77秒で余裕がある）。残響がループ長に近い曲は足し込む項が1つでは足りないので、MuseScore で64小節（2周）に複製して書き出し `[L, 2L]` を切り出す。

副作用として曲の頭に「前周の残響」が入る（初回再生時は本来存在しない音）。`menu` では -22dB 相当で、実聴で違和感なしを確認済み。

中間生成物（`.wav`）と MuseScore のバックアップ（`.mscbackup/`）はコミットしない。

### 音量を揃える — 統合ラウドネス -23 LUFS 目安

曲どうしの聞こえの大きさは統合ラウドネス（LUFS）で揃える。ピーク（dBFS）は歪みの有無を見る指標で、聞こえの大きさは測れない。目安は -23 LUFS。ゲーム業界の推奨（Sony ASWG-R001 の据置機向けは -23〜-24 LUFS）の範囲で、BGM は効果音が上に乗る前提なので放送より静かめのこの位置が理にかなう。

```
ffmpeg -i in.wav -af ebur128=peak=true -f null -     # I: が統合ラウドネス
```

MuseScore 側の作り方は、パート間のバランスを各トラックのフェーダーで作り、曲全体の音量を master で決める。ブーストは合算を押し上げて出口の余裕を食うので、バランスは下げる方向で組む。master フェーダーは書き出しに 1:1 で反映される（+2 dB 動かすと測定値も +2.0 動く）ので、全体音量の調整は master 1本で済む。

外れているとどうなるかの実例。`dungeon` は当初ティンパニのトラックだけ +12 dB で -17.4 LUFS ＝ 他より 5.6 LU 大きく、ピークも -2.9 dBFS まで来ていて効果音との合算で余裕が無かった。ミキサーを組み直して -23.4 LUFS / -9.8 dBFS に収めた。

組み込んだ曲の聴き比べ（曲どうしの音量差）とループの継ぎ目の確認は `sound_check` で行う（[../tech/tools.md](../tech/tools.md)）。本体と同じ再生経路を使うので、ここでの聴こえ方が実機と一致する。

## トラックライブラリ（ムード別・キャンペーン横断）

BGM は**ステージ単位**で流す。本作はマップそのものが戦場で1回の殴り合いが一瞬なので、**戦闘ごとに曲を切り替えず、攻撃・着弾は効果音（SFX）と戦闘演出で示す**（ネクタリス／Advance Wars 型。戦闘が別画面に遷移するファイアーエムブレム型とは分ける）。

**トラックはキャンペーンに属さない。** ムード（状況）別のライブラリとして育て、各ステージが JSON の `bgm` 欄で ID を選ぶ。同じようなマップ／状況なら別キャンペーンでも同じ曲を使い回す（FE 等の汎用マップ曲と同じ運用）。トラック ID もムード基準で命名し、キャンペーン接頭辞（`t1_` 等）は付けない。新しいムードが必要になったらライブラリに曲を足す。

## 管理・運用（ディレクトリ・トラックID・ステージ指定）

絵の管理（[../art/overview.md](../art/overview.md)、`godot/assets/units/` ＋ `godot/assets/units-src/`、autowire）と同じ思想で揃える。効果音を作る時も `godot/assets/sfx/`＋`godot/assets/sfx-src/` を並べる。

### ディレクトリ — `xxx` / `xxx-src` の対

```
assets/
  bgm/                  ← ゲーム用 .ogg（Godot が読む）
    menu.ogg
    menu.ogg.import     ← ループ設定（loop=true）。生成物だがコミットする
  bgm-src/              ← 制作元（.gdignore を置いて Godot のスキャン対象外にする）
    .gdignore
    menu.mscz           ← 編曲の正（必須）。track_id 名でフラットに置く
    menu.musicxml       ← 受け渡し・たたき台（任意）
    menu.wav            ← 書き出し中間物（コミットしない＝.mscz から再生成できる）
    credits.md          ← 権利・ライセンス台帳（曲単位）
```

### トラックID — 規約 autowire

- 曲は**トラックID**（`journey` / `raid` / `title` / `victory` …＝上記ライブラリ表）で扱い、`godot/assets/bgm/{track_id}.ogg` を規約で解決する（skin の画像 autowire と同型）。
- ファイルが**あれば**鳴る。**なければ無音＋開発ログ1行**（絵のプレースホルダの音版。ゲームは止めない）。曲が完成したら `.ogg` を置くだけで鳴り出す＝コード・データ変更なし。

### ステージ単位の指定 — ステージJSONの `bgm` 欄

```json
{ "name": "tutorial-st1",
  "bgm": { "main": "journey" } }
```

- スロット制：いまは `main`（必須）だけ。将来 `intro` 等が要るならスロット追加で対応。
- **フォールバック**：ステージの `bgm` → 全体既定。曲はステージJSONに1ステージずつ書く（冒険譚単位の一括指定は持たない＝どの曲が鳴るかをステージのファイルだけで読み切れるようにする）。

### レイヤー配置

| レイヤー | 実体 | 責務 |
|---|---|---|
| `data` | `godot/data/audio/bgm_catalog.gd` | トラックカタログ（ID→パス解決・autowire）と `bgm` 欄の読み取り。純ロジック |
| `application` | `godot/application/bgm_director.gd` | ステージ開始時に `bgm` 欄から「鳴るべきトラックID」を決定（未指定なら全体既定） |
| `presentation` | `godot/presentation/ui/bgm_player.gd` | `AudioStreamPlayer`×2 の入れ替え。ID を受けて鳴らすだけ |

ステージJSON の `bgm` 欄は `StageLoader.parse_bgm` / `load_bgm` が読む（会話・skin と同じく `BattleState` には入れない）。`main`（`godot/presentation/main/main.gd`）がそれを `BgmDirector` に渡し、決まったIDを `BgmPlayer` に流す。

場面の切り替わりは2箇所だけ。ステージ開始（`_install_state`＝新規ロードと中断セーブ復元で共通）と、セレクトを開いたとき（`SelectScreen.opened` → メニュー曲）。同じトラックIDを指す遷移では鳴り続ける（頭出しに戻らない）。

### 曲の出し入れ — 旧曲はフェードアウト・新曲は頭出し

新曲はフェードインさせず素の音量で頭から鳴らす。旧曲だけ 0.35 秒で落とす。フェードインを掛けると曲の入りが聞こえないまま過ぎるため（-60dB から 1 秒で上げると 0.5 秒地点でまだ -30dB）。スティンガーの頭を殺さない扱いと同じ理由。

旧曲の落としを短く取るのは、ゆっくり落とすと新旧の旋律がフル音量で重なって遷移が団子になるため。上の2箇所はどちらも旋律のある曲どうしの入れ替えで、重なった時間だけ「どこから曲が変わったのか」が分からなくなる。

ステージ曲は盤が1枚描き切ってから始める（`main._start_stage_bgm_when_drawn`）。`_install_state` の中で鳴らすと、残りの盤生成と初回描画のぶん（実測 0.1〜0.3 秒）だけ曲が盤より先行する。

## Godot 組込

`AudioStreamOggVorbis` で読み、`AudioStreamPlayer` で再生する。ループはインポート設定の `loop` / `loop_offset` で持つ（`.import` に乗る＝絵と同じ管理感覚）。ステージ中ずっと流れる曲はループ必須。

`.import` の `loop` はインポート後に手で `true` へ直し、`.godot/imported/` の生成物を消して再インポートすると確実に反映される。`.import` 自体は生成物だがコミットする。

## 権利・ライセンス台帳

商用（Steam）前提。曲ごとの出自を台帳（`godot/assets/bgm-src/credits.md`）に記録する。有料データ保護の方針（[../adr/ADR-0002-paid-data-protection.md](../adr/ADR-0002-paid-data-protection.md)）とは別で、こちらは他者の権利を侵さないための管理。

記録は2層で、曲ごとの台帳はその下の層。音に限らず全体を出所単位でまとめた正本は [../sales/credits.md](../sales/credits.md) で、クレジット画面とストアページの表記はそちらを引く。

記録項目は 曲名（本作での用途）／出典／入手形式／ライセンス（商用可否・改変可否・クレジット表記の要否）／改変度。

曲はすべて自作アレンジ。例外は `title`（酒場のざわめき）で、これは曲ではなく環境音であり、Sonniss GDC バンドル（[sonniss.md](sonniss.md)）の素材から作っている。表記義務は無いライセンスだが、自作物と混同しないよう台帳に自作ではない旨を明記する。

今後さらに第三者の素材を使うことになったら、表記が必要なものは指定文をそのまま Steam ページとゲーム内クレジットに載せる（自己流に変えない）。

- **投入済み（9本）**: `menu`（76.800秒）／ `journey`（71.111秒）／ `raid`（60.952秒）／ `dungeon`（96.000秒）／ `graveyard`（64.000秒）／ `afterglow`（41.739秒）＝いずれもループ長ちょうど・ラップアラウンド加算あり。`victory`（10.3秒）／ `defeat`（14.4秒）＝スティンガー（ループなし）。`title`（90.000秒・ループ）＝曲ではなく酒場のざわめき。自作でなく外部素材から作っており、MuseScore も `gen_bgm.ps1` も通らない（作り方は `godot/assets/bgm-src/title_recipe.txt`）。ループは末尾と先頭を4秒重ねて繋いでいる。曲が未配置のステージは無音＋ログ1行で進む（autowire）。
- **スティンガーの鳴らし方**: `main._on_battle_finished` が決着時に `BgmPlayer.play_stinger` で一発再生（ステージ曲を素早く下げ、フェードインなしで頭から出す）。戦果票の印が落ちる瞬間に合わせる（[../gdd/uiux.md](../gdd/uiux.md) §決着の演出）。勝利は鳴り終わってから `afterglow` へ繋ぐ＝ファンファーレは約10秒で終わるのに outro 会話はその後も続くため、繋がないと無音が居座る。敗北は繋がない（会話が無く、すぐ再挑戦かセレクトへ行く）。連結は待っている間に別の曲へ切り替わっていたら捨てる（会話を読み飛ばして次ステージが始まった後に割り込まない）。
- **全体既定は `map_calm`**（`BgmDirector.DEFAULT_STAGE_TRACK`）で、この ID の曲は無い＝ステージに `bgm` 指定が無いと無音になる。チュートリアル1・2は全ステージに `bgm` を書いたので該当するのはデバッグステージだけ。
