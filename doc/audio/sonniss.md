# Sonniss GDC バンドル索引

物音系の素材プール。効果音の調達方針は [sfx.md](sfx.md) を参照。

Sonniss が毎年 GDC に合わせて無償配布している効果音バンドル 2015〜2026 について、収録ファイル名だけを集めた索引を [sonniss_index.tsv](sonniss_index.tsv) に置く。音声ファイル本体はリポジトリに含めない。

## ライセンス

全年共通で、無償・商用可・クレジット表記不要・再配布不可・AI学習利用禁止。

表記不要だが、使った素材は `assets/sfx-src/credits.md` に記録する（[sfx.md](sfx.md) の権利台帳）。再配布不可のため、素材そのものをリポジトリに入れてはいけない。加工して書き出した `assets/sfx/*.ogg` はゲームの一部として扱う。

## 索引の読み方

1行1ファイル、タブ区切り4列。

```
年	パート番号	ライブラリ名	zip内フルパス
```

```
2017	3	Double Trouble Audio - Medieval Armor and Impacts	Sonniss.com - GDC 2017 - Game Audio Bundle Part 3of9/Double Trouble Audio - Medieval Armor and Impacts/Weapon_Impact_Parry_01.wav
```

4列目は zip を展開したときの実際の場所。3列目はそこからライブラリ名を取り出したもので、列で絞り込むためにある。2017〜2019 の zip は中身をもう一段フォルダで包んでいるため、4列目にはその包みも含まれる。

音を探す。

```bash
grep -i 'parry' doc/audio/sonniss_index.tsv
```

年やライブラリで絞る。

```bash
awk -F'\t' '$1==2019 && tolower($3) ~ /footstep/' doc/audio/sonniss_index.tsv
```

## 素材としての性質

各社の製品版から数本ずつ抜いた見本集で、1ライブラリあたり3〜4ファイルしか入っていない。この比率は年によらずほぼ一定（2026 が 3.0、2019 が 3.4、2020 が 3.5）。過去年の利点はライブラリの種類が多いことであって、1ライブラリの中身が濃いわけではない。

ただしファイル数はバリエーション数ではない。1ファイルが多テイクの詰め合わせになっていることがある（2026年版の `SWSH_SWING IMPACTS ... Var 01` は3秒間隔で21テイク、各0.8〜1.6秒、ピークは正規化済み）。無音で切れば、この1本だけで斬撃の鳴らし分けが足りる。ライブラリの本数だけ見て薄いと判断しないこと。

それでも足りない場合は、複数のライブラリを混ぜるか、気に入ったライブラリの製品版を個別に買うことになる。

長さは 2026 年版の WAV 338本を実測したところ、中央値6秒、5秒未満が44%、60秒以上が22%だった。短い単発音と長い環境音が混在している。物音系として使えるのは前者。他の年は未計測。

## 素材を取り出す

索引で当たりを付け、必要な数本だけを zip から抜いて試聴し、採用した1本を加工して `assets/sfx/` へ入れる。zip 本体は落とさない。

### 1. 用途の枠を決める

探し始める前に、その音に許された長さを調べる。ここを飛ばすと索引を引き直すことになる。長さは演出のコードが決めているので、定数を読めば分かる。

| 用途 | 枠 | 根拠 |
| --- | --- | --- |
| `cmb_open` | 0.8秒 | `LEAD_IN`。これを過ぎると攻撃音が重なる |
| `cmb_attack` / `cmb_hit` | 短い単発 | 一撃ごとに鳴る |
| `map_move` | 素材ごとの間隔以内 | 上記「鳴らす間隔」 |

音程の可否も先に決める。ゲーム中ずっと鳴る音は BGM の上に乗るため、音程を持つと曲の調とぶつかる（[sfx.md](sfx.md) の音量・調の扱い）。無音程の素材を選べばこの問題が消える。

頻度も見る。数百回鳴る音は、単体で物足りないくらいでちょうどよい。

### 2. 索引を引く

用途の枠が決まったら、それに合う長さが出やすいライブラリを狙う。索引にはファイル名しか無く、長さは載っていないため、ライブラリの種類で当たりを付けるしかない。

| ライブラリの種類 | 長さの傾向 |
| --- | --- |
| フォーリー（cloth / paper / foley / footstep） | 短い。単発音が多い |
| 武器・衝撃（weapon / impact / melee） | 短い。多テイクの詰め合わせがある |
| 予告編・映画的（trailer / cinematic / riser / transition） | 長い。5〜20秒の助走が中心 |
| 環境音（ambience / atmosphere / room tone） | 非常に長い。用途外 |

短い転換音が欲しいときに riser や transition で引くと外れる。0.8秒の `cmb_open` を探して riser 系8本を取り出したところ、全部 5.65〜20秒で、頭も末尾も切り出しに使えなかった。予告編用の助走は山に達してから残響で消える作りなので、どこを切っても勢いが残らない。

名前で引いて出てこないときは、何がその音を出しているのかまで戻して引き直す（[sfx.md](sfx.md) の「バンドルに録音が無かったもの」）。

### 3. 候補を書いて取り出す

products 側の `picks.tsv` に候補を1行ずつ足す。列は 年 / パート / 用途（`sfx_id` か `effect_id`）/ ファイル名。

```
2020	4	curse_wisp	SFX_Ghost_Whoosh_Male_03.wav
```

ファイル名はフォルダを含めない。`pick.py` はファイル名の完全一致で引くため、パスを付けると黙って外れる。同名ファイルが別ライブラリにあっても、年とパートで絞られるので取り違えない。

取得量を先に見る。

```bash
python tools/pick.py 2020 --dry
```

問題なければ取り出す。`assets/sfx-src/sonniss/<用途>__<年>__<元のファイル名>.wav` に置かれる。年でフォルダを分けず、全部この1階層に並べる。取得済みは飛ばすので、途中で止めても繰り返し実行できる。

```bash
python tools/pick.py 2020
```

### 4. 実測してから聴かせる

試聴を頼む前に、長さ・ピーク・テイク数を測って並べる。耳で判断するのはオーナーだが、枠に入らないものを混ぜても時間の無駄になる。

多テイクの詰め合わせは無音で区切って数を数える。1ファイルから複数の用途を採れることがある（`punch` と `map_board` は同じ収録の別テイク）。

### 5. 落ちたものは trash へ移す

不採用になった候補は消さずに `sonniss/trash/` へ移す。`pick.py` は採用側と `trash/` の両方を見て取得済みを判定するので、あとで `picks.tsv` を消し忘れたまま同じ年を引き直しても、一度落とした音は戻ってこない。

消さずに残すのは、別の用途で使えることがあるため。`claw` は `cmb_hit_none` の候補から落ちた板金鎧を回したもので、`menu_slide` の布は `map_capture` と共用している。枠が埋まらないときは、まず `trash/` と手元の原本の未使用テイクを当たる。

`picks.tsv` の行はそのまま残す。何を試して何を採らなかったかの記録になる。

### 6. レシピを書いて組み込む

採用が決まったら `assets/sfx-src/<sfx_id>_recipe.txt` に ffmpeg のコマンドを1行で残す。切り出し位置と当てたゲインが後から分かるようにするためで、原本を置けない（再配布不可）ぶんをこれで補う。

```
ffmpeg -y -i "sonniss/curse_wisp__2020__SFX_Ghost_Whoosh_Male_03.wav" -af "atrim=1.30:2.10,volume=-6.0dB" -c:a pcm_s24le curse_wisp.wav
```

あとは `tools/gen_sfx.ps1 <sfx_id>` で ogg にし、`assets/sfx-src/credits.md` に1行足す。ゲインの決め方は [sfx.md](sfx.md) の「外部素材はゲインを当てて合わせる」。

## 入手元と索引の作り方

公式アーカイブ: https://sonniss.com/gameaudiogdc/

zip 本体（199 GiB）を落とさずに索引だけを作っている。zip はファイル一覧（セントラルディレクトリ）が末尾にあり、`downloads.sonniss.com` は HTTP Range リクエストに対応しているため、各 zip の末尾だけを取れば全ファイル名が読める。73パート全体で通信量は約 5.9 MB。

手順は、HEAD で全体サイズを取得 → 末尾 64 KiB を Range 取得 → EOCD からセントラルディレクトリの位置とサイズを読む → その範囲だけを Range 取得 → パース。各パートは独立した完全な zip なので、どのパートにもこの方法が使える。

2026 年版のみ zip を手元に持っているため `zipfile` で直接読んだ。

取得スクリプトと生データ、公式 Tracklist の原本、各 zip の URL 一覧は、リポジトリ外の以下に置いてある。

```
C:\Users\tappe\OneDrive\project\products\assets\audio\sfx\sonniss.com\
```

| サブフォルダ | 中身 |
| --- | --- |
| `raw/` | 各 zip のセントラルディレクトリから読んだ生の一覧（JSON、年_パート単位）。zip の URL はここにある |
| `tools/` | 索引を再生成するスクリプト |
| `tracklists/` | 公式 Tracklist の原本（xlsx / CSV / 2015のみ PDF） |
| `meta/` | 2026年版 zip に同梱の Readme / License / Filelist |

再生成の手順と、つまずいた点（User-Agent 必須・Range が無視されることがある・curl の `--max-filesize` が HEAD にも効く）は、同フォルダの `README.md` に残してある。再生成したら `sonniss_index.tsv` にも反映すること（手順は README にある）。

## 索引の検証

取りこぼしに気付けないのが怖いので、二系統で確認した。

zip の EOCD が申告するファイル数と、実際にパースできた数を73パート全部で照合し、全一致。

公式 Tracklist（Sonniss が別途公開しているファイル名一覧）との照合では、2016・2018・2023 が完全一致。食い違った年は Tracklist 側の綴り違い（2017 の `birds_outsidie` は zip 内では `outside`）や、Tracklist に載っているのにバンドルには入っていないライブラリだった。実体は zip なので索引を正とする。

2015 の Tracklist は PDF で、埋め込みフォントが独自エンコードのためテキスト抽出が通らない。2015 の索引自体は zip から取っているので影響はない。
