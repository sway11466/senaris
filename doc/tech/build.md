# 配布ビルド

対象：エクスポートプリセット・チャネルと版の識別・同梱物の決め方・ビルドの手順
役割：「どのビルドに何が入り、それをどう作るか」を記録する生きたメモ

チャネルの性格と出す順序は [../sales/monetization.md](../sales/monetization.md)、権利と義務の正本は [../sales/credits.md](../sales/credits.md)、道具の索引は [tools.md](tools.md)。

---

## プリセット

軸はプラットフォーム × チャネル × 版（体験版／製品版）。名前は `<プラットフォーム>-<チャネル>-<版>` に揃える。

| プリセット | 機能タグ |
|---|---|
| `windows-itch-demo` | `itch,demo` |
| `windows-steam-demo` | `steam,demo` |
| `windows-steam-full` | `steam` |

軸を3つ持つのは、機能タグをコマンドラインから差せないため。`--export-release` はプリセット名と出力先しか取らないので、チャネルと版はプリセットの中に固定で書くことになる。版の1軸だけで組むと、チャネルを足した時点で組み直しになる。

プリセットは必要になった分だけ作る。使わないプリセットを先に置いても、検証されない設定が増えるだけ。

butler の channel（`windows-demo`）とは別物。あちらは itch のアップロード枠の名前で、プラットフォームを表す。

## ビルドに埋まる識別子

ビルドに焼き付くのは2つだけ。

- プリセットの機能タグ … チャネルと版。実行時は `OS.has_feature("itch")` のように問う
- `project.godot` の `application/config/version` … 版番号

OS は自前で持たない。Godot が `windows` / `linux` / `macos` のタグと `OS.get_name()` を標準で持っている。

刻印は `<OS>-<チャネル>-<版>-<版番号>` の形（`windows-itch-demo-0.1.0`）。用途は流出追跡ではなくサポート時の版特定（[../sales/monetization.md](../sales/monetization.md) の追跡）。

生成した定数ファイルをビルド前に書き出す方式も採れるが、採らない。生成物が `res://` に落ちると、エディタで動かしたときに古い値が残る。ビルド日時やコミットハッシュのような自由な文字列を刻む必要が出たら、そのとき足す。

## 読み出し口

`godot/infrastructure/platform/build_info.gd` が唯一の出どころ。

| 口 | 返すもの |
|---|---|
| `channel()` | 機能タグから。どれも立たなければ `dev`（エディタ実行） |
| `edition()` | 機能タグから |
| `os()` | Godot 標準から |
| `version()` | `config/version` から |
| `stamp()` | 上を繋いだ1行 |

刻印の表示もチャネルごとの分岐も、ここから引く。別々に持つとずれる。チャネル固有の機能（実績・entitlement）は `channel()` の上に乗せる。

刻印はタイトル画面のメニューが出ている状態の隅に置く。扉と動画は一瞬で飛ばせるので載せない。メニュー状態は冒険譚選択から戻ったときに直接出る＝何度でも戻ってこられる画面（[../gdd/title.md](../gdd/title.md)）。メニューの列とは別に置く。項目に見えると操作対象と誤解される。

## 同梱物の決め方

### 非リソースファイル

`.json` は Godot のリソースではない。「すべてのリソースをエクスポート」でも pck に入らないので、非リソースのフィルタに `*.json` を書く。ステージ定義もユニット表も地形表も `.json` なので、書き忘れるとステージを1本も読めないビルドができる。

エクスポートはファイルが落ちても警告を出さずに成功する。壊れたことは起動して初めて分かる。

### 収録リストから導出する

人が書くのは収録する冒険譚の一覧（`godot/tools/build/contents.json`）だけ。そこから必要な素材を導出し、差集合を除外フィルタとして `export_presets.cfg` に書き出す（CSV正本→JSON生成と同じ発想）。

一覧はチャネルではなく版で引く。チャネル別に中身を変えない方針のため（[../sales/monetization.md](../sales/monetization.md) のコンテンツの出し分け）。

導出は GDScript で書き、既定値の解決には本体のカタログをそのまま呼ぶ。地形の識別文字から地形IDを引く規約や、skin 省略時に type と同名になる規約を書き写すと、本体を直したときに黙ってずれる。

除外リストを手で書くと、冒険譚が増えるたびに行を足すことを覚えている必要があり、忘れると未公開の冒険譚が黙って出荷される。収録リスト側で管理すると忘れ方が逆になり、書き忘れた冒険譚は体験版に出てこないだけで済む。

導出の道筋は、既定値の規約に乗って閉じている。

```
contents.json（版 → 冒険譚ID）
└ campaign.json → 各ステージJSON
   ├ terrain の文字 → terrain_type の識別文字 → 地形ID
   │    既定のスキンは地形IDと同名。terrain_skins が差分を上書きする
   ├ player の type ／ enemy の skin ／ dialogue の skin
   │    skin を省けば type と同名
   ├ backdrop
   └ bgm の track_id
```

導出するのは冒険譚ごとに中身が変わる枝だけ。

| 枝 | 扱い |
|---|---|
| `assets/units/` `terrain/` `campaign/` `backdrop/` `bgm/` | 導出する |
| `assets/ui/` `fonts/` `menu/` `effects/` `formations/` `sfx/` | 丸ごと入れる |

後者を導出しないのは、削れる量に対して連鎖が一段深くなるため。攻撃エフェクトはユニット表を、陣形の絵はレシピの成立条件を経由する。危険な枝だけ落として、安全な枝は残す。

刻む単位はフォルダと接頭辞で止める。`assets/units/<skin_id>/` は丸ごと、`assets/terrain/<skin_id>*` は丸ごと。地形は接続タイルが1スキンにぶら下がっているので、ファイル単位で刻むと漏れる。

落とした一覧はファイルに書き出す。何が消えたかが読めない除外は、消えすぎたことにも気づけない。

デバッグ用の冒険譚（`data/stages/debug*/` と対応する `assets/campaign/`）も同じ仕組みで落ちる。収録リストに載っていないものは、未完成もデバッグも区別なく外れる。ステージセレクトの側は `OS.is_debug_build()` で既に塞がっていて、エクスポートしたビルドではボードごと出ない。

### 手で書く除外

開発専用で、どのビルドにも入れないもの。含めるとそれぞれのライセンス義務が生じる（[../sales/credits.md](../sales/credits.md)）。

```
tools/*
tests/*
addons/gut/*
```

`assets/*-src/`（元絵・プロンプト・楽譜）は `.gdignore` で Godot の走査から外れているため、フィルタに書く必要はない。

## ライセンス文の同梱

ライセンス文の同梱が義務の素材があるので、`THIRD-PARTY-LICENSES.txt` を実行ファイルと同じ階層に置く。pck に入れると解凍しないと読めず、同梱の意味を果たさない。

置き場と流れ。

- 素材の権利ファイルは素材の隣（`<名前>-LICENSE.txt` と、著作権表記1行の `<名前>-NOTICE.txt`）。素材を消したら一緒に消える関係を保つ
- 生成した `THIRD-PARTY-LICENSES.txt` は `godot/assets/licenses/` に置き、コミットする。配布物なので `tools/` ではなく `assets/` 側
- ビルドは生成物を実行ファイルの隣にコピーするだけ

生成は `gen_licenses.gd` を手で走らせたときだけ行う。走らせるのは Godot のバージョンを上げたときと、義務のある素材を足したとき。生成物が git に載るので、差分で何が増えたかが読める。

Godot 自身の分はリポジトリに無く、エンジンのバイナリに埋まっている。`Engine.get_license_text()` が Godot 本体の分、`Engine.get_license_info()` と `Engine.get_copyright_info()` が同梱している第三者の分を持つ。3つを組み立てて文章にする。

素材側の Apache License 2.0 の全文には著作権者名が入っていない（テンプレートのまま）。著作権表記は NOTICE ファイルが持つ。ライセンス文の同梱義務がある素材を足したら、この2本を素材の隣に置く。スクリプトは規約で拾うので触らない。

ゲーム内のクレジット画面は別（[../sales/credits.md](../sales/credits.md)）。義務は配布物への同梱で、画面表示は代わりにならない。

## export_presets.cfg の扱い

git 管理する。除外フィルタと非リソースのフィルタはここにしか無いので、追跡していないと消えたことに気づけない。載せれば差分がそのまま検出器になる。

生成物にはしない。Godot はエクスポートダイアログを開くたびにこのファイルを書き直すので、生成すると常にエディタと競合する。CSV正本→JSON生成が成立するのは、Godot が JSON を書き戻さないから。

pck 暗号化（[../adr/ADR-0002-paid-data-protection.md](../adr/ADR-0002-paid-data-protection.md)）を入れる際は、鍵をこのファイルに書けない。鍵を環境変数から流し込む工程が要る。暗号化には鍵を埋めたエクスポートテンプレートの自前ビルドも要る。

## ビルドの流れ

```
1. 版番号を上げる          project.godot の config/version
2. エクスポート            build.ps1 <プリセット名>
3. ライセンス文を添える     同上
4. 起動して確かめる         ステージが読める・出さない冒険譚が無い・刻印が正しい
5. 上げる                  チャネルごとの手順
```

2と3は1本のスクリプトにまとめる。片方だけやって忘れる形を作らない。

4を毎回やるのは、エクスポートが黙って失敗するため。ビルドできたことは正しさの根拠にならない。

5はスクリプトに含めない。公開ページに反映される操作で取り消しが効かないので、作ることと出すことを分ける。4の目視が間に入るのも同じ理由。

チャネルで変わるのは5だけ。1〜4はプリセット名が違うだけで同じ処理。

| チャネル | 上げ方 |
|---|---|
| itch | butler でフォルダを押し上げる。差分転送・itch アプリ経由の自動更新が効く |
| Steam | SteamPipe |
| BOOTH | ブラウザから手で |

出力は実行ファイル・pck・ライセンス文の3つが並んだフォルダ。実行ファイルは起動時に隣の pck を開くので必ずセットで配る。pck を実行ファイルに埋め込む設定は使わない。分けておくと、データだけ変えたリリースで実行ファイルが変わらず、更新の差分が小さくなる。

出力先は Godot プロジェクトの外（リポジトリ直下の `build/`）。中に置くとエディタのファイルシステムが実行ファイルと pck を拾う。

実行ファイルを作るにはエクスポートテンプレートが要る。Godot エディタのエクスポートテンプレート管理から入れる（バージョンの対応をエディタが持つ）。
