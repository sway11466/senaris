# 配布ビルド

対象：エクスポートプリセット・チャネルと版の識別・同梱物の決め方・ビルドの手順
役割：「どのビルドに何が入り、それをどう作るか」を記録する生きたメモ

チャネルの性格と出す順序は [../sales/monetization.md](../sales/monetization.md)、権利と義務の正本は [../sales/credits.md](../sales/credits.md)、道具の索引は [tools.md](tools.md)。

---

## プリセット

軸はプラットフォーム × チャネル × 版（体験版／製品版）。名前は `<プラットフォーム>-<チャネル>-<版>` に揃える。

| プリセット | 機能タグ |
|---|---|
| `windows-itch-demo` | `itch,demo` |
| `windows-steam-demo` | `steam,demo` |
| `windows-steam-full` | `steam` |

軸を3つ持つのは、機能タグをコマンドラインから差せないため。`--export-release` はプリセット名と出力先しか取らないので、チャネルと版はプリセットの中に固定で書くことになる。版の1軸だけで組むと、チャネルを足した時点で組み直しになる。

プリセットは必要になった分だけ作る。使わないプリセットを先に置いても、検証されない設定が増えるだけ。

butler の channel（`windows-demo`）とは別物。あちらは itch のアップロード枠の名前で、プラットフォームを表す。

## ビルドに埋まる識別子

ビルドに焼き付くのは2つだけ。

- プリセットの機能タグ … チャネルと版。実行時は `OS.has_feature("itch")` のように問う
- `project.godot` の `application/config/version` … 版番号

OS は自前で持たない。Godot が `windows` / `linux` / `macos` のタグと `OS.get_name()` を標準で持っている。

刻印は `<OS>-<チャネル>-<版>-<版番号>` の形（`windows-itch-demo-0.1.0`）。用途は流出追跡ではなくサポート時の版特定（[../sales/monetization.md](../sales/monetization.md) の追跡）。

生成した定数ファイルをビルド前に書き出す方式も採れるが、採らない。生成物が `res://` に落ちると、エディタで動かしたときに古い値が残る。ビルド日時やコミットハッシュのような自由な文字列を刻む必要が出たら、そのとき足す。

## 読み出し口

`godot/infrastructure/platform/build_info.gd` が唯一の出どころ。

| 口 | 返すもの |
|---|---|
| `channel()` | 機能タグから。どれも立たなければ `dev`（エディタ実行） |
| `edition()` | 機能タグから |
| `os_name()` | Godot 標準から |
| `version()` | `config/version` から |
| `stamp()` | 上を繋いだ1行 |

刻印の表示もチャネルごとの分岐も、ここから引く。別々に持つとずれる。チャネル固有の機能（実績・entitlement）は `channel()` の上に乗せる。

刻印はタイトル画面のメニューが出ている状態の左下に置く。設定画面を開いている間だけ伏せる＝戻るボタンが同じ隅に出る（[../gdd/settings.md](../gdd/settings.md)）。扉と動画は一瞬で飛ばせるので載せない。メニュー状態は冒険譚選択から戻ったときに直接出る＝何度でも戻ってこられる画面（[../gdd/title.md](../gdd/title.md)）。メニューの列とは別に置く。項目に見えると操作対象と誤解される。

起動ログの1行目にも出す。報告にログが添えられたときは、画面を見てもらわずに版が分かる。

## 同梱物の決め方

### 非リソースファイル

`.json` は Godot のリソースではない。「すべてのリソースをエクスポート」でも pck に入らないので、非リソースのフィルタに `*.json` を書く。ステージ定義もユニット表も地形表も `.json` なので、書き忘れるとステージを1本も読めないビルドができる。

エクスポートはファイルが落ちても警告を出さずに成功する。壊れたことは起動して初めて分かる。

### 収録リストから導出する

人が書くのは収録する冒険譚の一覧（`godot/tools/build/contents.json`）だけ。そこから必要な素材を導出し、差集合を除外フィルタとして `export_presets.cfg` に書き出す（CSV正本→JSON生成と同じ発想）。

一覧はチャネルではなく版で引く。チャネル別に中身を変えない方針のため（[../sales/monetization.md](../sales/monetization.md) のコンテンツの出し分け）。

除外リストを手で書くと、冒険譚が増えるたびに行を足すことを覚えている必要があり、忘れると未公開の冒険譚が黙って出荷される。収録リスト側で管理すると忘れ方が逆になり、書き忘れた冒険譚はビルドに出てこないだけで済む。

収録リスト方式の穴は「作ったのに載せ忘れる」の1つだけなので、そこは声を出して塞ぐ。`data/stages/` にあるのにどの版にも載っていない冒険譚は警告する（デバッグ用は対象外）。

導出するのは、1つのIDが1つのフォルダになっている素材だけ。

| 枝 | 扱い |
|---|---|
| `assets/campaign/<冒険譚ID>/` `assets/units/<スキンID>/` | 導出する |
| フラットに並ぶ素材（地形・BGM・効果音・陣形・背景・UI・書体・メニュー） | 丸ごと入れる |

フォルダに分かれているものだけを相手にするのは、除外の線が名前の完全一致で引けるから。フラットに並ぶ素材は接頭辞で括るしかなく、そこに罠がある。地形スキンは名前が互いの接頭辞になっていて（`plain` / `plain_fence` / `plain_grave1_fort_chapel1` …）、`plain*` で外すと下位のスキンも巻き込む。さらに `combat_ground` `map_ground` `connect_to` で別のスキンを指すため、必要な集合が推移的に広がる。BGM も、トラックIDがステージJSONだけでなく再生側の定数からも来る（タイトル・メニュー・勝敗）。どちらも導出できないわけではないが、線が引ける範囲を超えた時点で、落ちたことに気づけない側の失敗が増える。

削れる量の側から見ても、フォルダに分かれている2つが大きい。

必要なスキンIDの拾い方は、JSONのどの欄に書かれているかを追わない。収録する冒険譚の JSON から文字列を全部拾い、実在するスキンIDと一致するものだけを残す。欄を1つ見落とすと絵が落ちて実行時に壊れるが、この形なら見落としようがなく、外れても余計な絵が1つ残るだけで済む。`skin` を省いた駒は `type` と同名のスキンで描かれる規約なので、`type` も同じ網に掛かる。

落としたものの一覧はビルドログに出す。何が消えたかが読めない除外は、消えすぎたことにも気づけない。

デバッグ用の冒険譚も同じ仕組みで落ちる。収録リストに載っていないものは、未完成もデバッグも区別なく外れる。ステージセレクトの側は `OS.is_debug_build()` で既に塞がっていて、エクスポートしたビルドではボードごと出ない。

`data/stages/` のうち `_` で始まるフォルダは冒険譚ではない（`_boot` ＝盤の外周の下敷き）ので、収録リストの対象外として常に入る。

### 手で書く除外

開発専用で、どのビルドにも入れないもの。含めるとそれぞれのライセンス義務が生じる（[../sales/credits.md](../sales/credits.md)）。

```
tools/*
tests/*
addons/gut/*
.gutconfig.json
```

`.gutconfig.json` は GUT の設定で、非リソースのフィルタ `*.json` に引っ掛かって入ってしまうので明示的に外す。

`assets/*-src/`（元絵・プロンプト・楽譜）は `.gdignore` で Godot の走査から外れているため、フィルタに書く必要はない。

## ライセンス文の同梱

ライセンス文の同梱が義務の素材があるので、`THIRD-PARTY-LICENSES.txt` を実行ファイルと同じ階層に置く。pck に入れると解凍しないと読めず、同梱の意味を果たさない。

置き場と流れ。

- 素材の権利ファイルは素材の隣（`<名前>-LICENSE.txt` と、著作権表記1行の `<名前>-NOTICE.txt`）。素材を消したら一緒に消える関係を保つ
- 生成した `THIRD-PARTY-LICENSES.txt` は `godot/assets/licenses/` に置き、コミットする。配布物なので `tools/` ではなく `assets/` 側
- ビルドは生成物を実行ファイルの隣にコピーするだけ

生成は `gen_licenses.gd` を手で走らせたときだけ行う。走らせるのは Godot のバージョンを上げたときと、義務のある素材を足したとき。生成物が git に載るので、差分で何が増えたかが読める。

Godot 自身の分はリポジトリに無く、エンジンのバイナリに埋まっている。`Engine.get_license_text()` が Godot 本体の分、`Engine.get_license_info()` と `Engine.get_copyright_info()` が同梱している第三者の分を持つ。3つを組み立てて文章にする。

素材側の Apache License 2.0 の全文には著作権者名が入っていない（テンプレートのまま）。著作権表記は NOTICE ファイルが持つ。ライセンス文の同梱義務がある素材を足したら、この2本を素材の隣に置く。スクリプトは規約で拾うので触らない。

ゲーム内のクレジット画面は別（[../sales/credits.md](../sales/credits.md)）。義務は配布物への同梱で、画面表示は代わりにならない。

## export_presets.cfg の扱い

git 管理する。フィルタの中身はここにしか無いので、追跡していないと消えたことに気づけない。載せれば差分がそのまま検出器になる。

ファイル全体を生成物にはしない。Godot はエクスポートダイアログを開くたびにこのファイルを書き直すので、生成すると常にエディタと競合する。CSV正本→JSON生成が成立するのは、Godot が JSON を書き戻さないから。

例外は `exclude_filter` の1欄で、ここはビルドのたびに収録リストから書き直される。手で書かない。書き直した結果は git に載るので、同梱物が変わればビルドのあとに差分として現れる。

pck 暗号化の鍵はこのファイルに書かない。環境変数から流し込む（下記「エクスポートテンプレート」）。

## ビルドの流れ

```
1. 収録リストと版番号を更新   contents.json ／ project.godot の config/version
2. ビルドする                build.ps1 <プリセット名>
     除外フィルタを書き直す → エクスポート → ライセンス文を添える
3. 起動して確かめる           ステージが読める・出さない冒険譚が無い・刻印が正しい
4. 上げる                    チャネルごとの手順
```

2の3工程を1本にまとめるのは、どれか1つを忘れる形を作らないため。古いフィルタのまま出す・ライセンス文を添え忘れる、はどちらもビルドが成功したまま起きる。

3を毎回やるのは、エクスポートが黙って失敗するため。ビルドできたことは正しさの根拠にならない。ビルドログは出力の隣に残るので、何が落ちたかはそこで読む。

4はスクリプトに含めない。公開ページに反映される操作で取り消しが効かないので、作ることと出すことを分ける。3の目視が間に入るのも同じ理由。

チャネルで変わるのは4だけ。1〜3はプリセット名が違うだけで同じ処理。

| チャネル | 上げ方 |
|---|---|
| itch | butler でフォルダを押し上げる。差分転送・itch アプリ経由の自動更新が効く |
| Steam | SteamPipe |
| BOOTH | ブラウザから手で |

出力は実行ファイル・pck・ライセンス文の3つが並んだフォルダ。butler はフォルダをそのまま上げるので、ここには配るものだけを置く（ビルドログはフォルダの外に書く）。実行ファイルは起動時に隣の pck を開くので必ずセットで配る。pck を実行ファイルに埋め込む設定は使わない。分けておくと、データだけ変えたリリースで実行ファイルが変わらず、更新の差分が小さくなる。

出力先は Godot プロジェクトの外（リポジトリ直下の `build/`）。中に置くとエディタのファイルシステムが実行ファイルと pck を拾う。

## エクスポートテンプレート

実行ファイルの素になるのがエクスポートテンプレート。通常はエディタのテンプレート管理から公式配布のものを入れるが、本作は使わない。pck 暗号化（[../adr/ADR-0002-paid-data-protection.md](../adr/ADR-0002-paid-data-protection.md)）の復号鍵はテンプレートにビルド時に焼き込まれるので、鍵を入れたものを自前でビルドする。

鍵は体験版と製品版で分ける。体験版は誰でも手に入る＝最も解析されやすいビルドなので、破られても失うのが体験版の中身だけで済む形にする。テンプレートは鍵ごとに1本要る。

鍵の定期的な入れ替えはしない。鍵は配ったビルドに同梱されるため、入れ替えても配布済みのものは守れない。入れ替えるのは漏らしたときだけ。

体験版も暗号化する。有料版の直前に切り替える形にすると、切り替えを覚えている必要が生まれる。

### 鍵

16進64桁（256bit）ちょうど。桁が違うとテンプレートのビルドが止まる。

作るのは PowerShell で、値を画面に出さずクリップボードへ入れる。

```powershell
$b = [byte[]]::new(32)
[System.Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b)
(-join ($b | ForEach-Object { $_.ToString('x2') })) | Set-Clipboard
```

`Get-Random` は暗号用の乱数ではないので使わない。

保管はパスワードマネージャ。リポジトリにも OneDrive にも置かない。版ごとに項目を分け、どの Godot のバージョン向けかも書く。

使うときは、そのセッションだけの環境変数に入れる。

```powershell
$env:SCRIPT_AES256_ENCRYPTION_KEY = (Read-Host 'key')
```

値を直接書かないのは、PSReadLine がコマンド行を履歴ファイルに平文で残すため。`Read-Host` への入力は履歴に残らない。エクスポートのときは変数名が `GODOT_SCRIPT_ENCRYPTION_KEY` に変わる。同じ鍵を、テンプレートのビルドと pck の暗号化の両方に渡すことになる。

鍵を失うと、その鍵で出した pck を作り直せない。新しい鍵で作り直すことはできるが、配布済みの実行ファイルとは噛み合わないので、pck だけ差し替える更新が使えなくなり、実行ファイルごと出し直しになる。

### ビルド環境

- Visual Studio Build Tools 2022（C++ のワークロード）
- SCons
- AccessKit と Direct3D 12 の依存。Godot 同梱の取得スクリプトが落とす

```powershell
python misc\scripts\install_accesskit.py
python misc\scripts\install_d3d12_sdk_windows.py
```

この2つを入れないと、要るものが無いと言われて設定の段階で止まる。`accesskit=no` `d3d12=no` で切ることもできるが、切らない。公式配布のテンプレートには両方入っているので、切ると公式より機能の欠けたものを配ることになる。とくに Direct3D 12 を落とすと、Vulkan の動かない環境の逃げ道が消える。

### ソース

置き場は OneDrive の外。同期対象に入れると、ビルドの中間生成物が延々と上がる。

エディタと同じバージョンのタグを使う。

```
git clone --depth 1 --branch <エディタと同じタグ> -c core.longpaths=true https://github.com/godotengine/godot.git
```

### ビルドと保管

鍵を環境変数に入れてから、鍵ごとに1本ずつ。

```powershell
scons platform=windows target=template_release arch=x86_64 production=yes d3d12=yes accesskit=yes -j<並列数>
```

出来た `bin/godot.windows.template_release.x86_64.exe` を、どの鍵のものか分かる名前に変えて OneDrive の外へ置く。`.console.exe` も対で置く。`debug/export_console_wrapper` を後から立てたとき、片方だけ無いと理由が分かりにくい。

テンプレートには鍵が焼き込まれている。鍵と同じ秘密物なので、リポジトリにも OneDrive にも置かない。バックアップは要らない。鍵さえあれば同じものを作り直せる。

エディタのバージョンを上げたら作り直す。使っていない側の鍵のぶんも含めて全部。ファイル名にバージョンを入れておくと、どれが作り直し待ちか分かる。

鍵だけを変えたときに作り直されるのは、鍵の生成ファイル1本とリンクだけ。初回ほどはかからない。

### プリセット側

`export_presets.cfg` に3つ。

| 欄 | 値 |
|---|---|
| `encrypt_pck` | `true` |
| `encrypt_directory` | `true`（pck の索引＝中のファイル名も隠す） |
| `encryption_include_filters` | `*` |

include フィルタは必ず書く。空欄だと `encrypt_pck` が `true` でも1ファイルも暗号化されない。暗号化するかは include に一致したファイルだけで決まり、空欄は「どれにも一致しない」になる。エラーも警告も出ないまま平文の pck ができる。`*.*` ではなく `*` にするのは、拡張子の無いファイルを取りこぼさないため。

`custom_template/release` には、保管したテンプレートのパスを書く。鍵ごとに別のテンプレートなので、プリセットごとに違うものを指す。機械依存の絶対パスになるが、そのまま書く。パスが変われば、エクスポートがテンプレートを見つけられずに落ちる。

鍵はこのファイルには書かない。エディタのエクスポートダイアログを開くと `export_credentials.cfg` に鍵が書かれるので、そちらは追跡しない。

`build.ps1` は、プリセットが暗号化する設定なら、何もする前に環境変数の鍵を確かめて止まる。エクスポートの途中で落ちると、書き直した除外フィルタだけが残る。

### 確かめ方

ビルドできたことは、暗号化できたことの根拠にならない。出来た pck を見る。

- 平文が残っていないか。`res://` や収録した冒険譚のIDで pck を検索して、何も出ないこと
- 索引が暗号化されているか。pck の先頭、`GDPC` の後ろ5つ目の32bit がフラグで、最下位ビットが立っていれば索引も暗号化されている
- 鍵の無いテンプレートで開けないこと。公式配布のテンプレートを実行ファイルの名前にして pck の隣に置き、起動して復号に失敗すること

エクスポートのとき、エディタと違う ICU のバージョンでテンプレートを作ると表示が壊れることがある、という警告が出る。同じバージョンのソースから作っていれば条件は満たしているが、警告が消えるわけではないので、起動して日本語が正しく出ているかを見る。
