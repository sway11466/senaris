# i18n（多言語対応）

テキストの多言語化の方針。Steam での海外販売を前提に、プレイヤーが読む文字列はすべて翻訳キー経由にする。

## 方針

- 正本は日本語。`fallback=en` で、未翻訳キーは英語にフォールバックする。英語のほうが多言語ユーザーにとって読める可能性が高いため。
- リリース時の対応言語は ja＋en の2言語。以降の言語追加は翻訳CSVに列を足すだけで済む構造を維持する（中国語圏等はフォント整備が別途要るため、実施はリリース後に判断）。
- プレイヤーが読む文字列を GDScript・データCSV・ステージJSON に直書きしない。すべて翻訳キーにして `tr()` で解決する。開発用のログ・push_error 文言は対象外（日本語直書きでよい）。
- `OS.is_debug_build()` でだけ出る項目（HUD のデバッグメニュー等）も対象外。配布ビルドには入らない（[build.md](build.md)）＝プレイヤーが読まないため。翻訳キーにすると、訳す必要のない語が翻訳CSVに混ざる。

## 仕組み

- 翻訳の正本は `godot/data/i18n/*.csv`（1行目 `keys, ja, en, …`）。Godot 標準の翻訳インポータが `.translation`（言語別・生成物だが git 管理）を生成し、`project.godot` の `locale/translations` に登録する。
- コードは `tr("キー")`、ステージJSON・マニフェストはテキスト欄に翻訳キーを書く（例: `"title": "t1.title"`）。
- 話者名・会話の実装詳細 → [../campaign/authoring.md](../campaign/authoring.md)。

## CSV の使い分け（罠）

- 翻訳CSV（`godot/data/i18n/`）: 翻訳インポータを使う（既定のまま）。
- データCSV（`godot/data/units/` 等の性能表）: `importer="keep"` 必須。既定のままだと翻訳インポータが食って壊れる。
- 逆向きの使い分けなので、CSV を新設するときはどちらの系統かを最初に決める。

## キー命名規約

- 基本形は `<系統>.<id>.<項目>`。系統ごとに CSV ファイルを分ける。
  - `dialogue.csv` — 会話・話者名（`t1.st3.intro.1` / `char.cap.name`）
  - `campaigns.csv` — 冒険譚・ステージのタイトル/説明（`t1.title`）
  - `names.csv` — データ側の表示名（ユニット・地形・移動タイプ・AI特性・兵種。`unit.cleric.name` / `terrain.road.name` / `movement.foot.name` / `ai.charge.name` / `category.infantry.name`）。画面の文言と違い、どの画面でも同じ1語＝用語集として一括で訳す
  - `ui.csv` — UI 文言（`ui.<画面>.<項目>`。画面＝`title` / `hud` / `info` / `report` / `talk` / `save` / `quest` / `select` / `board`（盤のコマンドメニュー） / `banner`（ターンバナー） / `result`（戦果票） / `combat`（戦闘・スキル演出））
- キーは追加のみとし、意味変更での使い回しをしない（翻訳済み文字列が古い意味のまま残る事故を防ぐ）。
- 画面をまたいで同じ語が出ても、キーは画面ごとに立てる（他画面のキーを引かない）。第2セグメントは表示先の画面を指すので、引くと規約が崩れ、片方の画面の文言だけ変えられなくなる。訳文が重複するコストより、画面ごとに独立して直せることを採る。

## 表示名の扱い（データCSVの name 列）

- ユニット・地形などの表示名は、id からの規約キー（`unit.{skin_id}.name` 等）で翻訳CSVから引く。画像の autowire（`godot/assets/units/{skin_id}/…`）と同じ「規約で解決する」方式。
- データCSVの `name` 列は表示に使わず、開発用メモに降格する（列自体は残してよい。2行目の日本語ラベル行と同じ扱い）。

## UI 文言

- 新規の UI はプレイヤー向け文字列を `tr()` 必須とする。
- 既存の直書き（戦闘レポート・会話パネル・依頼書など）は画面ごとにキー化する。移行 → [backlog feature-67〜69](../backlog.md)。
- 長い案内文（操作ヒントなど）は1行1キーにする。翻訳CSVのフィールドに改行を持たせない＝`test_i18n_translation.gd` が CSV と `.translation` を素の文字列で突き合わせているため。行と行の間の空行はコード側が持つ。
- 文字列を連結して1行を組む箇所は、連結の書式ごとキーにする（`"%s （%s）"`）。語順が言語で変わるため、部品だけをキーにするとつなぎ目が固定されてしまう。
- ページ割り・桁揃えのような表示の都合を、文字列の字面で判定しない（見出しを「`【` で始まるか」で見分ける等）。日本語の飾りに依存した判定は英語で効かなくなる。

## 英語の用語

英訳は直訳にせず、英語圏のターン制戦術SLGで同じ概念を指す語に寄せる。会話・冒険譚CSVの英文や、データCSVの列名は根拠にしない（先に決まっていただけで、妥当な英語である保証がない）。妥当な英語を先に決め、食い違う周辺をそちらに合わせて直す。

同じ概念は画面をまたいで同じ語で訳す。キーは画面ごとに立てるが（[キー命名規約](#キー命名規約)）、訳文まで画面ごとに変えると、同じものが場所によって別名になる。

| ja | en | 理由 |
|---|---|---|
| 兵数 | Strength | 頭数を持たない駒（馬車・飛空艇・ドラゴン級＝`combat_lineup` が `single`）にも当たる語。`Troops` はその駒で嘘になる |
| 防御 | Defense | 物理・魔法・対空を分けない単一値なので、`Armor` のように軽減の種類を限定する語は採らない |
| 対地攻撃 / 対空攻撃 | Atk vs Ground / Atk vs Air | `Ground Attack` は「地上への攻撃」とも「地上からの攻撃」とも読めて向きが決まらない。`vs` で対象を明示する |
| 防御貫通 | Ignores N% Defense | `Pierce N%` だと N% が何の割合か決まらない |
| 包囲 | Encircled | 移動を止める ZOC（[movement.md](../gdd/movement.md)）が別に実在するので、`ZOC` は使えない。囲まれた側に掛かる状態なので形容詞形 |
| 占領 | Capture | |
| 地形 | Terrain | |
| 移動 / 移動種別 / 移動コスト | Move / Move Type / Move Cost | `Movement` と混ぜず綴りを1つに保つ |
| 拠点 / 本拠地 | Base / HQ | 拠点のスキンには町・礼拝堂・詰所も含まれるため、要塞に限定する語（`Stronghold`・`Fort`）は採らない。`Fort` は地形タイプ名でもある。`HQ` は勝敗条件の建物であることを一語で伝える |
| 控え | Reserves | `Garrison` は他作品では「その拠点を守る兵」を指すが、本作の控えは守らない（盤に出るまで戦闘に関与しない）。誤って読まれる |
| 特性 | Trait | `Ability` はユニットスキル（[skills.md](../gdd/skills.md)）と読まれる |
| 補正 | Modifier | 地形の攻防補正は `Atk Mod.` / `Def Mod.`。日本語が同じ語族で通しているので英語も揃える |
| 部隊 | Squad | |
| マス（ヘックス） | hex | 看板にしている盤の形なので `tile` にしない |
| カメラの移動 | Pan | 駒の移動（`Move`）と混ざらないようにする |
| 実効攻撃力 / 実効防御力（総攻撃 / 総防御） | Effective Atk / Effective Def | サマリーの「総攻撃」と詳細タブの「実効攻撃力」は同じ量（補正チェーンの結果）なので英語は1語に揃える。`Total` だと式の `Effective Atk²` と別物に見える |
| 支援 | Support | |
| 反撃 / 反撃なし | Counter / No Counter | |
| 損害率 | Loss rate | |
| 対地 N / 対空 N（攻撃の値） | vs Ground N / vs Air N | 行ラベル `Atk vs Ground` の短縮。値の欄では `Atk` を繰り返さない |
| 貫通（行ラベル） | Pierce | 値が防御列の係数（×0.50）として並ぶので、`Pierce N%` の「N% が何の割合か」問題が起きない |
| バフ / 状態（状態補正の行ラベル） | Modifier | 情報パネルの「補正」行と同じ中身（状態補正エントリ）なので同語に揃える |
| ステージ | Quest | ステージセレクト＝Quest Board（酒場の依頼ボード）のメタファに揃える。UI の文言に `Stage` を出さない |
| 冒険譚 | Tales | 日本語がキャンペーンでなく風味の語を選んでいるのに合わせる。酒場の物語（Tales）の中の依頼（Quest）という入れ子 |
| 待機 | Wait | FE・AW 系の定番 |
| 乗車 / 降車 | Board / Unload | AW の定番 |
| ピュリファイ | Purify | 落とすのは呪いだけでなく毒も＝魔法限定に読める `Dispel` は嘘になる。解除の演出表示は `Cleansed` |

## テスト

- `godot/tests/unit/test_i18n.gd`・`test_i18n_translation.gd` が翻訳CSVの整合（キーの実在・ja/en 両方が埋まっていること）を守る。翻訳キーを追加したらテストが検出範囲に含むことを確認する。
- テスト方針の全体 → [testing.md](testing.md)。
