# 戦闘演出シーン

2ユニットの戦闘を見せる演出画面の設計。戦闘の解決（損害計算）は [../gdd/combat.md](../gdd/combat.md)／domain 側で確定済みで、本シーンはその結果を表示するだけ（数値を再計算しない）。効果対象が1体のユニットスキルも同じ画で見せる（→ ユニットスキルの演出）。使う画像スロットは [../art/overview.md](../art/overview.md)、立ち絵の作画方針は [../art/units.md](../art/units.md) §3.3。

盤の見た目は3Dハイブリッド（[../adr/ADR-0003-board-3d-hybrid.md](../adr/ADR-0003-board-3d-hybrid.md)）。演出も同じ3/4俯瞰に寄せ、地形の上に隊列が並ぶ地続き感を出す。

## 配置

- シーンの窓は**盤エリア（右の情報ボックスを除いた範囲）の中央**に置く。右の InfoPanel は隠さず、戦闘レポート（下記）を演出と同時に読めるようにする＝「演出=結果／右パネル=根拠」を同時に見せる。会話シーン（盤に暗幕＋右の箱にパネル）と同じ画面文法。クリックスキップは**盤エリア内**のクリックで効く（右パネルはレポートのタブ操作に使うため吸わない）。レイアウト境界は `presentation/ui/ui_layout.gd`（`UiLayout.RIGHT_BOX` / `board_area`）に集約。
- 暗転は画面共通の基盤 `presentation/ui/screen_lighting.gd`（ScreenLighting）に頼む。幕は**画面全体**（濃さ・フェードは全場面共通＝会話・カットインと同じ）。InfoPanel は前面パネル層（`main.tscn` の `Front`・幕より前）に居るので沈まない＝暗い画面の上に「戦闘窓」と「情報パネル」が同じ高さで浮く画になる（根拠を読ませたい面は暗くしない）。HUD・ターン板は幕の下＝沈む。
- 左右は陣営で固定：プレイヤー左・敵右（攻撃側/防御側で入れ替えない）。立ち絵は向きを陣営に焼き込む（プレイヤー＝右向き／敵＝左向き）ので反転はしない。
- 背景は地面を3Dで組む（[../../presentation/combat/combat_ground_3d.gd](../../godot/presentation/combat/combat_ground_3d.gd)）。盤と同じ地形タイルPNGを床に寝かせ、俯瞰カメラで撮った絵を窓に敷く＝背景専用の描き下ろしは無い。タイル生成は盤と共有（[../../presentation/board/terrain_tiles.gd](../../godot/presentation/board/terrain_tiles.gd)）。
- 地面は左右半分に分け、左＝左の駒のマスのスキン、右＝右の駒のマスのスキンで敷く＝地形は駒の足元に出す。継ぎ目は画面中央（両隊列の間）で、ヘックスの辺なりのジグザグで切り替わる。どのスキンかは各駒の座標から引く（ステージの `terrain_skins` 差分＝平地と雪原を撮り違えない）。
- 盤の並びは写さず、それぞれの半分をそのスキンで敷き詰める＝同じ地形の組み合わせなら毎回同じ構図になり読める。タイルの絵をそのまま敷けないスキン（オブジェクト・線地形）は `terrain_skin.csv` の `combat_ground` 列が下地を指す（空＝自分自身で敷き詰める・既定）。
  - オブジェクトのスキン自身は帯に混ぜず、下記の重ね絵スロットで2Dで出す。地面が奥へ行くほどタイルを縮めて重ねる作りなので、混ぜると奥では小さく靄に沈み、手前では立ち絵に隠れる。重ねる側に出せば大きさが帯と切り離せる。
- 地面の上に重ねる絵は4スロット。左右それぞれ自分の側の駒のマスのスキンから引く（地面を左右で分けるのと同じ理屈＝自分の地形の物は自分の側に出る。攻め手・守り手で区別しない。中央の継ぎ目だけは1本なので、守り手側に絵があればそれ、無ければ攻め手側の絵）。`assets/terrain/{skin_id}_combat_back.png`（奥）／`{skin_id}_combat_rear.png`（隊列の後ろ）／`{skin_id}_combat_line.png`（中央の継ぎ目）／`{skin_id}_combat_front.png`（手前）を持てる。置いてある絵だけを出す＝1枚だけでも、全部無くて地面だけでもよい。盤の立ち絵は使わない（戦闘は近景で、要る絵が違う → [../art/terrain.md](../art/terrain.md)）。
  - そのマスが占領されている拠点なら、所有チーム別の絵があればそちらを使う＝`{skin_id}_team{N}_combat_{slot}.png` を置けば切り替わり、置かなければ中立の絵のまま（盤のタイルと同じ作法 → [../art/terrain.md](../art/terrain.md)）。持ち主は盤の状態から開くたびに引く＝戦闘中に占領されても次の戦闘から新しい絵になる。
  - 奥はその側の半面いっぱいに渡す帯。幅を窓の半分に合わせ、高さは絵の縦横比が決める（屋根が窓から出る絵は、出ない大きさまで縮める）。下端は隊列の頭が少し被る高さ＝奥に建っていると読める。全幅に広げないのは、拠点や堂が誰の拠り所かを絵で言うため。外側の端は窓の外へ抜け、内側の端だけが画の中で終わる＝絵は左陣営向きに描き、右陣営では左右反転して使う。塊を1個浮かべる置き方（キャンバスの余白で大小を持つ・立ち絵と同じ仕組み）は、絵の端がどこにも接がらず宙に浮くのでやめた。
  - 隊列の後ろは、その側の本人（隊列の先頭スロット。`single` なら1体の立ち位置）の真後ろに立てる1枚（玉座など、そのマスに置かれた物を本人の背後に見せる）。帯（奥）と違い、駒と同じ物差しで置く＝駒の戦闘立ち絵と同じ幅のキャンバスを本人の中心xに、上端を駒のキャンバスの上端に揃えて描く。キャンバスが正方より縦に長いぶんは足元の線より下へ垂れる。大小・後ろへの引き・足元からの上下は絵のキャンバスの余白が持つ（駒と同じ仕組み。`terrain_skin.csv` の `combat_scale`＝ファイター何体ぶんの背丈、書き出しは `gen_terrain_tile.ps1 -CombatRear`、後ろへのずらしは `-RearShift <px>`、足元より下へは `-RearDrop <px>`）＝演出側に位置・大きさの定数を持たない。立ち絵より下のレイヤー＝本人も従者も手前に出る。絵は左陣営向き（物が右＝戦場の方を向く）に描き、右陣営では左右反転して使う。
  - 中央は継ぎ目（両隊列の間）に立てる1枚。柵や城壁を「壁越しの対峙」の絵にするのに使う＝壁越しにするかは絵の有無で決まる（コードでもCSVでも決めない）。手前（下）から奥（上）へ走るので窓の全高に渡し、幅は絵の縦横比が決める。立ち絵より下のレイヤー＝隊列は手前に出る。
  - 手前は足元に散らかる物（略奪品の山・橋の欄干）。その側の半面の下辺に接地させる。両方が同じ地形なら両半面に出る。幅は窓の半分、高さは絵の縦横比が決める。前列の足元に少し被せて額縁にする。絵は左半面用に描き、右半面では左右反転して使う。
  - 既定が敷き詰めなので、`combat_ground` を書いていないスキンでも必ず地面が出る（穴が開かない）。壁は全ユニット移動不可＝駒が立てないので対象外。
- タイル画像が引けないスキンは地面を敷かず、窓の地形色（`TERRAIN_COLOR`・守り手の地形で1色）が出る＝どの地形が未整備か分かる（気付ける穴あき運用）。
- 立ち絵は2Dのまま地面の上に重ねる（隊列の奥行きは位置と重なり順で出す＝下記）。地面は窓より少し広く取り、シェイクで縁が覗かないようにする。
- 敷き方は盤のヘックス格子ではなく、手前から奥へ帯を積む。帯ごとにタイルを縮め、カメラの遠近に強制遠近を上乗せする。ここは盤ではないのでマス目が揃っている必要がなく、目盛りとして読ませないぶん絵の奥行きを取る。帯は半分以上重ねて手前を上に置く（瓦葺き）＝大きさの違う帯は列の位相がずれるので、重ねないと噛み合わせの谷に穴が開く。
- カメラの俯角は42°（盤の52°より倒す）。奥は靄で落とす＝距離感を出しつつ、遠くのタイルの繰り返しを目立たせない。靄の濃さはステージが持つ：ステージJSONの `haze` に最奥（水平線）での濃さを 0〜1 で書く（必須・省略なし）。屋外は 0.80（最奥で手前の3割ほどの明るさ）、洞窟は 0.30（壁と床の明るさが近く、水平線直下に暗い帯を作らない）。靄は地面（と背景）だけに掛ける＝重ね絵と立ち絵より下のレイヤーなので、塊も隊列も暗くならない。重ね順は下から 地面 → 背景 → 靄 → 重ね絵（奥・後ろ・中央） → 立ち絵 → 手前の重ね絵 → バー。
- 奥の背景（水平線から上に敷く1枚）はステージが持つ。ステージJSONの `backdrop` に絵のID（`assets/backdrop/{id}.png`）を書けば、窓の高さ0.36のところに水平線を引き、そこから上をその絵にする。空とは限らない＝野戦なら空、洞窟なら岩壁で、この盤がどこかを一枚で言う（→ [../art/backdrop.md](../art/backdrop.md)）。書かなければ水平線を引かず、地面が窓の上端まで続く。
  - 水平線の高さは固定＝ステージや地形で動かさない。重ね絵の下端（0.44）より0.08上に置く＝守り手側に建つ塊が水平線に胴を横切られない（横切ると背景と地面の境目で壁が割れて見える）。すぐ上ではなく少し離すのは、絵の中で奥に建つ建物は土台が下端より少し上（町で0.04）にあり、ぴたりだとその下に背景が覗くため。カメラの俯角42°・FOV42°では本当の地平線は画面の外（視線の42°上・画面上端は21°上）なので、これは幾何ではなく絵として引く線。
  - 背景があるときは靄を水平線から下だけに掛け直す（背景まで靄で潰さない）。背景の下端は水平線を1pxまたがせる＝ぴたり合わせるとどちらにも覆われない行が残り、素の地面が明るいまま抜ける。
  - 背景は地面の上・地形の重ね絵の下＝拠点の屋根は背景に抜ける。シェイクするので地面と同じだけ窓の外へはみ出させる。
- 窓は角を丸めた横長の矩形。角丸の描画をマスクにして中身（地面・立ち絵・エフェクト・シェイク）を切り抜く＝角の外には盤の暗幕が覗く。縁取りはマスクの外側に重ねて描く。

## 兵数の表示（隊列スロット）

並べ方はスキンごとに選ぶ。`unit_skin.csv` の `combat_lineup` 列（表示パターン）で指定し、値は3種。どのスキンをどれにするかはオーナーが個別に決める＝性能や分類から自動で決めない（「大型なら単体」のような規則はコードにもデータにも持たない）。

| 値 | 並べ方 | 想定 |
|---|---|---|
| `squad`（既定） | 本人の `combat` を兵量ぶん複製 | 数えられる兵。歩兵・弓兵・魔法兵・バリケード・バリスタ など大半 |
| `retinue` | slot1＝本人、残りは `retainers` の別スキン | ボス系（ゴブリンロード・ネクロマンサー） |
| `single` | 1体だけ描き、複製しない | 数えられない駒。馬車・飛空艇（積載数が駒単位）／ドラゴン級の大型単体 |

- `retainers` 列は `retinue` のときだけ意味を持つ。
- `single` は絵が減らないので、損害は下記の兵量バーと数値で見せる。1体で隊列8体ぶんの面積を受けるため、演出側で一段大きく描く（隊列の1.25倍）。スキン個別に足したいぶんは `combat_scale`。

### 兵量バー

- 兵量バーは表示パターンに関わらず**常に**両陣営に出す。8分割の刻み入り＝隊列8スロットと同じ数え方で、「絵が減る／バーが減る」が同じ情報の二重表現になる。パターンごとに損害の読み方が変わらないようにするための措置。
- 減少はフロー4（兵数の更新）と同じタイミングでアニメさせる（0.35秒で目盛りが落ちる）。`single` ではこれが損害の主表示になる。
- 置き場所は窓の下端寄り（各陣営の隊列の下）。幅は窓の内寸の30%・高さ2.8%で、左右それぞれの隊列の中心に置く。

以下は `squad`／`retinue` の隊列の組み方。

- 各陣営の立ち絵（`combat`）を、その時点の兵数（1〜8・[../gdd/combat.md](../gdd/combat.md)）ぶん複製して並べる。同じ1枚を使い回し、スロットの表示ON/OFFで数を合わせる。兵数は戦闘ルールで上限8＝オーバーフロー処理は不要。
- 隊列テンプレ：散開スキャッター（計8）で中心（激突点）へ正対。奥行き(x)と高さ(y)を互い違いにずらし、格子整列にしない（隊列に見えつつ自然な群れ）。隊長は後列中段＝群れの後ろに構える。
- x で3列に分かれる（後列3・中列2・前列3。前＝敵側）。足元の位置には地面の傾き（x が前ほど下）が乗るので、後列は y を大きめ（画面下）、前列は y を小さめ（画面上）に取って傾きを打ち消す。これをしないと3列が斜めに潰れて一塊に見える。
- スロット番号＝生存優先度。表示は slot1..兵数。損害は外側から消え、slot1 の隊長が最後まで残る。少人数では隊長と中列に寄って崩れる。
- ボス系（`retinue`）：slot1（後列中段）を本人の `combat` にし、残りを従者＝別スキンの `combat` で埋める。slot1 は最後まで残るので、兵数が減るほどボスだけになる。ボスが手下の後ろに構える絵になる（敵陣営では画面の外側が後ろ）。
  - 従者は `unit_skin.csv` の `retainers` 列（`|` 区切り）。並び順＝slot2 から順。slot が余ればリストを先頭から巡回する（`skeleton|zombie` なら交互）。上限7（隊列8のうち先頭は本人）。
  - ボスを手下より大きく見せたいときは `combat_scale` を上げる（盤の駒は `map_scale` で別管理なので戦闘だけ大きくできる）。例＝ネクロマンサー 1.26。
  - 既存スキンを指すので絵は増えない。例＝ネクロマンサーにスケルトンとゾンビを混ぜる、ゴブリンロードにゴブリンを従える。
  - 未定義の `skin_id` を指すと変換が止まる（[../../data/units/convert.gd](../../godot/data/units/convert.gd)）＝黙って絵が出ない事故を防ぐ。
- サイズは全スロット一定（`FIG_SCALE`＝列で変えない）。3/4俯瞰の奥行き感は位置（前ほど下・奥ほど上）と重なり順で出し、拡大率では付けない＝列ごとの大小差を出さず揃える。
- 座標は陣営ボックス内の正規化値（0〜1・x は中心へ向かうほど1／敵側は 1−x でミラー）。実px はシーン解像度で決める＝下表は相対値の叩き台（微調整は実装時）。

| slot | x(奥0→前1) | y(上0→下1) | 群れ位置 |
|---|---|---|---|
| 1（隊長） | 0.45 | 0.36 | 中核 |
| 2 | 0.55 | 0.68 | 中核（対） |
| 3 | 0.23 | 0.52 | 菱形の翼 |
| 4 | 0.77 | 0.52 | 菱形の翼 |
| 5 | 0.66 | 0.20 | 外周 |
| 6 | 0.34 | 0.84 | 外周 |
| 7 | 0.12 | 0.20 | 外周 |
| 8 | 0.88 | 0.84 | 外周 |

- 立ち絵が未用意のスキンはプレースホルダ（ベタ塗り＋フルネーム）。主要ユニットから順次差し込む（autowire＝置くだけ切替）。

## 右パネル（戦闘レポート）

戦闘発生時、右の情報ボックスに戦闘レポート（`presentation/ui/combat_report_view.gd`）を出す。演出シーンと同じ detail（`BattleState.attack` の `"detail"`）から描く＝盤の数字と必ず一致する。タブ3枚構成で、戦闘のたびにサマリーへリセット。

- **サマリー**: ユーザーが見える特徴の左右比較（式は出さない）。左右は陣営で固定（自軍左・敵右＝演出シーンと同じ並び）
- **攻撃側／守備側**: 各ユニット視点の数式チェーン（攻撃・防御・損害行）＝数字の根拠

### サマリーの行構成

| 行 | 表示例 | 備考 |
|---|---|---|
| 絵 | （combat スロット優先・map 代用） | 未用意は陣営色の板 |
| 名前 Lv | 聖騎士 Lv3 | |
| 兵量 | 5/8 → 3/8 | 損害＝結果の主役 |
| 総攻撃 | 132 | 実際に使われた向きの値。反撃なしの守備側は「反撃なし」 |
| 総防御 | 96 | 反撃なしの攻撃側（＝被弾なし）は「—」 |
| 攻撃(基礎) | 対地12 | vs_aerial なら対空表記 |
| 防御(基礎) | 8 | |
| 地形 | 森 ×0.90/×1.20 | ペアは常に**攻/防**の順（以下同） |
| 包囲 ※効いた時のみ | ×0.68 | 攻防共通の係数 |
| 支援 ※効いた時のみ | +12/+8 | |
| バフ ※ある時のみ | ホーリーアリア ×1.30/×1.30 | 状態補正エントリの `name`（combat.md 参照）。target が片側なら「×1.30/—」 |

包囲・支援・バフの行は両側とも素通しなら出さない（サマリーを薄めない＝「効いたものだけ示す」の方針と統一）。

## 動き・エフェクト

- キャラのフレームアニメはしない（立ち絵は静止）。動きはシーン側で付ける：
  - 命中の瞬間に画面シェイク。
  - 被弾側の隊列にフラッシュ。
  - 攻撃エフェクト：損害は攻守同時なので、双方が自分のエフェクトを相手（被弾側）の隊列へ出す。攻撃主体を分かりやすくするため攻撃側を先・反撃を少し遅らせて出す。片方向になるのは間接攻撃（反撃なし）だけ＝下記 特殊ケース。詳細は次節。

### 攻撃エフェクト

- どのエフェクトを使うかは `unit_skin.csv` の `combat_effect` 列（エフェクトIDを指す）。エフェクト自体の定義は `data/effects/combat_effect.csv`＝スキンをまたいで共有する。剣で斬った跡に陣営の個性は要らず、誰が斬ったかは立ち絵と左右の位置で既に読めるため、味方とゴブリンで同じ斬撃を使う。
- 出し方は2種（カタログの `kind`）。絵とは別の属性で、同じ絵を別の出し方に回せる。

| kind | 動き | 使う武器 |
|---|---|---|
| `impact` | 被弾側の隊列の上に1枚重ね、拡大しながらフェード | 斬撃・近接の魔法（聖光） |
| `projectile` | 攻撃側の隊列から被弾側の隊列へ飛び、着弾で消える | 矢・投石・遠隔の魔法 |

- エフェクトは1発ではなく、殴った側にいま並んでいる数ぶん出す（8人の弓兵が撃つなら矢は8本）。減っていれば発数も減る＝「相手が弱っている」が絵でも伝わる。反撃は減った後の隊列が振るので、その時点で並んでいる数に合わせる。
- 出る場所はどちらも被弾側（＝殴られた側）の隊列スロット。1発が1体に当たって見えるよう、被弾側のスロットへ順に配る（殴った側のほうが多ければ先頭から巡回＝誰も居ない場所を斬らない）。`projectile` は始点が攻撃側の対応スロットになるだけで、着弾は被弾側。
- 発ごとに時差をつける（0.025秒）。同時に出すと1枚の大きな絵に見えて斉射・乱戦にならない。シェイク・フラッシュ・損害数は最後の1発が届いた時点。
- 大きさはカタログの `scale` 列（1.0＝被弾側の立ち絵1体ぶん。絵の長辺を基準に合わせる＝縦長の斬撃と横長の矢が釣り合う）。エフェクトの絵は余白を切り詰めて作るので、大小の差は画像ではなくこの列で付ける。
- タイミングの基準は着弾の瞬間。シェイク・被弾フラッシュ・損害数はそこに揃える。`projectile` は飛翔ぶん（既定0.45秒）着弾が遅れるので、その一式も同じだけ遅れる。飛ぶ距離は窓の幅の約0.7倍あり、尺を詰めると数フレームで通り抜けて「飛んだ」と読めない。
- どちらの kind も、絵は「右へ向かう一撃」で描き、左向きのときだけ演出側が水平反転する（`projectile` は左へ飛ぶとき、`impact` は左側の隊列を殴るとき）。立ち絵と違い斬撃や矢は反転しても破綻しない＝1枚で両陣営に使える。左右対称の絵（聖光など）は反転しても見た目が変わらないだけで害はない。
- 未設定・画像が無いスキンは既定のスパーク（コードで描く星）に落ちる＝穴が開かない。
- 聖光（クレリック）は射程1の近接なので `impact`。飛ばしても距離が短く「飛んだ」と読めない。遠隔の魔法（メイジ等）が来たときに `projectile` を使う。
- 損害は攻守同時（相討ちあり・[../gdd/combat.md](../gdd/combat.md)）。数値は「敵の失う兵数／自分の失う兵数」を表示。
- 補正（レベル・包囲・地形・支援・状態）は、効いたものをアイコン/バッジの有無で軽く示すだけ。数式の内訳は演出では出さず、攻撃前プレビュー（現行と同じ数式表示・[../gdd/combat.md](../gdd/combat.md)）に委ねる＝演出=結果、プレビュー=根拠。

## 特殊ケース

- 間接攻撃（攻撃距離2以上＝反撃なし・[../gdd/combat.md](../gdd/combat.md)）：攻撃側エフェクト→防御側被弾のみの片方向（攻撃側は無傷・被弾演出なし）。射程1-2の弓兵でも、距離2から撃てばこちらになる。
- 全滅（片側0）：消滅側フェードアウト。相討ち（両0）も両方フェードで、専用の決着演出は設けない。
- 支援ユニット（隣接自軍）は演出に出さない（対峙は2ユニットのみ）＝上の補正アイコンで示すに留める。

## ユニットスキルの演出

効果対象が1体のユニットスキル（レシピの `shape` が `solo` かつ `buff_scope` が `unit`＝[../gdd/skills.md](../gdd/skills.md)）も、2体が対峙する同じ画で見せる。起きることは攻撃とほぼ同じで、違うのは兵数が減らず補正が乗る点だけ。陣営全体に掛かるもの（ホーリーアリア）は対象外＝従来どおり陣形スキルのカットインと盤の見た目で見せる。

- 進行は戦闘と分ける。ため→着弾→反撃→幕引き、という順番はスキルには無い（反撃が起きない・兵量が動かない）ので、戦闘の進行に分岐を足さず別の塊にする。窓・暗転の掛け外し・盤エリアへのレイアウト・地面・隊列・立ち絵・兵量バーは共通の部品として両方から使う＝窓の形や隊列の並べ方を2箇所で直さない。
- 左右は陣営が違えば戦闘と同じ（プレイヤー左・敵右）。同陣営どうし（味方に掛ける強化・敵が敵に掛けるもの）は陣営で決まらないので、発動者を左・対象を右に置く。
- 立ち絵は中央（相手）を向いていない側だけ水平反転する。向きは陣営に焼き込んである（プレイヤー＝右向き／敵＝左向き）ので、左に敵陣営の駒が来るとき、または右にプレイヤー陣営の駒が来るときに反転が要る。反転すると武器の持ち手が入れ替わるが、2体が同じ側を向いて立つより対峙が読める。
- 地面は対象（掛けられる側）の地形で組む。戦闘で守り手の地形を使うのと同じ考え方で、演出の舞台は受ける側に置く。
- 兵量バーは戦闘と同じく両陣営に出す。値は動かない＝スキルでは兵数が変わらないことが、そのまま伝わる。
- 損害数の代わりに、乗った補正を出す（攻撃 -80 ／ 防御 -80）。落とすもの（ピュリファイ）は落とした件数。数値の根拠は右パネルの状態補正行に出る。
- エフェクトはレシピの `combat_effect`、無ければ発動者スキンの `combat_effect` へ落ちる（→ [../gdd/skills.md](../gdd/skills.md) 実装方針）。出し方（`impact` / `projectile`）・大きさ・反転は攻撃エフェクトと同じ規約で、専用の器は足さない。
- 発数は発動者にいま並んでいる兵数ぶん。効果量が残兵数で決まる（`buff_value_per_troop`）のと絵が一致する＝削れたゴーストの呪いは薄い、が見て分かる。
- 出る場所は対象側の隊列スロット。攻撃で被弾側に配るのと同じ。
- スキップは戦闘と同じ（下記 テンポ・スキップ）。

## フロー

1. 戦闘確定（domain が損害を算出）→ 本シーンへ結果を渡す。
2. 開幕：暗幕が差し、窓が上下に開き、両隊列（戦闘前の兵数）が外側から中央へ寄る。
3. 演出：シェイク＋フラッシュ＋エフェクト、損害数の提示。
4. 兵数を戦闘後の値へ更新（消えた分の隊列スロットを畳む）。
5. 幕引き：全体をフェードアウトして閉じる。盤へ戻る。

### 幕開け・幕引き

盤と演出は同じ画面に同居するので、切り替わりを動きで知らせる。開きは動きで合図し、閉じは静かに溶かす（非対称）。

- 開き：窓を縦に潰した状態から中心を軸に上下へ開く。窓が開ききってから、両軍の隊列を外側から中央（激突点）へ寄せる。隊列を寄せる動きは「陣営で左右を固定して中央へ正対」という舞台の文法をそのままなぞる。バーと地形の重ね絵は動かさない（窓に属する表示なので、隊列と一緒に流れると窓が滑って見える）。
- 開きに使う時間は「ため」（`LEAD_IN`）の内側で消化する＝ためが短くなるだけで、演出全体は伸びない。
- 閉じ：窓を閉じる動き（開きの逆再生）は使わない。切断の動きになって余韻と逆に働く。全体のアルファをゆっくり落として溶かす。
- `finished` はフェードが終わってから出す＝盤は幕が引き切るまで動かない。そのぶん連戦・AIターンは1戦闘あたりフェード時間だけ伸びる。

## テンポ・スキップ

- プレイヤーの攻撃はフル演出。クリック/キーでいつでも結果へスキップできる。スキップも幕引きのフェードを通す（ここだけ切り落とすと見た目が揃わない）。フェード中にもう一度クリックすれば余韻ごと飛んで即座に閉じる＝連打で待たされない。
- AIターンの戦闘は既定で短縮（結果ダイジェスト・シェイク最小）。連戦（1ターンに複数戦闘）はキューで詰めて流す。
- グローバル設定「演出：フル／短縮／オフ」の3段。オフでも結果（損害数）は必ず出す。

演出速度の設定は置き場所が未定＝設定画面を作る段で決める（[backlog.md](../backlog.md) feature-16・feature-47）。
